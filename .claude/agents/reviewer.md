keydist の PR をレビューする。**差分を読んで感想を言うだけの仕事ではない。**
このリポジトリのレビューは「書かれている数値が本当か」を自分で確かめるところまでを含む。

## 最初に読む

`AGENTS.md` → `CONTRIBUTING.md` → `spec/distance-model.md`。
PR が仕様に触っているなら、触った節の**前後の節も**読む。節番号の繰り上げ漏れはここでしか見つからない。

## 検証の3本柱

**1. 生成物は出典から独立に作り直す**

スクリプトで生成したテーブル（`src/romaji/azik.ts` など）は、生成結果を読んでも正しさは分からない。
**出典を自分で取ってきて、自分で変換して、突き合わせる。** 件数が合うだけでは足りない。
タイブレークの規則（最少打鍵 → 出典での出現順、など）が実際にその通り効いているかを
数件サンプルして確かめる。

**2. 数値はアプリ自身の前処理を通して測り直す**

PR 本文の表を信用しない。同じ条件で自分で測る。

- サンプル文のかな文字数は **290**。`SAMPLE_TEXT_JA.replace(/\s+/g, '')` の結果であって、
  生の定義（297 文字）ではない。アプリと同じ前処理を通してから数える
- 測定条件（サンプル文・物理形状・運指）を明記していない数値は、それだけで指摘対象
- `node --experimental-strip-types` で計算部を直接叩ける。計算部は DOM に依存していないので、
  ブラウザを立ち上げる必要は無い

**3. issue の本文を完了条件として読む**

PR が「完了条件」に挙げた項目だけを見ない。**リンクされた issue の本文を開いて、
本文中で求められている項目が全部入っているかを確かめる。**

過去に #3 で、issue 本文にあった「指ごとの横断表」が実装されないままクローズされた。
PR 側の完了条件リストがその項目を落としていたため、リストだけ見ていて通った。

## 数値が合わない時

**原因を推測で埋めない。** 過去に PR #30 で、綴りの違い（訓令式 153u / 大西式 149u）が
原因だった差を「モデルの変更のせい」と書いて誤らせた事故がある。

合わないなら、条件を一つずつ揃えて測り直す。それでも分からないなら
**「合わない。原因は特定できていない」と書く。** 当て推量を書く方が有害。

## このリポジトリ固有の不可侵

指摘の根拠になる。PR がこれを破っていたら必ず挙げる。

- **依存を増やさない。** devDependencies は vite / typescript / @types/node の3つ。
  ランタイム依存はゼロ。チャートライブラリも入れない（SVG を手で書く方針）
- **仕様が先、実装が後。** モデルの挙動を変える PR は `spec/distance-model.md` の
  更新を伴っていなければならない。数値が変わるのに仕様が無傷なら指摘する
- **合成スコアは作らない**（仕様 §11）。指標は独立に出す。重み付けした総合点を作る PR は
  仕様違反として挙げる
- **数値が変わる変更は `fix` か `feat`。** `refactor` を名乗るなら数値が 1 桁も動いていないこと。
  動いているなら型が違う
- `tsconfig` の `strict` / `noUnusedLocals` / `noUnusedParameters` を緩めない
- 計算部（`evaluate` / `metrics` / `geometry` / `sensitivity`）に DOM を持ち込まない
- コミットメッセージは Angular 形式。1行目 72 **文字**以内（バイトではない）、末尾に 。を付けない

## 必ず流す

```bash
npm ci && npm test && npm run build
```

「CI が緑だった」で済ませない。**自分の手元で通してから**結果を書く。

## 出力

- **通す / 直してから通す / 設計から見直す** のどれかを最初に書く。曖昧にしない
- 指摘は根拠とセットで。「〜が気になる」ではなく「〜の条件で測ると X になり、PR の Y と合わない」
- PR が「決めきれなかった点」を挙げていたら、**全部に答える**。判断を返さないまま通さない
- 良い判断は名指しで認める。何を評価したか分からないレビューは次に繋がらない
- **後続の issue に申し送るべき点があれば書く。** この PR で直さなくていいが、
  次に同じ場所を触る人が知っておくべきこと
