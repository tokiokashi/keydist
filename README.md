# keydist

キーボードの論理配列を、モデル文章を打った時の**指の総移動距離**で評価する。

https://tokiokashi.github.io/keydist/

## 配列の書き方

文字 → 打鍵ステップ列。ステップの列が順次性を、ステップ内の集合が同時性を表す。
キーは QWERTY 刻印で指す。

```json
"が": [["thumb-r", "f"]]   同時押し（1 ステップ）
"が": [["shift"], ["f"]]  前置シフト（2 ステップ）
"が": [["f"], ["shift"]]  後置シフト（2 ステップ）
```

1 本の指で複数キーを押す場合（キーの間を押す）は、その指の目標位置をキーの重心にする。

複数のシフト面を持つ配列は、`trigger`・`mode`・`rows` から同じ形式へ展開できる。
`rows` は QWERTY の 4 行で、セル配列を使えば `きゃ` のような複数文字の見出しも置ける。

```ts
{
  trigger: ['thumb-r'],
  mode: 'simultaneous',
  rows: [/* QWERTY の 4 行 */],
}
```

`mode` は `prefix` / `suffix` / `simultaneous` のいずれかで、面の展開後は直接書いた
`Sequence` と同じように評価される。

旧定義や保存済み配列にある `space` は、右親指キー `thumb-r` のエイリアスとして受け付ける。

## 何を測るか

各打鍵について、その指がどこから動いてきたかを決めて距離を積む。

```
g = 0        →  d(前のキー, 今のキー)              同指連続。ホームに戻る時間がない
1 ≤ g ≤ N    →  min(d(前のキー, k), d(ホーム, k))   窓の内側。残る／戻るの小さい方
g > N        →  d(ホーム, 今のキー)                 復帰済み
```

`g` は前回その指を使ってから挟まった**他の打鍵数**、`N` は残す／戻すを比べる先読み打鍵数で、利用者が設定する。
`N` を増やすと比較できる候補が増えるため、総距離は減るか変わらない。
ホームへの復帰移動そのものは距離に計上しない。

詳細は [spec/distance-model.md](spec/distance-model.md)。

## 出力

合成スコアは作らない。次を独立に出す。

- 指ごと／全体の総移動距離
- 1 打鍵あたりの平均移動距離
- 入力 1 文字（ローマ字展開・コンボ結合の前、かな・英字）あたりの平均移動距離。
  打鍵数はローマ字の綴り・コンボ・かな直接入力で配列ごとに変わるため、
  「1 打鍵あたり」では打鍵数削減の効果が分母に吸収されて消える。
  文字数は展開前で固定するので、削減の効果はこちらに残る
- 入力 1 文字あたりのアクション（ステップ）数、および押下キー数。
  コンボ・同時押しは指の移動距離には現れないが（[何を測っていないか](#何を測っていないか)）、
  この 2 つには現れる。前者はまとめて打つほど下がる時間的なコスト、
  後者はキーを押す総回数（コンボでまとめても減らない）
- コンボ定義のうち命中した件数と、コンボが命中した延べ回数。
  命中件数は「一度でも当たった定義」の数、延べ回数はテキスト中で当たった回数を表す
- 配列 × 指のマトリックスとして、指ごとの移動距離 [u/文字]、押下数 [押下/文字]、
  隣接指のホーム間隔からの超過（平均）[u] を並べて出す。押下数の面には生の押下回数もツールチップで出す
- 同指連続回数と比率
- 隣接指のホーム間隔からの超過の平均と実測最大値（ホームに並んだ状態が 0。標準偏差はばらつきとして併記。大きいほど上下段をまたぐ運指が多い）
- `N` を振った時の総移動距離の変化

## 何を測っていないか

- 2 次元の動きを 1 次元の距離に圧縮する
- 他の指や手全体が引かれる動きは扱わない
- ホームに構える前提
- 「指の疲れ」は出さない
- 実際のタイピングは再現しない
- キーと指の対応は固定。運指の個人差は入らない
- ホームへ戻る移動は数えない
- 総移動距離は下界
- 同時押し・コンボは距離に出ない。アクション/文字で読む
- 配列を比べる時は形状を揃える。形状が変われば距離の絶対値が変わる

コンボを加えた実測では、移動の多い配列で距離が減り、移動がすでに最小化された配列ではむしろ増える。

測定条件: かな 1676 文字 / `N` = 3 / ロウスタッガード / 綴りは**訓令式**。
既定の日本語サンプルは現代文の自作文で、旧「吾輩は猫である」の290文字もサンプル欄から選べる。
これは自作の例文であり、実際の文書の統計とは異なる。書き手の語彙や文体の癖が数値に残るため、実際の文書を代表するものではない。
綴りは配列と対で効くので、大西を大西式綴り（`sh` / `ji`）で打つと別の値になる
（新サンプルではコンボなしで 1076u、同指連続 32）。

| 配列 | コンボなし | コンボあり | 同指連続 |
|---|---|---|---|
| QWERTY | 2032u | 1766u | 238 → 237 |
| Colemak-DH | 1042u | 1020u | 42 → 105 |
| 大西 | 1087u | 1032u | 38 → 86 |

総距離だけを見て「コンボは効果がない」と読まないこと。打鍵数の削減は
「入力 1 文字あたりのアクション数」（[出力](#出力)参照）の側に直接出るので、
指標としてはそちらで読む。

ローマ字配列のコンボは、定義ごとの発火条件に従う。現時点で拗音限定（`youonOnly`）なのは
私家版コンボのヤ行19件で、拗音のローマ字塊の内部で直前に子音がある場合だけ発火する。
そのため、`きゃ` の `ya` はコンボになるが、単独の `や` は `y` + `a` に分かれる。

詳細は [spec/distance-model.md §12](spec/distance-model.md#12-数値の性質)。

## 日本語

同じかなテキストを、ローマ字配列にもかな配列にも食わせて比較できる。

- **ローマ字配列** — かな → ローマ字のテーブルを通してから打つ。
  テーブルは配列と独立しており、既定配列ごとに別の綴りを割り当てられる。
  促音は差し替え後の綴りから展開する（`っか` → `kka`、`し` を `shi` にすれば `っし` → `sshi`）
- **かな配列** — かな → 打鍵ステップ列を直接持つ。テーブルを通さない

どちらも最終形は打鍵ステップ列なので、評価器は両者を区別しない。

入っている日本語向けの配列:

| 配列 | 出典 |
|---|---|
| 大西 | 公式配置。公式が前提とする綴り（シャ行 `sh` / じ `ji` / じゃ行 `j`）で打つ |
| 大西（私家版 + コンボ） | 下段を差し替えた版に、Vial キーマップのコンボ 73 件を適用。綴りは訓令式 |
| 薙刀式 v18 | [公式配布の DvorakJ 定義](https://oookaworks.seesaa.net/article/456099128.html)から機械的に生成 |
| 親指シフト（NICOLA） | [NICOLA 配列規格書](http://nicola.sunicom.co.jp/spec/kikaku.htm)準拠の DvorakJ 定義から移植。専用キーボードの配置を ANSI に写しているため、距離の絶対値は参考値 |
| 新下駄 | [DvorakJ の定義](https://github.com/k-ayaki/dvorakj_2023/blob/master/data/lang/jpn/%E5%90%8C%E6%99%82%E3%81%AB%E6%89%93%E9%8D%B5%E3%81%99%E3%82%8B%E9%85%8D%E5%88%97/%E4%B8%8B%E9%A7%84%E9%85%8D%E5%88%97%E7%B3%BB/%E6%96%B0%E4%B8%8B%E9%A7%84%E9%85%8D%E5%88%97.txt)から移植した7面の同時打鍵配列 |
| 月 2-263 式 | [DvorakJ の定義](https://github.com/k-ayaki/dvorakj_2023/blob/master/data/lang/jpn/%E9%A0%86%E3%81%AB%E6%89%93%E9%8D%B5%E3%81%99%E3%82%8B%E9%85%8D%E5%88%97/%E6%9C%88%E9%85%8D%E5%88%97%E7%B3%BB/%E6%9C%882-263.txt)から移植した中指前置シフト配列 |

コンボは「出力する文字列 → その文字を出すキーの集合」で書く。
キーを物理位置ではなく文字で指すので、同じ定義を別の英字配列にも適用できる。

ローマ字の綴りは配列と対で意味を持つ。大西配列は上段と中段の同じ列に `y` と `s` が並ぶため、
`sya` が同指連続になる。`sha` なら `h` が隣の列に来て指が分かれる。
同じ綴り替えを QWERTY に適用しても効果は出ない。

入っているローマ字の綴り:

| 綴り | 内容 |
|---|---|
| 標準 | QWERTY 向け。ジャ行 `j`、シャ行 `sh`、チャ行 `ch` を使う（初期割り当ては訓令式） |
| 訓令式 | 1 かな 1 綴りの素のローマ字（`si` / `sya` / `zi` / `zya`） |
| 大西式 | 大西配列公式が前提とする綴り（`si` / `sha` / `ji` / `ja`） |
| AZIK | 拡張ローマ字。二重母音・撥音・促音をまとめて1綴りに落とし、打鍵数を削る（`かん` → `kz`、`きゃん` → `kyz` など）。促音は `;` の1打。[出典](https://github.com/toriwasa/azik-roman-table) の `azik_romantable.txt` から機械的に生成（`scripts/gen-azik-romaji.ts`） |

サイドバーの「ローマ字の綴りを設定」から、既定ルールを基底にした差分を保存できる。
差分は 1 行に `かな = 綴り` と書き、`しゃ = sha` や `かん = kz` のような複数かなの
見出しにも対応する。促音の自動生成の有無も綴りごとに設定できる。保存した綴りは、
モーダル内の「既定配列への割り当て」で QWERTY などにも適用できる。

## 自作の配列を足す

サイドバーの「配列を追加」から、段ごとに文字を並べて入れる。

- 数字段は空でよい。空なら QWERTY のものを使う
- 各段に置ける数は形状で決まる（ANSI なら 12 / 12 / 11 / 10）。超えると弾く
- 同じ文字を複数のキーに置いてもよい。打鍵には先に書いた方を使い、
  後の方は刻印だけ残す
- ローマ字の綴りを選べる。綴りは配列と対で効くので、配置に合う方を選ぶ。自作の綴りは
  「ローマ字の綴りを設定」から作成して割り当てる

追加した配列はそのブラウザの localStorage にだけ保存される。

既存の定義ファイルは「配列を追加」のファイル欄から取り込める。

- DvorakJ `.txt`: CP932 / UTF-8。配列表ブロックの単打と同時打鍵を読む
- Vial `.vil`: 第 0 層の配置とコンボを読む。コンボ出力が M0 などのマクロなら、
  text / tap アクションから出力文字列を復元する
- 紅皿 `.bnz` / `.ini`: UTF-16LE / UTF-8。ローマ字面またはかな面と、左右の親指シフト面を読む

面の出力にかなが含まれるかを中身から判定し、かな面は直接打鍵、ローマ字面は選択した
ローマ字テーブルを通して評価する。Enter・Delete・Esc・Home・End・矢印などの機能キーは
解析から外し、元ファイルのラベルだけを配列表に残す。未対応のキーコードや空のコンボは無視し、
取り込めた定義だけを保存する。対応付けられない面を無視した場合は、取り込み後に警告を表示する。
ファイル名やコメントは配列の同定に使わない。

## 既知の制限

- シフトを扱わない。大文字は小文字として数える
- 面定義を UI から編集する機能はまだない（面はコード定義のみ）
- 変換操作（変換キー・確定・文節移動）は打鍵列に含めない。打ち手による差が大きく、配列間では共通のため
- 出力される総移動距離は**下界**。窓の内側では常に小さい方を採るため、実際の運指はこれ以上になる
- コンボ・同時押しの効果は測らない（詳細は「[何を測っていないか](#何を測っていないか)」）
