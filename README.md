# keydist

キーボードの論理配列を、モデル文章を打った時の**指の総移動距離**で評価する。

https://tokiokashi.github.io/keydist/

## 配列の書き方

文字 → 打鍵ステップ列。ステップの列が順次性を、ステップ内の集合が同時性を表す。
キーは QWERTY 刻印で指す。

```json
"が": [["space", "f"]]   同時押し（1 ステップ）
"が": [["shift"], ["f"]]  前置シフト（2 ステップ）
"が": [["f"], ["shift"]]  後置シフト（2 ステップ）
```

1 本の指で複数キーを押す場合（キーの間を押す）は、その指の目標位置をキーの重心にする。

## 何を測るか

各打鍵について、その指がどこから動いてきたかを決めて距離を積む。

```
g = 0        →  d(前のキー, 今のキー)              同指連続。ホームに戻る時間がない
1 ≤ g ≤ N    →  min(d(前のキー, k), d(ホーム, k))   窓の内側。残る／戻るの小さい方
g > N        →  d(ホーム, 今のキー)                 復帰済み
```

`g` は前回その指を使ってから挟まった**他の打鍵数**、`N` は指を残す打鍵数の窓幅で利用者が設定する。
ホームへの復帰移動そのものは距離に計上しない。

詳細は [spec/distance-model.md](spec/distance-model.md)。

## 出力

合成スコアは作らない。次を独立に出す。

- 指ごと／全体の総移動距離
- 1 打鍵あたりの平均移動距離
- 入力 1 文字（ローマ字展開・コンボ結合の前、かな・英字）あたりの平均移動距離。
  打鍵数はローマ字の綴り・コンボ・かな直接入力で配列ごとに変わるため、
  「1 打鍵あたり」では打鍵数削減の効果が分母に吸収されて消える。
  文字数は展開前で固定するので、削減の効果はこちらに残る
- 入力 1 文字あたりのアクション（ステップ）数、および押下キー数。
  コンボ・同時押しは指の移動距離には現れないが（[何を測っていないか](#何を測っていないか)）、
  この 2 つには現れる。前者はまとめて打つほど下がる時間的なコスト、
  後者はキーを押す総回数（コンボでまとめても減らない）
- 配列 × 指のマトリックスとして、指ごとの移動距離 [u/文字]、押下数 [押下/文字]、
  隣接指間距離の平均 [u] を並べて出す。押下数の面には生の押下回数もツールチップで出す
- 同指連続回数と比率
- 隣接指間距離の平均と実測最大値（標準偏差はばらつきとして併記。大きいほど上下段をまたぐ運指が多い）
- `N` を振った時の総移動距離の変化

## 何を測っていないか

コンボ（複数キーの同時押しで 1 文字を出す）や同時押しは、指の移動を減らす最適化ではなく
「複数打鍵を 1 打にまとめる」最適化なので、**距離軸には現れない**。実測でも、移動の多い
配列では距離が減り、移動がすでに最小化された配列ではむしろ増える。

測定条件: かな 290 文字 / `N` = 3 / ロウスタッガード / 綴りは**訓令式**。
綴りは配列と対で効くので、大西を大西式綴り（`sh` / `ji`）で打つと別の値になる
（コンボなしで 149u、同指連続 1）。

| 配列 | コンボなし | コンボあり | 同指連続 |
|---|---|---|---|
| QWERTY | 292u | 280u | 32 → 38 |
| Colemak-DH | 144u | 171u | 3 → 28 |
| 大西 | 153u | 157u | 5 → 7 |

総距離だけを見て「コンボは効果がない」と読まないこと。打鍵数の削減は
「入力 1 文字あたりのアクション数」（[出力](#出力)参照）の側に直接出るので、
指標としてはそちらで読む。

詳細は [spec/distance-model.md §12](spec/distance-model.md#12-数値の性質)。

## 日本語

同じかなテキストを、ローマ字配列にもかな配列にも食わせて比較できる。

- **ローマ字配列** — かな → ローマ字のテーブルを通してから打つ。
  テーブルは配列の属性なので、配列ごとに別の綴りを割り当てられる。
  促音は差し替え後の綴りから展開する（`っか` → `kka`、`し` を `shi` にすれば `っし` → `sshi`）
- **かな配列** — かな → 打鍵ステップ列を直接持つ。テーブルを通さない

どちらも最終形は打鍵ステップ列なので、評価器は両者を区別しない。

入っている日本語向けの配列:

| 配列 | 出典 |
|---|---|
| 大西 | 公式配置。公式が前提とする綴り（シャ行 `sh` / じ `ji` / じゃ行 `j`）で打つ |
| 大西（私家版 + コンボ） | 下段を差し替えた版に、Vial キーマップのコンボ 73 件を適用。綴りは訓令式 |
| 薙刀式 v18 | [公式配布の DvorakJ 定義](https://oookaworks.seesaa.net/article/456099128.html)から機械的に生成 |

コンボは「出力する文字列 → その文字を出すキーの集合」で書く。
キーを物理位置ではなく文字で指すので、同じ定義を別の英字配列にも適用できる。

ローマ字の綴りは配列と対で意味を持つ。大西配列は上段と中段の同じ列に `y` と `s` が並ぶため、
`sya` が同指連続になる。`sha` なら `h` が隣の列に来て指が分かれる。
同じ綴り替えを QWERTY に適用しても効果は出ない。

入っているローマ字の綴り:

| 綴り | 内容 |
|---|---|
| 訓令式 | 1 かな 1 綴りの素のローマ字（`si` / `sya` / `zi` / `zya`） |
| 大西式 | 大西配列公式が前提とする綴り（`si` / `sha` / `ji` / `ja`） |
| AZIK | 拡張ローマ字。二重母音・撥音・促音をまとめて1綴りに落とし、打鍵数を削る（`かん` → `kz`、`きゃん` → `kyz` など）。促音は `;` の1打。[出典](https://github.com/toriwasa/azik-roman-table) の `azik_romantable.txt` から機械的に生成（`scripts/gen-azik-romaji.ts`） |

## 自作の配列を足す

サイドバーの「配列を追加」から、段ごとに文字を並べて入れる。

- 数字段は空でよい。空なら QWERTY のものを使う
- 各段に置ける数は形状で決まる（ANSI なら 12 / 12 / 11 / 10）。超えると弾く
- 同じ文字を複数のキーに置いてもよい。打鍵には先に書いた方を使い、
  後の方は刻印だけ残す
- ローマ字の綴りを選べる。綴りは配列と対で効くので、配置に合う方を選ぶ

追加した配列はそのブラウザの localStorage にだけ保存される。

## 既知の制限

- シフトを扱わない。大文字は小文字として数える
- かな配列（月配列・薙刀式など）の定義がまだ入っていない（記法は対応済み）
- 変換操作（変換キー・確定・文節移動）は打鍵列に含めない。打ち手による差が大きく、配列間では共通のため
- 出力される総移動距離は**下界**。窓の内側では常に小さい方を採るため、実際の運指はこれ以上になる
- コンボ・同時押しの効果は測らない（詳細は「[何を測っていないか](#何を測っていないか)」）
