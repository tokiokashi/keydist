# ADR-0009: 単体ページの計算をWeb Workerで走らせる

- 番号: ADR-0009
- 日付: 2026-10-06（このリポジトリの最初のコミットの日。旧リポジトリから履歴を持たずに取り込んだため、決めた日は読めない）。後の調整は2026-10-20（コミット `cf7c4853`）と2026-11-02（issue #465、コミット `45bd7e9d`）
- 状態: 採用

## 背景

長いテキストでは、計算が長くなり、メインスレッドで走らせると入力とスクロールが止まる。
決めた当時の議論は、取り込み前の履歴にあり読めない。以下は、`docs/architecture.md` と、後のコミット本文に書かれている内容に限る。

## 決定

- 単体ページの計算は、ブラウザではWeb Workerで走らせる。長いテキストで入力とスクロールが止まらないため（`docs/architecture.md`「依存の規則」）
- ペインが頼む窓口は `engine/computer.ts` の `EngineComputer`。メインスレッドの `EngineCache` と、Worker越しの `engine/worker-client.ts` のどちらも満たす
- Workerの入口は `app/standalone/engine-worker.ts` で、そこに載せたAnalyzerの定義だけがWorkerで計算できる
- 数値は変わらない。Workerの中も同じ `EngineCache` と同じ純関数で、メッセージは値の複製だけ
- Workerは、走っている依頼を途中で止められない（止めると立て直しになり、Worker内のキャッシュが空になる）。このため、長くなる計算は小さい依頼に分ける。集合のAnalyzerは、メンバー1件・段1つの計算を `SetAnalyzerWarmup` に切り出せる。後回しの依頼は、後回しでない依頼が待っていない時にだけWorkerへ送る
- 計算が長く、いつも見ているとは限らないAnalyzer（今はN感度）は、Workspaceのペインでは画面に入るまで計算を始めない（2026-10-20、コミット `cf7c4853`）
- メインスレッドへ返すTraceを、打鍵の列を除いた要約にする。Workerから打鍵の列を複製すると、長いテキストで数GBがメインスレッドに残ったため。打鍵の列が要る打鍵再生は、構造解析の結果が持つ同じ列を読む。評価に渡すテキストが40万字を超える時は、計算を始めずに知らせる（2026-11-02、issue #465、コミット `45bd7e9d`）

## 却下した案

- メインスレッドで計算し続ける案は、入力とスクロールが止まることを理由に退けられている
- 走っている依頼を打ち切る案は、Worker内のキャッシュが空になる立て直しになるので採らず、依頼を小さく分ける方を採った（`docs/architecture.md`）

## 結果

- Workerの入口に載せないAnalyzerは、Workerで計算できない。Analyzerを足す時は、入口にも足す（ADR-0006）
- 計算部が純粋な層に収まっている（ADR-0007・ADR-0008）ので、Workerへ数値を変えずに移せた
- 40万字を超えるテキストは、計算を始めずに知らせる。この上限の根拠は、issue #465の修正が数GBのメモリ使用を抑えたことで、上限そのものを測った記録は読み取れない
