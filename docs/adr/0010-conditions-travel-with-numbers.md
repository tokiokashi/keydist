# ADR-0010: 測定条件を数値に付随させ、比較の可否は裁定しない

- 番号: ADR-0010
- 日付: 2026-10-06（取り込みの日。決めた日は読めない。READMEの「日付」を参照）
- 状態: 採用

## 背景

物理配列・指の割当・窓幅 `N`・綴りの規則などの測定条件を変えると、数値は変わる（`spec/distance-model.md` §12.3）。
配列ごとに適した物理配列を選んで「その配列の最良」同士を比べるのも、物理配列を固定して論理配列だけを比べるのも、どちらも成立する問いで、どちらか一方の比べ方を正解とする根拠がモデルの側に無い。

決めた当時の議論は、取り込み前の履歴にあり読めない。以下は、`spec/distance-model.md` と `AGENTS.md` に書かれている内容に限る。

## 決定

- 条件は配列ごとに変えられる
- モデルが負う責務は、どの条件で出した数値かを常に数値と一緒に運ぶこと
  - 出力（`Metrics`）は、使用した条件を保持する
  - 画面は、既定と異なる条件で測った配列について、その差分を数値のそばに示す
  - 数値を持ち出す時（書き出し・共有）は、条件を同じ入れ物に入れて運ぶ
- 読み手が条件を見て比較の意味を判断できる限り、条件を揃えることは要求しない
- 優劣の判定・順位付け・合成スコアを作らない（`AGENTS.md` 「数値を扱う時・外に出す時」）

## 却下した案

- 条件を揃えた比較だけを許す案は、却下の理由が書かれている。どちらの比べ方も成立する問いで、モデルがどちらかの比べ方を正解にする根拠が無い（`spec/distance-model.md` §12.3）
- 優劣の判定・順位付け・合成スコアは、作らないことが `AGENTS.md` に書かれている。理由は書かれていない

## 結果

- 設定を足す基準（`AGENTS.md`）も、同じ責務に沿って書かれている。推奨値を既定に置き、既定と違う設定で出た数値にはその差分を示す。示せない設定は足さない（`AGENTS.md` 「設定項目を足すか決める」）
- 条件の解決順は、既定値 → 全体 → Workspace → 物理配列 → 打ち方 → 配列 → Setupの順（ADR-0003）
- 条件が数値に付随する仕組みは、条件の要約・出どころの札・`Metrics` の条件のスナップショット・書き出しと共有の入れ物にある
- 漢字を読みに直して評価した数値は、読みの辞書の名前と版、解析器の名前と版を、条件のスナップショットに持つ。読みは辞書と解析器の版で変わるため
