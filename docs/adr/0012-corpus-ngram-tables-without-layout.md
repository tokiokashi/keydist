# ADR-0012: コーパスのn-gramの表を、配列に依らない前処理と、走りごとの数え方で作る

- 番号: ADR-0012
- 日付: 2026-11-12（PRの日付）
- 状態: 採用

## 背景

言語の側の統計として、コーパスの文節の読みの系列とかなの系列のn-gramの表と、統計が足りているかの量が要る（issue #100）。
かなの系列には、すでに `docs/kana-chain-comparison.md` の定義と実装（`interpretation/ngram-table.ts`）がある。その表は、配列ごとの評価に渡すテキストの全体から作り、句読点・打てない文字も1文字に数え、鍵は文字を続けて書いた文字列である。
コーパスの表は配列の定義を参照しない（issue #100）。文節の読みは文字列の単位なので、文字を連結した鍵のままでは、区切りの違う並びが同じ鍵になる。

## 決定

- 数え方は `ngram-table.ts` を一般化して使う。`countNgrams` に単位をつなぐ区切り（`separator`）を足し、既定の空は従来どおり文字を連結した鍵にする。新しい表の定義を別に作らない。走りごとに数える `countNgramsInRuns` を足す
- 文節の系列の鍵は、読みを `U+0000` でつなぐ。前処理が制御文字を取り除くので読みに現れず、含む単位は例外にする
- 前処理は、`prepareEvaluationText` を配列が `,` `.` を持たない条件で呼ぶ。片仮名の書き換えは配列の見出しで決まるので当てず、片仮名とひらがなを別の文字に数える
- 空白・改行と、読みに直らなかった漢字で系列を切り、n-gramは走りの中だけで数える。`。` `、` では切らない
- 統計が足りているかは、文脈が1回だけの割合（Good-Turing推定を文脈へ当てた量）で見る。上限は `kana-chain-comparison.md` の候補が1つの段の割合の上限と同じ0.1で、結果を見る前に固定した

定義は `docs/corpus-ngram.md`。実装は `interpretation/corpus-ngram.ts`。

## 却下した案

- かなの系列だけ、配列ごとの評価に渡すテキストから作る案。2つの系列を同じコーパス・同じ前処理で並べて比べる目的に合わない。配列によって変わる段（片仮名の書き換え）が入ると、配列ごとに表が変わる
- 読みに直らなかった漢字を、除いてつなぐ案。実際には隣り合わない文字・文節の並びができる。`kana-chain-comparison.md` も、範囲を除いた所に新しい並びを作らない
- 句読点と段落の境目を含め、全文を1つの系列にする案。段落の境目をまたぐ文節の組は、言語の内容でなく文書の構造で決まる。文の区切り（`。`）は打鍵で続けて打つので切らない
- 続きが1種類しか無い文脈の出現の割合（`kana-chain-comparison.md` の候補が1つの段に近い量）を主にする案。表から出す量は、生成した段の割合とは別の量で、既存の上限を持ち越す根拠が無い。出現が1回の文脈の割合は、Good-Turing推定として読める。前者は今回出さない

## 結果

- 既存の距離モデルの値・回帰の記録・`kana-chain-comparison.md` の測定値は動かさない。`countNgrams` の既定の引数の挙動は変えていない
- 先行研究に、文脈が1回だけの割合の標準の閾値は確認できていない。0.1は既存の上限との整合だけを根拠にする
- 『吾輩は猫である』全文では、文節の系列は1次で上限を超える（`scripts/corpus-ngram-tables.ts` の出力）。表そのものをリポジトリに置くかは、この判断で決めない
