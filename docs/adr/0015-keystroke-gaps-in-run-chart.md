# ADR-0015: 打鍵の間隔をRun Chartの下に並べ、記録の選択は解析設定に置いて共有リンクに載せない

- 番号: ADR-0015
- 日付: 2026-11-15
- 状態: 採用

## 背景

ADR-0014で、評価に渡したテキストの範囲を打った記録（ストロークごとの時刻）を保存できるようになった。
次に、記録の打鍵の間隔を、Run Chartの点と同じ横軸（評価に渡した本文の文字位置 `e`）に並べて、間隔が長くなる箇所が指標の大きい箇所や文節の区切りと対応するかを、利用者が数値で見られるようにする。
ADR-0014は、記録を図に出すことと集計を範囲外とした。

## 決定

- **置き場はRun Chartにする。** 指標の図の下に、同じ横軸・同じ表示の範囲・同じ区切りの線で間隔の図を置く（`analyzers/run-chart/record-view.tsx`）。定義は `spec/keystroke-record.md` §6
- **選んだ記録の `id` は、Run Chartの解析設定 `record` に置き、共有リンク（URL）には載せない。** 記録は利用者の手元の資産で、リンクを開いた先には無い。Workspaceの資産と書き出しのファイルには、他の解析設定と同じく載る。手元に無い `id` は、見つからない旨を示す
- **記録を今の入力と照らす計算はengineが持つ**（`engine/keystroke-record-check.ts`）。打鍵の列を作り直す計算は、純粋な抽出から呼べないので、抽出が読む資産に選んだ記録（`ExtractionAssets.keystrokeRecord`）を載せ、engineが記録を照らした結果をメンバーの `recordCheck` として渡す。食い違いの判定は `spec/keystroke-record.md` §4.1
- **記録を選んでいる間は、区切り方によらず文節の分割器を読み込む。** 文節の区切りの直後の表が文節の区切りを使うため（`usesSegmentation`・`assetsKeyOf` を記録の選択に合わせる）
- **`e` ごとの値は、その `e` を最初に持つストロークの間隔にする。** その `e` に入る直前の止まりが現れるのは、その `e` を打ち始めるストロークだからである
- **集計窓でならした値は出さない。** 間隔は1つの `e` に1つの値で、窓でならすと、止まりが1文字に現れるかを見分けにくくなる
- **表は生の間隔の打数・四分位平均・平均を並べ、打数の下限も2群の差も置かない。** 基準の時間と打鍵の上乗せは引かない。測りたいのは、文章を打つ測定が引いて消す側の止まりだからである

## 却下した案

- **別のAnalyzerを足す。** 横軸・表示の範囲・区切りの線をRun Chartとそろえるには、同じ計算（点の位置・範囲・区切り）を重ねて持つか、結果を共有する仕組みが要る。Run Chartの抽出が持つ値をそのまま使える方が単純である。Workspaceで別ペインにして並べる使い方は、今は要望が無い
- **選んだ記録をURLに載せる。** 開いた先に記録が無く、いつも「見つからない」になる
- **集計窓でならした値を並べる。** 上記
- **記録の食い違いを警告しつつ間隔を出す。** 食い違う条件のもとの間隔は、指標の図の位置と対応しない。出さずに、食い違う項目を示す
- **間隔と指標の相関係数を出す。** 相関する量を並べて優劣に読まれる恐れがあり、この判断の範囲に入れない

## 結果

- 間隔の定義・食い違いの判定・表の集計は `src/interpretation/record/keystroke-gaps.test.ts` と `test/keystroke-record-check.test.ts` が確かめる
- 打鍵の列を作り直す計算は、記録を選んだペインの最初の抽出で1回走る（結果はメンバーの部分結果として覚える）。全文の作り直し1回分の時間は、ADR-0014の測定（10万字で2.14秒）と同じ桁である。記録を選んだペインで測っていない
