# ADR-0016: 薙刀式私家版の中指シフトは、前後の打鍵と同じ指になる時に同じ手のキーで押す

- 番号: ADR-0016
- 日付: 2026-11-17
- 状態: 採用

## 背景

薙刀式私家版（#876）は、中指シフト `d` `k`・濁音 `f` `j`・半濁音 `v` `m` のどれも、左右のどちらのキーで押しても同じかなになる。配列を足した時は、どのシフトもかなのキーと反対の手のキーを既定の打ち方にした。
そのため、ます（`k` + `f` の後に `i`）のように、反対の手のシフトのキーが前後のかなと同じ指になる打鍵が多く、Testerの練習文で同指が362回と、全配列で最も多かった。

オーナーは実際には次のように打ち分けている（#878）。

1. 続けて同じシフトを押す間は、同じキーを押し続ける。同指になってもキーを替えない
2. 中指シフトは反対の手から始め、反対の手のキーが前後のかなと同じ指になる時は同じ手のキーにする（ます、すま は `d`）
3. 濁音のシフトは、同じ指になっても反対の手のまま押す（でく は `j` + `e` の後に `h`）

1は、どこで区切って打つかで決まる（め／ます なら `d`、めま／す なら `k` のまま）。距離モデルは打鍵の区切りを持たない。オーナーは2と3だけを今入れると決めた（#878 のコメントに残した）。

## 決定

- 配列が `sameFingerAvoidingShiftKeys` に持つシフトのキーだけ、前後の打鍵を見て押す手を替える。薙刀式私家版は `d` `k` を持つ。定義は `spec/distance-model.md` §4の Input Alternative Selection Policy
- 既定の打ち方と、トリガーのキーだけが集合の別のキーに替わった打ち方とで、同じ指になる打鍵の数を比べ、少ない方を選ぶ。数えるのは、同じアクションの中・直前の入力の最後のアクション・次の入力の最初のアクションとの3つ
- 次の入力は、最長一致で切り出して、手を替える選び方を掛ける前の打ち方で見る
- 濁音・半濁音のシフトは集合に入れず、反対の手のままにする
- 条件にしない。この打ち方は薙刀式私家版という1人の打ち方の配列の定義の一部で、他の打ち方を選びたい人は想像できるが実例が無い。`AGENTS.md`「設定項目を足すか決める」の「割れる人を想像できるが実例が無いもの」に当たる

## 却下した案

- **手を替える選び方をすべての左右のシフトに掛ける。** 中指シフト月光・月配列U9も左右のシフトを持つが、作者の打ち方の根拠が無いまま数値が変わる。薙刀式私家版でも、濁音はオーナーの打ち方と食い違う
- **シフトの種類（中指・濁音）を配列に書かず、生成側でキーの名前から決める。** 生成側が配列ごとのキーを知ることになる。配列の定義に持たせる方が、他の配列で同じ打ち方を足す時に生成側を変えずに済む
- **前後の打鍵を全部見て、同じ指の数が最小になる組を探す。** 入力ごとに直前と直後だけを見る今の選び方で、オーナーの例（ます・すま・でく）は全部説明できる。全体の最小化は計算が重く、選ばれる打ち方が離れた文字で変わり、仕様から追いにくい
- **条件にして、利用者が手を替えるかを選べるようにする。** 上の「決定」のとおり、選び分けたい実例が無い。要望が出たら、置き場と既定値を決めて足す
- **1（押し続けの区切り）も今入れる。** 区切りを持たないモデルでは、め／ます と めま／す を分けられない。#878 に残す

## 結果

- Testerの練習文（空白を除いた1676かな）・ロウスタッガード（ANSI）・ほかは既定の条件で、薙刀式私家版の同指は362回から256回、移動距離は1335.7uから1281.7uになった。他の配列の数値は動かない
- `src/trace/generate.test.ts` が、ます・すま で `d`、まで で `k`、でく で `j` を選ぶこと、打てない文字を挟んだ先の入力を見ないこと、替えたキーが同じ打鍵の別のキーと同じ指になる時に替えないことを確かめる
- 押し続けの区切り（1）は入っていない。めます は、め を `k`、ま を `d` で押す
