# ADR-0017: 漢直の配列は、表に漢字がある語を表記のまま打ち、評価に渡すテキストは読みのままにする

- 番号: ADR-0017
- 日付: 2026-11-20
- 状態: 採用

## 背景

漢字直接入力（漢直）の配列は、漢字を読みから変換せず、1字ずつ決まった打鍵列で打つ。T-Codeは、40キーから2つを順に打つ1600通りの打鍵列に、ひらがな・カタカナ・漢字・記号を割り当てている。

今の評価は、配列に渡す前に、テキストの漢字を、どの配列でも読みに直す（`spec/distance-model.md` §4.6の1.）。評価に渡るテキストに漢字が残らないので、漢直の配列が出力に漢字を持っていても、漢字の打鍵列は使われない。

漢直の配列を他の配列と同じテキストで評価するには、次の5つを決める必要があった。

1. 漢字を表記のまま打つ対象と単位
2. 配列で打てない漢字を含む語の扱い
3. 評価に渡すテキストと、入力かな数 `C`・文字数 `W`・窓幅 `N` の数え方
4. コンボを止める境と、利用者が直した読みの扱い
5. 変換の操作を数えないことによる偏りの書き方

形態素解析は、語ごとの読みだけを返し、1字ごとの読みは返さない。組み込みの44配列のどれも、出力に漢字を持つ見出しを持たない（`LAYOUT_BY_ID` の全見出しを `\p{Script=Han}` で検査した）。

## 決定

定義は `spec/distance-model.md` の §4.3「漢直の配列と表記で打つ語」・§4.6・§7 R3・§11.5・§12.4と、`spec/keystroke-record.md` の「文字位置」の節にある。

- 出力に漢字を含む見出しを1つ以上持つ配列を、漢直の配列とする。ローマ字を経ない打ち方の漢直の配列を評価する時だけ、§4.6の1.で読みに置き換える語のうち、表記を最長一致で配列の見出しに切り分けられ、読み飛ばす字が残らない語を、表記のまま打つ。判定は語の単位で、表記だけで決める
- 表記を切り分けられない字が1字でも残る語は、語全体を読みで打つ
- 評価に渡すテキストは、どの配列でも読みのままにする。表記で打つ語は、その読みの範囲を1つの塊として、表記の見出しの打鍵列で打つ
  - `C` は `Trace.inputChars`（読みのテキストの字数）で、配列に依らない
  - `W` は、表記で打つ語も読みに置き換えたものとみなした値で、漢直でない配列と同じになる
  - 表記で打つ語の入力は、見出しの数によらず、どれも語の読みの範囲全体を覆い、`N` はその範囲で数える
  - 打鍵再生と打鍵の記録には、表記の見出しが出る
- コンボを止める境は読みのテキストの位置に置き、表記で打つ語の読みの範囲の内側に来た境は置かない。利用者が直した読みは、表記で打つかの判定に使わず、語の読みの範囲と `C` だけを決める
- 辞書に読みが無い語（未知語）と辞書を読み込めない時は、テキストに残った漢字を、見出しにあれば打ち、無ければ `skipped` に数える。この扱いは変えない
- §12.4に、変換の操作を打鍵に数えないことで、漢直の配列とかな配列の数値に偏りが出ることを書く

実装は次の形にした。

- 読みに置き換えた語の、読みのテキストでの範囲と表記を、語の列から求める（`input/text/notation-words.ts`）。画面側（`hosts/shared/reading-evaluation.ts`）が `PaneText.notationWords` に、配列を見ずに全部持つ
- `resolveEngineInput` が、漢直の配列をローマ字を経ずに評価する時だけ、候補を評価に渡すテキストの位置と前処理（記号と英数字の範囲）の後の表記へ写し、`ResolvedInput.notationWords` に載せる。他の配列は空にする
- `generateTrace` が、表記を見出しに切り分けられる語だけを、読みの範囲の代わりに表記の字の列として打つ。計算部は画面側に依存しない。`ResolvedInput.notationWords` はTraceのキーに入る
- 漢字の見出しを持たない配列は、`ResolvedInput.notationWords` が空なので、Traceのキーも数値も変わらない
- `MODEL_VERSION` を21から22へ上げた。自作の配列で漢字を見出しに持つものは、同じSetupとテキストで数値が変わるため

## 却下した案

表記で打つ語を、評価に渡すテキストの上でどう扱うかの比較。

| 案 | `C` | `N` が指す範囲 | 採否 |
|---|---|---|---|
| 読みのテキストのまま、表記で打つ語を塊にする | 配列に依らない | 配列に依らない | 採る |
| 評価に渡すテキストに表記の漢字を残し、その字数で数える | 配列ごとに変わる。1かな換算の量の分母がそろわない | 漢字1字が1位置になり、§7 R3が避けている「配列ごとに同じ `N` が指す範囲がずれる」ことが起きる | 採らない |

配列で打てない漢字を含む語の扱いの比較。

| 案 | 打鍵列 | 必要な情報 | 採否 |
|---|---|---|---|
| 語全体を読みで打つ | 表に無い漢字が1字でもあれば、語の漢字は全部読みで打つ | 今の語の列だけ | 採る |
| 表にある漢字だけ表記で打ち、残りの字だけ読みで打つ | 実際の交ぜ書き変換に近い | 1字ごとの読み。形態素解析は語ごとの読みしか返さない | 採らない |
| 表に無い漢字を打てない文字として `skipped` に数える | 表に無い漢字の打鍵が0になる | 今の語の列だけ | 採らない。打たない字が増えるほど距離が小さく出る |

そのほかに比べた案。

- **表記で打つかの判定に、利用者が直した読みを使う。** 直した読みは、辞書の読みと同じ語に当たる別の読みで、表記の字の打鍵列を変えない。判定を表記だけで決めれば、読みを直しても打鍵列が変わらず、直しの画面が打鍵を動かす量を、読みの範囲の長さ（`C`）に限れる
- **表記で打つ語を、ローマ字を経る打ち方の配列にも当てる。** ローマ字を経る打ち方は、読みのかなを綴りの単位に切り、その単位を打鍵の最小の単位として持つ（§7 R3、記録の打った綴り）。表記の見出しは綴りの単位に載らず、綴りの窓の作り直しも表記で打つ語を持たない。ローマ字の配列が漢字の見出しを持つ例が無いので、当てずに、読みで打つ。漢字を見出しに持つ配列がローマ字を経る打ち方を選べる例が出た時に見直す
- **語の候補を、配列ごとに画面側で選んで渡す。** 画面側が配列の見出しを知る必要が出て、1つのテキストを複数の配列で比べるペインでは配列ごとに語の列を持つことになる。候補を配列に依らず全部持たせ、配列を知っている `resolveEngineInput` で選ぶ

## 結果

- 組み込みの44配列は、出力に漢字を持つ見出しを持たない。`test/fixtures/analyzer-regression.json` の81件の数値は、`MODEL_VERSION` を上げて作り直した後も、変更の前と同じだった
- `src/trace/notation-words.test.ts` と `src/engine/notation-words.test.ts` が、漢字の見出しを数個だけ持つ小さな配列で、表記で打つ語・読みで打つ語・`C` と `W` の一致・`N` の範囲・境・見出しの切り出しの端・キーを確かめる。外部の漢直の表はリポジトリに入れていない（ライセンスを確認中）
- 配列の定義（T-Codeなど）は、別の作業で足す。定義の持ち方（2打の順次打鍵など）と、表記で打つ語の選び方の相互作用は、その時に実際の表で確かめる
