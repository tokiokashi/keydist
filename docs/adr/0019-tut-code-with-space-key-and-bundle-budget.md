# ADR-0019: TUT-Codeは「Aモード」の表を使い、空白キーを2打目以降の右親指として持つ

- 番号: ADR-0019
- 日付: 2026-11-20
- 状態: 採用

## 背景

TUT-Codeは、T-Code（ADR-0018）と同じ40キーと空白キーに、1打から4打の打鍵列で字を割り当てる。出典はT-Codeと同じ配布物の `tut.tbl` で、2つの表を持つ。T-Codeの表（`t.tbl`）と違い、41番目の欄（空白キー）に字を置き、3打と4打の字は表の欄に入れ子の表を持つ。決めることは次の4つだった。

1. どちらの表を使うか
2. 空白キーの扱い
3. 打鍵列の持ち方と配列図
4. 組み込みの表が増やす配布物のサイズの扱い

## 決定

- 「Aモード（ひらがな）」の2652字を使う。「Bモード（カタカナ）」と、モードを切り替える機能の欄は使わない。評価テキストの前処理（`spec/distance-model.md` §4.6）が配列の見出しに無い片仮名をひらがなに書き換えて打つので、片仮名の語は「Aモード」の表で打てる
- 空白キーは右親指（`thumb-r`）とする。2打目以降の空白キーは `spaceThumb`（§4）に依らず右親指のままにする。`spaceThumb` は今の仕様のまま、空白の単打だけを決める
- 各字を打鍵の数だけのステップの順次打鍵で持ち、どの打鍵も層のトリガーに数えない（ADR-0018と同じ）。配列図の順次打鍵の照合は、各ステップが1キーの順次打鍵なら何打でも扱うので、足した変更は無い
- 写しは `test/fixtures/sources/tut-code.json`、定義は `src/input/layouts/tut-code.ts`

## 却下した案

| 案 | 採否 |
|---|---|
| 「Bモード（カタカナ）」の表も持ち、切り替えのキーを層として持つ | 採らない。評価テキストの前処理が片仮名をひらがなに書き換えるので、カタカナの表を使う入力が生まれず、切り替えのキーが層・トリガーの集計に数えられて配列の性質が読めなくなる |
| 2打目の空白キーも `spaceThumb` が `left` の時に左親指へ移す | 採らない。§4の改訂が要る。数値に使う仕様を、配列を1つ足す変更で広げない |
| 漢直の表を遅延読み込みにして、バンドルの上限を上げない | 採らない（下の「バンドルの上限」） |

## バンドルの上限

組み込みの表は、計算用Workerと、画面のJavaScriptの両方に入る。TUT-Codeの追加でgzipサイズは、計算用Workerが92253Bから100707B（上限102000Bの内）、`JavaScript全体` が949503Bから965611B、個別画面（ヒートマップ）の初期読み込みが398731Bから406382Bに増えた。`JavaScript全体` と個別画面の2つが上限を超えたので、上限を970000Bと410000Bに上げた。

- 上限を上げる: 配列の定義は同期の読み出しで、画面・Worker・Testerが `LAYOUT_BY_ID` から直接引く。増加は、画面に出す2652字の表そのものである
- 遅延読み込みにする: 漢直の表だけを別のチャンクに分け、使う時に読む。配列の定義の読み出しが非同期になり、配列を引く全ての経路（解決・Tester・配列図・読み込みの待ち）に待つ処理が要る。今回の増加は `JavaScript全体` で16108Bで、上限の引き上げで足りる間は、遅延読み込みの作りを足さない。漢直の配列がさらに増える時に、改めて比べる

## 結果

- `src/input/layouts/tut-code.test.ts` が、組み込みの表と出典の写しの一致、2652字の各字の打鍵の数と空白キーの位置、層が単打の1つでトリガーの押下が0であることを確かめる
- `spaceThumb` が `left` でも、ASCIIの空白を持たない配列（T-Code・TUT-Code）は空白の単打を左親指へ移さない（`canTypeSpaceWithLeftThumb` が、ASCIIの空白の入力を持つ配列だけを対象にする）。TUT-Codeの全角空白の1打は、`spaceThumb` に依らず右親指のまま残る
