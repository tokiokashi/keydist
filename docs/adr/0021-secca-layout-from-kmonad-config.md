# ADR-0021: 雪華はKMonadの設定を再現して作った1つの表で持ち、かなは同時押し、漢字と熟語は順次打鍵にする

- 番号: ADR-0021
- 日付: 2026-11-21
- 状態: 採用

## 背景

雪華（h3at2o/secca）は、かなを薙刀式の同時打鍵で打ち、漢字約3700字・異体字・熟語約2.4万語を、左手の2キーを押したまま右手を打つ順次打鍵で打つ配列である。定義は文字の表ではなく、KMonadの設定（`config.kbd`、51キー・175層）とXComposeの表（`.XCompose*`）で、設定は押すキーから、XComposeの記号列（compose sequence）を出力するキーを引く。文字から打ち方を逆に求める仕組みが要る。決めることは次の6つだった。

1. 打ち方の持ち方（出典の写しと、組み込みの表）
2. かなの表し方
3. 漢字・異体字・熟語・固有名詞・記号の表し方、空白キーの扱い
4. 右手のキーの位置
5. 作れない行の扱い
6. 配布するサイズの扱い

## 決定

- 出典の写しを `test/fixtures/sources/secca/` に変えずに置く。`scripts/secca-core.ts` が `config.kbd` の語彙（`tap-next`・`tap-next-release`・`layer-toggle`・`around` など）を読み、押す順の再生で、どの押し方がどのcompose sequenceを出すかを求める。`scripts/secca-table.ts` が、各見出しの打ち方を1つ選んで表にする。表は `src/input/layouts/tables/secca.json` で、`scripts/gen-secca-table.ts` が作る。`test/secca-source.test.ts` が、写しから作り直した表が組み込みの表と一致することを確かめる
- 押す順の再生は、押した順にキーを処理し、最後のキー以外はホールド側の役を受け持つ、と簡約する。最後のキーはタップ側の役を受け持つ。出力は押した時点で出る。ここに「層を保っているキーを全部離す」操作（`^`）を足す。左手のくずし字入力（「d・f・kを押して、dとfを離し、wを押す」で人形）と、空白キーを打った後に離す必要がある熟語のうち約77行（Compose列の途中でキーを離さないと次の層に入れない）は、この操作が無いと作れない。全キーを最後まで押し続ける簡約では、熟語の約2.1万行が作れなかった
- かなは、同じキーの集合の見出しを1ステップの同時押しで持つ。単打・空白キーとの同時押し・2キー・3キーの組があり、空白キーを先に押す組は、薙刀式の「中央シフト」と同じに、空白キーを押した面（`SandS`）の1つで持つ。表に出るかなの面の割り当て（行・段・濁音・半濁音・拗音）は、薙刀式v18の面を型にして、表のかなのキーの組で置き換える。表にあるのに型の面に置き場が無い組は、生成時に失敗させる。非空白の複数キーの組91個が、薙刀式v18の面のセルと完全に一致する。違う6つ（空白キーを押した面のぬ・ほ・ひ・む・ね・れ）は、作者の設定を優先して表の値にする
- 漢字・異体字・熟語・固有名詞・記号は、新しく押すキーごとに1ステップの順次打鍵で持つ。空白キーは右親指の1ステップに数える。どれも層のトリガーに数えない。数えるのは、かなの空白キーを押した面だけで、押下の1回として数える（ADR-0018・ADR-0019と同じ）。押す順で字が変わる朝（f→d→j）と元（d→f→j）、暴（f→d→j→k）と担（d→f→k→j）は、別の打鍵列になる
- 右手は、作者がQWERTYで書く位置で持つ。作者の設定は右手を1列右へずらす物理配列（orz）に合わせてあるので、設定のキーを、作者の表記のQWERTYの位置へ戻す。左手は変えない。ずらしは手の置き方で、字の割り当てではないので、どの物理配列の上でも、配列の位置で測る
- 使う層は、かなの基底層（`kana1`）から層切り替えで入る層に限る。出力が空の行（112行）と、カタカナのモードで出る行（375行。CapsLockの状態を持つモードで、今の打鍵の形では書けない）は表に入れない。残る59行は、どの押し方でも作れないので入れない。内訳は、全角英字52行（層切り替えで入る専用の層に依る）、記号3行（`grave minus`・`grave period`・`asciitilde underscore`。設定が2つのcompose sequenceに分けて出す）、異体字4行（`] , - g` の経路に `,g` の別名が無い躯・脃・醤・飰）である。他の行は、漢字3703/3703、異体字293/297、熟語23970/23970、固有名詞2/2を作れた
- 表は1つのファイルにする。生成した表は378597B（gzip 173270B）で、ADR-0020の独立したファイルとして配る。計算用Workerと画面のJavaScriptには入らない

## 却下した案

| 案 | 採否 |
|---|---|
| 作者のXComposeの表から、文字と打ち方を別の表に手で起こす | 採らない。`config.kbd` が層と押し方を決めるので、設定を再現しないと、写しと表がずれた時に見つからない |
| 全キーを最後まで押し続ける簡約 | 採らない。熟語の約2.1万行が作れない。作者の `kuzushiji.txt` は左手を離すと書いている |
| かなの記号（`「` など）を薙刀式の編集モード1と同じ同時打鍵にする | 採らない。作者の設定は記号をcompose sequenceで出すので、順次打鍵で持つ。薙刀式とは違う打ち方になる |
| 作れない行を近い打ち方で代用する | 採らない。使わない行は表に入れず、生成時に報告する（`gen-secca-table.ts --report`） |
| 表を複数のファイルに分ける | 採らない。宣言が持つ表のファイルは1つで、配列の定義が全部の節を要る |
| 漢字と熟語の途中の空白キーも層のトリガーに数える | 採らない。順次打鍵のステップの1つなので、数えるのは、かなの空白キーを押した面だけにする |

## 結果

- 配列図の選択（キーを1つずつ選ぶ図）が、かなの同時押しの組を選び続けられるように、`toggleSelectedKey` が、続けて押せる同時押しの組も続けて押せるキーに数えるようにした。順次打鍵と同時押しを両方持つ配列は雪華だけで、他の配列の選択は変わらない
- 配列の検査（`validateCanonicalInputMap`）は、見出しの組の数の2乗の時間だった。雪華の約2.8万見出しで約80秒かかったので、ステップの形ごとの区画に分けて比べるようにした。最初に見つかる衝突は同じで、雪華の読み込みは約0.6秒になる
- 押す順の再生は、KMonadの `tap-next-release` が、待つ間のイベントを全部受け取り、最初の離しで順に再生する、という理解に拠る。KMonadのソースでは確かめていない。簡約が正確なのは、この理解が正しい時である。実機の打鍵との照合は、今していない
- 漢直の表の最大の1ファイルのgzipが7516Bから173270Bに増えたので、バンドルの上限を9000Bから191000B（実測の約1.1倍）に上げた。他の項目は、上限の内に収まっている
