# ADR-0022: 順次打鍵の割り当ての無い組は、打ちかけの入力も今の打鍵も取り消す

- 番号: ADR-0022
- 日付: 2026-11-28
- 状態: 採用

## 背景

ADR-0018の結果に、空欄の組を続けて打った時のTesterの扱いを書いた。エンジンは、割り当ての無い組の2打目を新しい1打目として続けていた。keydistのT-Codeの定義では、1打目 `1`・2打目 `1` に字が割り当てられておらず、続く `l` と合わせて `1` `l` の字（執）が出ていた。ADR-0018の時点では、実際のT-Code入力環境の扱いを確かめていなかった。

決めることは、割り当ての無い組を打った時に、2打目を新しい1打目として続けるか、打ちかけの1打目も取り消して打ち直しにするかである。

## 決定

打ちかけの入力（文字をまだ出していない打鍵）に続けた打鍵が、どの入力の続きにもならない時は、打ちかけの打鍵も今の打鍵も文字を出さず、どちらも次の入力に使わない。実装は `src/tester/engine/typing-input-engine.ts` の `#unassignedContinuation`、固定するテストは `src/tester/engine/sequential-unassigned.test.ts`。

- 今の打鍵だけで文字になる打鍵（TUT-Codeの数字）でも、打ちかけの入力があれば、その文字は出さない
- 3打以上の入力の途中で続かなくなった時も、そこまでの打鍵を全部取り消す
- 1打目が文字を出す入力（雪華のかなとの共有キー）は、打ちかけの入力にならないので、この扱いの外である

Emacs用のtc（kanchoku/tc、`tc.el`）は、2打目が表に無い組の打鍵を、同じ扱いにしている。

- `tcode-decode`（532行）は、表に値が無い打鍵で `out-of-table` を返す
- `tcode-decode-chars`（579行）は、`complete` でも `incomplete` でもない時に `nil` を返し、読み込んだ打鍵の列を持ち越さない
- `tcode-eval-action`（643行）は、`nil` の動作に `ding` を鳴らして `nil` を返し、`tcode-input-method`（682行）は `(throw 'cancel nil)`（724行）で入力を打ち切る

つまり、文字を出さず、1打目も2打目も次の入力に使わない。調べたのは2026-11-28時点のmasterの `tc.el`（コミット 5d84e847、ヘッダの版は `$Id: tc.el,v 1.60 2003/03/29`）である。

- 3打の組（TUT-Code）も、入れ子の表を同じ `tcode-decode-chars` が再帰で引くので、同じ扱いになる
- 表の `■` `◆` `◇` は、読み込み時に値の無い欄（`nil`）になる。`tc-tbl.el` の `tcode-non-2-stroke-char-list`（98〜101行）に挙げられ、`tc.el`（999〜1001行）の表の組み立てで欄に入れない
- tcが `1` `1` を割り当てているのは空欄ではなく、LL表を出す機能である（`tc-tbl.el` 106行の `tcode-special-commands-alist`）。keydistは機能の欄を持たず（ADR-0018）、`1` `1` を割り当ての無い組として扱う。ここで言う割り当ての無い組は、keydistの定義で字が無い組であって、tcの表の空欄とは一致しない

## 却下した案

| 案 | 割り当ての無い組の後 | 採否 |
|---|---|---|
| 打ちかけも今の打鍵も取り消す | 次の打鍵が新しい1打目 | 採る。tcの挙動と同じで、打ち間違いの1打が、後の字の1打目に混ざらない |
| 2打目を新しい1打目として続ける（今まで） | 2打目が次の入力の1打目 | 採らない。tcにこの扱いは無く、1打の打ち間違いが続く字の化けになる（`1` `1` `l` が `1` `l` の字を出す） |

漢直Winは配布物の `t.tbl` を出典にしたが、本体の動作は読めるソースも文書も確かめられず、調べていない。

## 結果

- 打ちかけの入力に、表のキーでない打鍵を続けた時の扱いは、この判断では変えない。tcは、表のキーでない打鍵を途中で打つと打ちかけを捨てる（`tc.el` 593〜614行の `tcode-decode-chars`。取り消しの打鍵（DELやC-h）は取り消し、空白は打鍵の文字をそのまま挿入し、他のキーはそのキーの文字だけを挿入する）。Testerは、表に無いキーを押しても打鍵の履歴に残すので、`1` `escape` `l` は `1` `l` の字（執）になる。tcに合わせるかは別に決める

- 空欄の組の続きの扱いは、エンジンのテストで固定した
- Testerは、取り消した打鍵を知らせる表示（tcの `ding` に当たるもの）を持たない。打鍵は取り消され、文字が出ないだけである
