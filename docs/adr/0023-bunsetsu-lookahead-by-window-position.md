# ADR-0023: 先読みを文節で数える位置と、かなの位置を別々に持つ

- 番号: ADR-0023
- 日付: 2026-11-28（PRの日付）
- 状態: 採用

## 背景

表による解析の先読み `N` は、表の単位に合わせて文節の数で数える（issue #96・#102）。`N` は、距離の計算で指を残す候補を持つか（§9）と、担当する指が2本以上のキーを打つ指を選ぶ範囲（§9.1）に使われる。
§9.1の2.（指の左右の入れ替わり）と3.（同じ指が近くに戻る打鍵）は、別に「かなの位置の差 `ΔI` が0か1」を読む。この2つが読む位置は、先読みとは別の量である。
issue #102の本文は `ΔB` を「指が最後に参加した入力が始まる文節との差」としていた。2026-10-25の決定で、`lastEnd[f]` と `ΔI` に合わせて定義し直すことになった。

## 決定

- `ΔB = max(0, B(s) - B(lastEnd[f]))`。`B(p)` は文字位置 `p` が属する文節の番号。§9の `ΔI ≤ N` を `ΔB ≤ N - 1` に置き換える（§13.3）
- Trace生成は、入力ごとに、かなの位置（`start`・`end`）と、先読みの位置（`windowStart`・`windowEnd`）を別に持つ。区切りを渡さなければ、先読みの位置はかなの位置と同じで、今の解析は変わらない。指を選ぶ探索の状態も、かなの位置から数えた差と先読みの位置から数えた差を別に持つ
- §9.1の2.と3.は、`ΔI` のまま測る
- `N` は1以上8以下で、既定は1。表の次数と独立で、`N ≥ k+1` の結果は `N = k+1` と同じ（§13.3）。先読みの単位は条件に持つが、今の解析の設定にはしない

## 却下した案

| 案 | 却下の理由 |
|---|---|
| かなの位置を文節の番号に置き換え、先読みも2.と3.も同じ位置で測る | 2.と3.の「`ΔI` が0か1」が、「同じ文節か次の文節」に変わる。隣り合うかなの間を数えるという2.と3.の意味（§9.1）が、文節の長さで変わる |
| `ΔB` を、最後に参加した入力が始まる文節との差にする | `ΔI`（§7 R3）が `lastEnd[f]` から測るのと食い違う。複数のかなを覆う入力で、参加した指の「最後の位置」が一致しない |
| 文節ごとに先読みを別の `N`（かな数）に換算し、今の `N` を使う | 換算の規則が文節の長さの分布に依り、`N` を変えた時の挙動を仕様に書けない。表の項目の中でしか文節の長さが決まらない |
| 今の解析にも文節の先読みを設定として足す | AGENTS.mdの「設定項目を足すか決める」の3つ目（割れる人を想像できるが実例が無い）にあたる。要望が出たら足す（issue #102の2026-10-25の決定） |
| `N=0` を選べるようにする | 文節の先読みは今の文節を含めて数えるので、0は今の文節の中も見ないことになる。§7 R4の比較が成り立たない |

## 結果

- `test/fixtures/analyzer-regression.json` の値は動かない。`src/trace/finger-selection.test.ts` に、全通りを数え上げた参照実装を先読みの位置を別に持つ形へ広げて、先読みの位置を文節の番号にしたときの指の選び方が一致することを確かめる検査を足した
- 上限8と既定1は、測定から決めた値ではない。上限は§5.1が判定に使う範囲を持ち越し、既定は選べる最小の値である。`N` を変えた時の値の動きは、`scripts/corpus-ngram-table-analysis.ts --lookahead` で見られる
