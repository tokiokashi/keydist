# ADR-0023: 雪華の簡約で、保留中のtap-next-releaseがあるとき層を保つキーの離しを許さない

- 番号: ADR-0023
- 日付: 2026-11-28
- 状態: 採用

## 背景

ADR-0021は、雪華の打ち方を求める簡約に、層を保っているキーを全部離す操作（`^`）を常に許していた。許す根拠は、KMonadの `tap-next-release` が、待つ間のイベントを全部受け取り、最初の離しで順に再生する、という理解だった。この理解はKMonadのソースで確かめておらず、ADR-0021の結果の節にもそう書いてある。

KMonadのmaster `30b9705fb56059483969624d58cad077d5c62300` の `src/KMonad/Model/Button.hs` の `tapNextRelease` を読むと、挙動は次のとおりだった。

- 保留中の `tap-next-release` は、自分より後に押したキーの押しを控え、その離しの順序だけを見る
- 自分の離しが先に来ると、タップに決まる
- 自分より後に押したキーの離しが来ると、ホールドに決まり、その離しをその時点で再注入する
- 自分より前に押したキーの離しは、保留の対象にならず、即時に処理される。層を保つキーがその離しなら、層はその時点で外れる

ADR-0021の簡約は、この離しの扱いを表さず、保留中の `tap-next-release` の後に空白キーを押して、層を保つキーを離し、続きを打つ形を許していた。

## 決定

- ADR-0021の押す順の再生の簡約のうち、`^` を許す条件を絞る。ADR-0021は置き換えない。出典の写しから表を作る方法・かなの同時押し・漢字と熟語の順次打鍵・右手の位置・表を1つのファイルで配る判断は、ADR-0021のまま続く
- `findChords` の `^` は、押したままのキーの中で最初の `tap-next-release` が最後に押したキーで、そのキーのホールド側が層を持たない時だけ許す。押したままのキーに `tap-next-release` が無い時も許す。条件は、押したままのキーに `tap-next-release` のホールド側の役で押したかの印（`HeldKey.pendingRelease`）を持たせて判定する
- 表を作り直すと、熟語の77行が作れない行になる（荊妻 `w e ; spc ^ u d` など）。77行は77語で、見出しの重複は無い。他の行は、表の差分が無い。表の件数は、熟語23970語から23893語になり、作れない行は59行から136行になる。内訳は全角英字52行・記号3行・異体字4行・熟語77行
- 簡約の前提ごとに、KMonadのソースとの一致を次のように確かめた

| 前提 | 結果 |
|---|---|
| 最後に押したキーの `tap-next-release` は、自分の離しが先なので打つ役になる | 一致 |
| 最後でないキーの `tap-next-release` は、後に押したキーの離しでホールドに決まる | 一致 |
| `tap-next-release` が保留中でも、層を保つキーを全部離せる | 食い違い。保留中の `tap-next-release` より前に押したキーの離しは即時に処理され、層が外れる。この簡約から外す |
| `tap-next-release` の待つ間のイベントを、決まった後に押す順と離す順のまま再生する | 一致。ホールドに決まった時は、決まった時点の層で再生する |
| `tap-next` と `tap-hold-next` は、次のイベントが自分の離しでなければホールドに決まる | 一致。`tap-hold-next` の待ち時間は来ないものとする |
| `tap-next-release` が保留中に押した `tap-next-release` は、押しが溜まり、前のものが決まった後に処理される。決まる順は押した順である | 一致 |
| 層・`_`・`XX`・`around`・マクロの扱い | 一致 |

- 層を保つキーの離しを許す形は、くずし字入力（`dfkw` の人形のように、左手の2キーを離して右手を打つ）を残す。この形は押したままのキーに `tap-next-release` が無い、または最後のキーが層を持たない `tap-next-release` で、離しが保留の外になる。`test/secca-source.test.ts` が人形の打鍵 `dfkw` を確かめる

## 却下した案

| 案 | 採否 |
|---|---|
| 保留中の `tap-next-release` が1つでもあれば、`^` を許さない | 採らない。最後に押した `tap-next-release` が層を持たない時は、その離しが `^` の前に決まるので、同じ打ち方がKMonadのソースでも成り立つ。この形を禁じると、ソースの挙動で成り立つ形まで作れなくなる。この案で表を作り直すと、作れない行は136行から21224行になる。`^` を含む21088行が全部作れなくなる |
| 77行を別の押し方で作る | 採らない。直した探索（深さ10まで）で、77行を出す押し方は見つからなかった |
| 簡約をKMonadの全イベントのエミュレーションに置き換える | 採らない。探索の1手ごとにイベントの再生が要り、実装が大きくなる。簡約の条件1つで、エミュレータとの照合で食い違いが出た77行が除ける。実行時間は測っていない |

## 結果

- 確かめた範囲はKMonadのソースの読みと、再実装したKMonadのエミュレータとの照合である。実機のKMonadでは確かめていない
- かなの3キーの同時押し15字は、2番目に押したキーを3番目より先に離すと、2字に分かれる。表は同時押しを1ステップで持つので、この離す順の依存を表さない。簡約の限界として残す
- 作れない行は、`gen-secca-table.ts --report` が `unreachable` で報告する
- 数値が変わる。組み込みの評価テキストには、この77語が含まれず、雪華の数値は動かない。77語を並べた文では、動く（測った値はPRに書いた）
- バンドルは増えない。表のサイズは378597Bから377442Bに、`zlib.gzipSync` で数えたサイズ（`scripts/measure-bundle.ts` と同じ方法。ADR-0021の173270Bと同じ方法）は173270Bから172796Bに減る
