# ADR-0026: 表の項目は、ホームの状態から文脈を打ち、最後の文節の距離だけを数える

- 番号: ADR-0026
- 日付: 2026-11-28（PRの日付）
- 状態: 採用

## 背景

文節のn-gramの表（`docs/corpus-ngram.md`）を、配列で打鍵して集計する解析が要る（issue #96）。表の項目は連続する `k+1` 文節の読みと出現回数で、項目の前に何が打たれたかは残っていない。
決めることは、打鍵の状態の始め方、距離をどの文節に入れるか、配列ごとに変わる前処理の扱い、表が持たない情報（コンボを止める境・表記で打つ語）の扱いだった。

## 決定

- 項目ごとに、すべての指をホームに置いた状態（`spec/distance-model.md` §6の初期値）から、文節の読みをつないだテキストを打つ。文脈の `k` 文節は状態を作るためだけに打ち、最後の1文節の距離を出現回数で重み付けして足す（§13.1・§13.2）
- 距離は、ステップの `kanaEnd` が属する文節に入れる。`docs/span-metrics.md` のステップの帰属と同じ規則で、2つの文節にまたがる入力は、終わりの文節に入る
- 片仮名の書き換え（§4.6の5段目）は、項目のテキストの上で、その配列の見出しで当てる。打てない文字は `skipped` に数え、位置は1つの位置として数える。表の単位は配列に依らないまま、配列ごとに結果が変わる
- コンボを止める境と、漢直の配列で表記のまま打つ語は持たない。表は読みの文節だけを持ち、原文の語の境目を残さない

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 距離を、入力が始まる文節（`kanaStart`）に入れる | 区間の集計（`docs/span-metrics.md`）が `kanaEnd` に帰属させる規則と食い違う。2つの定義が同じ入力を別の文節に入れると、並べて読む時に混乱する |
| 文脈の距離も数える | 表の項目は `k+1` 文節の並びで、出現回数は並び全体のもの。文脈の文節の距離まで数えると、同じ文節が文脈と最後の文節の両方で重みを受け、出現数と対応しなくなる |
| 配列ごとに表を作り直す（片仮名の書き換えを表に入れる） | `docs/corpus-ngram.md` が表を配列に依らず作る定義にしている（ADR-0012）。配列ごとに数えると、表の統計が配列に依って変わる |
| コンボを止める境と表記で打つ語を、原文から作って項目に付ける | 表は読みの文節の並びで、同じ読みの文節が別の語から来た場合を区別できない。区別するには表の定義を変える必要がある |

## 結果

- 文脈より前の打鍵が無いので、文節の最初の打鍵が前の文節の指の位置から始まる実際の文章の打鍵とは違う。この違いが距離を増やすか減らすかは、定義からは決まらない（§13.7）
- コンボを止める境を持つ配列と漢直の配列は、評価に渡すテキストを頭から打鍵する解析との差に、この違いが入る（§13.1）
