# ADR-0030: 表による解析を、固定の最小テキストで解決したSet Analyzerとして置き、表は主スレッドで取得してWorkerへ渡す

- 番号: ADR-0030
- 日付: 2026-11-28（PRの日付）
- 状態: 採用

## 背景

issue #96の2回目の単位で、標準のコーパスの文節の読みの表（ADR-0026〜0029、`spec/distance-model.md` §13）を画面に出す。表による解析は、評価に渡すテキストを入力にしない。入力は表と、配列・物理配列・Trace生成の方針（`TableAnalysisSetup`）である。既存のAnalyzerの契約は、抽出の入力が解決済みのテキストから作ったTraceであることを前提にしている。

表は約0.9MB（gzip約0.18MB）で、全ページの初期読み込みと計算用Workerのサイズに入れられない。

## 決定

- 表による解析を、複数のSetupを並べるSet Analyzer（`analyzers/ngram-table/`）として置く。契約に次の2点だけを足す
  - `ExtractionAssets.ngramTable`: 表の1つの次数。抽出が読み、`assetsKeyOf` でキーに入れる
  - `AnalyzerSetMember.setup`: メンバーの配列・物理配列・Trace方針・綴りの規則。抽出はTraceを読まず、これで項目を打つ
- メンバーの解決には、固定の最小の日本語のテキスト（1文字）を使う。評価に渡すテキストの選択は値を変えず、読みに直せないテキストでも対象が失敗しない。Traceの生成は最小のテキストの分だけで済む
- 表は主スレッドで取得し（`platform/ngram/table-loader.ts`。`?url` で独立したファイルにする。開発サーバーでは `?raw`）、選んだ次数の1表だけを解決済みの入力に載せてWorkerへ送る。1回のメッセージで1度だけ複製され、同じメッセージの中のメンバーで共有される
- 抽出の結果は、表の識別子と `min(N, 次数+1)` をキーにして `member.remember` に載せる。仕様 §13.3の通り、`N` が次数+1以上なら値は同じなので、先読みだけを変えても計算し直さない
- 次数 `order` と文節の先読み `lookahead` は、このAnalyzerだけが読み、出力が動くので、このAnalyzerの解析設定に置く。今の解析の先読み `N`（かなで数える）とは別の項目にする
- ビルドの後に `scripts/check-ngram-table-assets.ts` が、表がJavaScriptに入らず、独立したファイルとして公開物にあることを確かめる。`scripts/generate-corpus-ngram-table.ts --check` が、同梱の表が出典から作り直した表と同じであることを確かめる

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 評価に渡すテキストを使って解決する | 使わない入力のためにTraceを作り、長いテキストで計算が重くなる。読みに直せないテキストで、値に関係のない失敗が出る |
| 要求の種類に「表」を足す（Traceを経由しない第3の経路） | Workerの通信・キャッシュ・ペインの状態に新しい経路を足す。契約の2点の追加で足りる |
| Workerの中で表を取得する | Workerのハンドラーは同期で、Workerを使えない環境では主スレッドで動く。取得を主スレッドに置く方が、2つの経路で同じ形になる |
| 全次数の表を一度に送る | 選べる次数は今0次だけで、次数が増えても使うのは1つ。送る量と複製の費用が増える |
| 次数を「未選択」を許す項目にする | 既定は選べる次数の最大と決まっている（§13.5）。未選択を持つと、保存した値が表の更新で意味を変える |

## 結果

- 既存のAnalyzerの値は変わらない。`test/fixtures/analyzer-regression.json` は動かさない
- 同梱する表が変わって既定の次数が変わったら、解析設定の既定と上限も直す。`analyzers/ngram-table/extract.test.ts` が一致を確かめる
- 利用者のテキストから表を作る経路は、この判断に含めない。表の取得を差し替える点（`ngram-table-source.ts`）を残してある
