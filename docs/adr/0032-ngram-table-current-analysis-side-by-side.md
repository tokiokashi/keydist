# ADR-0032: 表による解析の結果の表に、今の解析の値を、別の依頼で求めて並べる

- 番号: ADR-0032
- 日付: 2026-11-28（PRの日付）
- 状態: 採用

## 背景

表の元が利用者のテキストの時、同じテキストを今の解析（評価に渡すテキストを頭から打鍵して集計する解析）で測った値を、表による解析の値と同じ画面で読めるようにする要求が残っていた（issue #96の受け入れ条件）。

ADR-0030は表による解析のメンバーを固定の最小のテキストで解決すると決め、評価に渡すテキストで解決する案を、使わないTraceの費用と、読みに直せないテキストでの値に関係のない失敗を理由に却下した。ADR-0031も同じ案を却下した。今の解析の値は評価に渡すテキストのTraceと`Metrics`から出るので、この却下と両立する経路が要る。

2つの解析は、入力（前処理の範囲、前の文字から続く指の位置の有無）と先読み（文節かかなか）が違う（`spec/distance-model.md` §13.10）。

## 決定

- 今の解析の値は、表による解析のメンバーの解決とは別の依頼で求める。表の元が選んだテキストの時だけ、ペインのホスト（`hosts/shared/panes/SetAnalyzerPane.tsx`）が、同じ対象を評価に渡すテキストで解決し直して、計算の窓口へ依頼する。表による解析の抽出・メンバーの解決・キーは変えない（ADR-0030・0031の決定は変わらない）
- 依頼の抽出は、ペインに出さない集合のAnalyzer（`analyzers/ngram-table/current-extract.ts`）が行う。比較表と同じメンバーの解決と`Metrics`から、総移動距離・入力1かなあたり・入力かな数・打てなかった文字・かなで数える先読みを読み出すだけで、新しい量は定義しない。解析設定を持たない
- 評価に渡すテキストが上限を超える失敗と、対象を解決できない失敗は、依頼の失敗として届く行の理由（比較表と同じ文）をそのまま出す。長さは自前で比べず、解決の結果に任せる
- 結果の表に、配列・Setupごとに「表による解析（文節の先読み）」と「今の解析（かなの先読み）」の2行を並べ、入力かな数を両方に出す。差・比・順位は出さない。標準のコーパスの時は並べない
- 条件の要約から除く項目（`conditionExcludeIds`）を、解析設定で変わる関数にできるようにする。表の元が選んだテキストの時は、今の解析の値を変える先読みNと、記号・英数字の範囲を条件に残す。出どころの札に、今の解析の測り方を添える

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 比較表に表による解析の列を足す | 比較表は今の解析の値の表で、表の次数・文節の先読み・表の元のテキストの条件を持たない。表による値に条件を付随させられない |
| 表による解析のメンバーを評価に渡すテキストで解決する | ADR-0030・0031が却下した案。標準のコーパスの時にも使わないTraceを作り、読みに直せないテキストで表の値まで失敗する |
| 表による解析の抽出の中で、今の解析の値も求める | 抽出の入力が評価に渡すテキストのTraceを持たない。持たせるとメンバーの解決を変えることになる |
| 比較表の抽出を再利用する | 比較表の行は入力かな数と、行ごとの先読みNを持たない。足すと比較表の抽出の形が、表による解析の都合で変わる |
| 別のペインに並べる | 同じ配列の2つの値を同じ表で読む要求に合わない。ペインごとに対象と解析設定が別になる |

## 結果

- 同梱の表の値、今の解析の値、表による解析の値は変わらない。`test/fixtures/analyzer-regression.json` は動かさない
- 表の元が選んだテキストの時は、今の解析のメンバーごとの計算が加わる。長いテキストでは、計算用Workerの依頼が1件増える
- 今の解析の値を測れる大きさの上限は、既存の `MAX_EVALUATION_TEXT_LENGTH` である。それを超えると、今の解析の行だけ値を出さない
