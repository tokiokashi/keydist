# ADR-0033: コーパスの文字列の候補を、かなの系列の極大な繰り返しとして、接尾辞配列で取り出す

- 番号: ADR-0033
- 日付: 2026-11-28（PRの日付）
- 状態: 採用

## 背景

issue #100 の受け入れ条件に、長さを決めずに取り出した繰り返し現れる文字列を、統計量と再現の条件と一緒に出す、がある。目的は、文節のほかに集計の単位として使えるものがあるかを、オーナーが一覧を見て決める材料にすること。一覧を単位に使うかは決まっていない。
決定のコメント（2026-10-21）は、ジャンルの区分を持たないので、ジャンル間の出現率のばらつきを出さないと決めた。章（全11章）の間のばらつきは、一覧を見る時に決めるとした。
標準のコーパスは『吾輩は猫である』全文で、かなの系列は385,782単位、走りは3,659個（`docs/corpus-ngram.md`）。

先行研究で確かめた事（一次資料を開いて確かめた範囲）:

- Yamamoto & Church (2001) は、接尾辞配列とLCP配列で、`N(N+1)/2` 個の部分文字列を高々 `2N−1` 個の同値類にまとめ、全部分文字列の出現回数を求める。同値類は、接尾辞配列の区間で決まる
- Jin & Tanaka-Ishii (2006) は、文字列に続く文字のエントロピー（branching entropy）が増える位置を、語の境界とみなす。着想は Harris (1955)。Feng et al. (2004) のaccessor varietyは、文字列の前後に来る文字の種類の数で、語らしさを測る。端の出現を別に数える
- Gries (2008) のDPは、コーパスを部分に分けた時の、出現の割合と部分の大きさの割合の差の半分の総和

## 決定

- 候補は、かなの系列の走りの中の、出現回数が5以上の極大な繰り返し（左右どちらに1文字伸ばしても出現回数が減る文字列）にする。長さの上限は置かない。文節の区切りでは区切らない
- 取り出しは、走りごとに別の区切りの記号を挟んでつないだ列の、接尾辞配列とLCP配列で行う。LCP区間が右に極大な繰り返しにあたり、そのうち直前の記号が全部同じでないものを左にも極大として残す。接尾辞配列は倍加法の基数ソート、LCPは Kasai らの方法で作る。実装は `interpretation/suffix-array.ts` と `interpretation/corpus-candidates.ts`
- 統計量は、出現回数・長さ・左右の分岐の種類の数と分岐のエントロピー・文節の境界にそろう割合・章の間のDP（とDPを最大1に直した値、出現がある章の数）。走りの端は、分岐では1つの記号に数え、文節の境界にそろう割合では境界に数える
- 並べ方は出現回数の降順にし、統計量を組み合わせた点数と順位は作らない。出力はスクリプトのファイルで、画面には出さない
- 結果の一覧はリポジトリに入れない。出現回数の上位などの抜粋をPRに載せ、全体は別の置き場に置く

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 極大でない部分文字列も含めて、出現回数が下限以上の全部分文字列を出す | 同じ出現を共有する部分文字列（ある文字列の、出現回数が同じ接頭辞や接尾辞）が、長さごとに重なって並び、一覧が長くなる。極大な繰り返しなら、出現回数が減る所で切れた文字列だけが残る |
| 長さごとのn-gramの表を、長さの上限まで全部数える | 長さを決めずに取り出す要件に合わない。上限の長さの選び方で一覧が変わり、長さごとの表を足し合わせると同じ出現を重ねて数える |
| 長さの上限を置く | 上限で切った文字列を極大と数えるかを決める必要があり、上限で切れた文字列の統計量が、より長い文字列の一部の値になる |
| 文節の区切りで区切った系列から取り出す | 目的は、文節のほかに単位として使える文字列を探すこと。文節の区切りで区切ると、文節をまたぐ文字列が取り出せない。文節との関係は、境界にそろう割合で出す |
| 分岐のエントロピーや境界にそろう割合から、語らしさの点数を作って並べる | 統計量を組み合わせた点数や順位は作らない（`AGENTS.md`）。どの量を重く見るかを決めること自体が、オーナーが一覧を見て決める判断になる |
| 品詞や辞書の語を使って候補を絞る | issue #100 が、文節に区切った後の集計に品詞を使わないと決めている。辞書の語に絞ると、辞書に無い文字列が出なくなる |
| ジャンルの区分を作って、ジャンル間のばらつきを出す | 1作品なので区分できない（issue #100 の決定）。章の間のDPで、話題と登場人物の偏りだけを出す |
| 接尾辞配列のライブラリを足す | 実装は自前の2ファイルで、総当たりの参照実装との一致をテストで確かめられる。猫全文（385,782単位）の取り出しと統計量が0.4秒で済み、線形時間のSA-ISにする理由が無い。依存を足す理由が無い |
| 出現回数の下限を2にする | 猫全文で106,136件になり、一覧を読む量が増える一方、出現が2回の文字列の分岐のエントロピーは0か1ビットの2通りだけで、統計量として読めない |

## 結果

- 標準のコーパスで、出現回数5以上の極大な繰り返しは35,658件。取り出しと統計量の計算は0.4秒で、プロセスの最大の常駐メモリの増分は13MiB（Node v22.23.5。測り方と条件は `docs/corpus-ngram.md` の「再現の条件」と、PR本文）
- 小さな列で、全部分文字列を数える参照実装と、文字列・出現回数・分岐・エントロピー・境界にそろう割合・章のDPが一致することを、`corpus-candidates.test.ts` で確かめる
- 既存の表・判定の量・文脈の長さと、今の解析の値は変わらない
- 一覧を集計の単位として使うかは、まだ決めていない。issue #100 は閉じない
