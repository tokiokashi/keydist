# 設計判断の記録（ADR）

設計判断を1判断1ファイルで残し、判断の理由と置き換えを後から追えるようにする。
今の定義は `spec/` と `docs/architecture.md` が正で、決めた経緯・却下した案・以前の姿はここに書く。

## ファイル名と番号

- ファイル名は `NNNN-<短い説明>.md`。`NNNN` は4桁の連番で、書いた順に振る。欠番を詰めず、番号を使い回さない
- 見出しは `# ADR-NNNN: <判断を言い切った題>`

## 各ファイルが持つ項目

見出しの直下に、番号・日付・状態を箇条書きで置く。その後に次の4節を、この順で置く。

| 項目 | 書くこと |
|---|---|
| 番号 | `ADR-NNNN` |
| 日付 | 判断が入ったコミットかPRの日付。履歴から読めない時は、読めない旨と、読める最初の日付を書く |
| 状態 | `提案` / `採用` / `置き換え済み（→ ADR-NNNN）` のどれか |
| 背景 | 判断が要った状況と、その時点で分かっていた事実 |
| 決定 | 何を決めたか。今の定義への参照（`spec/` の節・`docs/architecture.md` の節・コード）を添える |
| 却下した案 | 採らなかった案と、却下の理由。読み取れる範囲だけを書く。読み取れない時は、その旨を書く |
| 結果 | 決定の後に分かったこと・守るために置いた検査・残る制約 |

- 理由が読み取れない判断は、読み取れた範囲だけを書き、推測で補わない
- 数値を書く時は、条件と、実行して得た値だけを書く
- 判断に関わったissue・PRの番号は、背景か結果に書いてよい（コードコメントと `spec/` には書かない）

## 判断を覆す時

- 新しいADRを書き、古いADRの状態を `置き換え済み（→ ADR-NNNN）` に直す。古いADRの本文は直さない
- 判断の一部だけを絞る・足す時は、古いADRの状態を `採用` のままにし、新しいADRの背景に古いADRの番号を書く
- 今の定義が変わる時は、`spec/` か `docs/architecture.md` を直す。経緯をそちらへ書き足さない
