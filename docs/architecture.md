# アーキテクチャ

keydist のコードの分け方と依存の向き。設計の経緯と未実装の部分は #544 にある。
ここは「今どう分けるか」の正で、依存の規則は `test/architecture-layers.test.ts` がそのまま検査する。

## 用語

用語を変える時は、この表と #544 の用語集を先に直してから使う。

| 用語 | コード | 意味 |
|---|---|---|
| 配列 | `Layout` | 論理配列。キーに何を割り当てるかの定義（面・trigger・コンボ等）。組み込みと自作がある。キーボードの界隈の普通の使い方どおり、単に「配列」と言えば論理配列を指す。画面でも「配列」と書き、「論理配列」と書き分ける必要は無い |
| 物理配列 | `Shape` | キーの物理的な位置（と規格。ANSI/JIS）。配列（論理配列）と対になる語。コードの識別子（`Shape`・`shapeId`・`src/input/shapes/`）は画面の語ではないので「shape」のまま |
| 指の割当 | `FingerAssignment` | 各キーを担当する指。物理配列の属性ではなく**カスケードの項目**（`fingerAssignmentId`）として持つ。既定は物理配列の規格から決まり、物理配列・配列・Setupのレベルで上書きできる（#544。`engine/finger-assignment.ts`）。組み込み（既定・JIS）と自作がある |
| ポリシー | `TracePolicy` | **Traceを作る**条件（trigger / action realization、SandSの手、反対側の親指、N、ローマ字規則等） |
| Setup | `Setup` | 配列 × 物理配列 × 上書き。**上書きを持ちたい時にだけ作る**資産（同じ配列を物理配列違い・指の割当違い・ポリシー違いで並べる用途）。上書きを持たないSetupは作らない |
| 対象 | `AnalysisTarget` | Analyzerが見るもの。**配列**（カスケードの実効値をそのまま使う。物理配列はカスケードの「既定の物理配列」）か**Setup**のどちらか。集合を見るAnalyzerは対象の列を持つ。計算の単位は、対象を解決した入力（配列 × 物理配列 × 指の割当 × ポリシー） |
| カスケード | settings cascade | ポリシー・指の割当・解釈の値を グローバル → 物理配列 → 打ち方 → 配列 → Setup の順に上書きして実効値を求める仕組み。配列を対象にした時の物理配列（既定の物理配列）もグローバルの項目として持つ |
| プリセット | `Preset` | 条件（カスケードの1レベル分の上書き）に名前を付けて持つ資産。**既定から変えた項目だけ**を持つ（疎）。流し込みは置き換えだけで、プリセットに無い項目は上書きを消して既定へ戻し、既定と同じ値は上書きとして残さない（既定が文脈で決まる項目、今は`fingerAssignmentId`は、既定を判定できないので値を残す）。レベルは持たず、対象のレベルで許されない項目は入れずに返す。手持ちは`setupLibrary`と別のキー（`keydist:presets`）で、参照先の資産（自作の指の割当等）は持たない（`input/presets/`・`engine/preset-commands.ts`） |
| テキスト | Text | 打つ文章。言語を属性に持つ。Setupと同じく**資産**として複数持ち、個別画面・Workspaceはそこから選ぶ。組み込み（サンプル）と自作がある |
| 打ち方 | input method | テキストの言語 × 配列の種類から導く（かな直接 / ローマ字 / 直接） |
| Trace | `Trace` | 対象を解決した入力でテキストを打った記録（打鍵列・指の移動・押し方）。`generateTrace` が作る |
| 解釈 | `…Interpretation`（`ChainInterpretation` 等） | **Traceの読み方**。Traceを変えずに数値の定義を変える（chain・arpeggio等の数え方、時間モデル） |
| Analyzer | `AnalyzerDefinition` | **機能の単位**。抽出 + 可視化 + 解析設定 |
| 抽出 | extract | Trace（と解釈の結果）からAnalyzerが使うデータを取り出す純関数 |
| 可視化 | visualization | 抽出したデータを表示するcomponent。計算しない。ペインの本体として描く（「Analyzerがペインに渡すもの」） |
| 解析設定 | `AnalyzerOptions` | どの数値を・どの切り口で・どう見せるか |
| engine | engine | 解決・Trace生成・解釈・抽出の実行とキャッシュ |
| 個別画面 / Workspace | host | Analyzerを載せる器。「個別画面」は開発者向けの語で、画面には出さない（画面で個別画面を名指しする操作を置かないため） |
| 資産 | assets | ユーザーが作って保存するもの（自作配列・物理配列・指の割当・ローマ字規則・Setup・カスケードの値・プリセット・Workspace・個人速度・テキスト） |

使わない語: `Shape` を指す「物理形状」「形状」（物理配列と呼ぶ）、mode（en / ja）、段の名前としての「評価」（`evaluate`）、View、`AnalysisSession` / `AnalysisSnapshot`、解釈を指す「ポリシー」（`ChainPolicy` / `ArpeggioPolicy`）。

## 流れ

```text
対象（配列 または Setup）→ 解決（配列 × 物理配列 × 指の割当 × ポリシー）+ テキスト
  ↓ Trace生成
Trace
  ↓ 解釈（構造・時間モデル・複数のAnalyzerが使う指標）
  ↓
Analyzer（抽出 → 可視化）
  ↓
host（個別画面 / Workspace）
```

条件は3種類に分ける。「その値を変えると、同じ名前の数値の意味が変わるか」で判定する。

| 種類 | 何を決めるか | 持ち主 |
|---|---|---|
| ポリシー | Traceの中身 | カスケード |
| 解釈 | Traceは同じまま、数値の定義 | カスケード（当面グローバルのみ） |
| 解析設定 | どの数値をどう見せるか | Analyzerのインスタンス |

指の割当（`FingerAssignment`）もこの分類では**ポリシー**と同じ扱いになる
（Traceの中身を変え、持ち主はカスケード）。ただし型は`TracePolicy`ではなく独立した
`FingerAssignment`で、`generateTrace`へは物理配列と合成した`Geometry`として渡る
（`engine/resolved-input.ts`）。

## 画面の構成

全画面を1つの器（シェル）に載せる。個別画面は**ペインが1枚だけのWorkspace**と同じ形にする。
同じAnalyzerを個別画面にもWorkspaceにも同じcomponentで載せる（#544 完了条件）ため、器の側と
ペインの側で持ち物を分けておく。

```text
シェル
├─ サイドバー      ナビゲーション（最下端に版表示・旧バージョン・テーマ切替）
└─ 本体
   ├─ 文脈バー     （Workspace名）/ テキスト / Undo・Redo / 共有（個別画面のみ）
   └─ ペイン（個別画面は1枚、Workspaceは複数）
      ├─ 見出し    Analyzer名 / 対象 / 解析設定（Workspaceのペインは⋯も。Analyzer名とⓘはタブが持つ）
      ├─ 条件の要約（押すと条件のモーダルが開き、全体の条件を編集できる。Workspaceのペインは見出しの1行に畳む）
      └─ Analyzerの中身
```

| 場所 | 持つもの | 持たないもの |
|---|---|---|
| サイドバー | ナビゲーションだけ。個別画面とWorkspaceで同じもの（区分は下記） | テキスト・Setup・解析設定などの入力 |
| 文脈バー | Workspaceの時はWorkspace名、使うテキストの選択（1行のチップ。選択・編集は開いた時だけ出す）、常時出す操作（Undo/Redo。個別画面は共有も。Workspaceは共有を出さない。URLのidはこのブラウザの保存先を指し、受け取った側では開けないため） | ペイン固有の値 |
| ペイン | 対象（配列かSetup、またはその集合）、解析設定、条件の要約、ペインへの操作（Workspaceのペインは⋯） | テキスト |

- 個別画面では、ペインの見出しを文脈バーの下に一緒に固定する（図を下までスクロールしても対象と解析設定を変えられるように）。Workspaceのペインの見出しは固定しない
- 対象をペインに置くのは、Workspaceのペインが「従う / 固定」の対象を自分で持つため（#544 §6）。ページ上部に置くと、ペインを並べた時に破綻する
- テキストは器の値。個別画面は全体で1つの選択、Workspaceは自分の選択を持つ（#544 §5）
- テキストの編集: 組み込みのサンプルを書き換えると、自作のテキストとして新しく保存し、以後はそれを編集する。自作のテキストは、明示的に複製しない限りその場で書き換える
- **メニューバー（編集 / 表示…）は置かない。** 全操作の目録はコマンドパレット（書き込みはすべてコマンドを通す #544 §8-2 ので、コマンドの一覧から作れる）で持つ。ペインと文脈バーにグローバルな操作が入り切らなくなった時に、メニューバー（かデスクトップアプリ化）を検討する
- **トップは道具の全体像を説明するページ。** サイドバーの Analyze / Workspace の区分を見本として描き（名前は各Analyzerの`pane-meta`とサイドバーと同じものを使い、各画面へのリンクにする）、Analyzerとは・SingleとMultiの違い・始め方（気になる配列を1つ選ぶ。選んだ配列は Single の対象になり、Multi の組にも入る。選んだ後に各 Analyzer へのリンクを出す。書き込みは`setTargetForSingleAndMultiCommand`の1回の操作）・Workspace（複数のAnalyzerを並べて見る画面。サイドバーの「＋ 新しいWorkspace」から作る）、の4点を短く説明する。あわせて観測値の注記と、旧バージョン（`/analyzer`）への控えめなリンクを置く。操作の細部（元に戻す・共有・条件の要約など）は書かない。画面への入口はサイドバーが持ち、見本のリンクはその写しなので、増やすときは両方そろえる。`/classic/` への直接の導線はトップにもサイドバーにも置かない（ビルドとURLは残る）
- **「数値は観測値であり、配列の優劣を判定するスコアではない」の注記はトップにだけ置く。** トップは全体像を説明するページという原則の例外。各ペイン・各Analyzerの本体と説明には出さない（ペインごとに繰り返すと、これ見よがしに出しすぎになる）
- 書体はシステムフォントを使う

### サイドバー

- 区分見出しは英語にする。Analyze（その中に Single = 対象を1つ見るAnalyzer / Multi = 複数の対象を見るAnalyzer。対象の数で揃える）、Workspace（用語集の語のまま）、Assets（手持ちの資産）。先頭だけ大文字にし、全部を大文字にはしない
- Testerは区分に入れず、単独の項目として置く。Testerと同じ種類のものが増えた時に区分へ昇格する
- Workspaceの区分は保存したWorkspaceの一覧と「＋ 新しいWorkspace」。1つも無い時は案内文を出す
- **最下端に版表示・旧バージョン（`/analyzer`）へのリンク・テーマ切替（自動 / 明 / 暗）を置く。** ナビゲーションだけという原則の例外。`/analyzer` はシェルに載らないページで、リンクを押すと画面ごと切り替わる。v1.0.0で消す時は `/classic/` へ付け替える
- パソコン幅では**固定**（常時表示）と**固定解除**を切り替えられる。固定解除の時は完全に隠れ、左端か文脈バーのボタンで本体の上に重ねて出し、離れると引っ込む
- スマホ幅では常に引き出しにする（固定は選べない）

### 文脈バー

- Workspaceの時は、左端にWorkspace名を置く（ページのh1）
- 競合で選ばれずに残ったコピー（「…（編集） 2」等）ができたら、チップの角に点を付ける。開くと一覧のそのコピーに「新しい」と出る。コピーを開くか一覧を見ると消える。通知（トースト・バナー）は出さない。印は資産（テキストの`unseen`）に持つので他タブにも出る（#611）
- テキストはチップで出し、開くと選択・編集する
- 文脈バーが狭い時（バー自身の幅で決める。53.5rem未満。サイドバーの固定で本体の幅が変わるのでコンテナクエリ）は、☰ / テキストのチップ / 既定の物理配列 / Undo・Redo（個別画面は共有も）を1行に収める。そのために「テキスト」という文字とテキストの言語の表示は見た目から省き、物理配列はキーボードのアイコン、共有（個別画面のみ）もアイコンだけにする（テキストのチップが残りの幅を使う）。狭くてもUndo/Redoと、個別画面の共有は常時出す。中間の段階は置かず、テキストと物理配列のチップが重なる幅になる前にまとめて切り替える
- Workspaceの文脈バー（Workspace名がある）は、狭い時に**2段**にする（同じ境目）。1段目: ☰ / Workspace名 / ⋯ ………… 元に戻す・やり直す、2段目: テキストのチップ（残りの幅を全部取る）/ 物理配列のチップ。名前と⋯を足した1行ではテキストのチップが潰れて、文字も▾も見えなくなる（390pxで18px。タップの最小の大きさ24pxを下回る）ため、チップを2段目へ送る。名前が長い時は名前を省略し、⋯と元に戻す・やり直すは1段目から出さない。Workspaceは共有を出さない

### Workspace

保存したWorkspaceを開き、Analyzerをペインとして並べる器。個別画面と同じAnalyzerのcomponent（`hosts/shared/panes/`）を載せる。

- **資産として持つ。** 名前・自分のテキストの選択・連動の組（と組ごとの対象）・ペイン・ペインの並び・板の高さが1件のWorkspaceで、手持ちは資産のcodec（版番号 + decode）を通して保存する。書き込み（作成・名前の変更・ペインの追加/複製/閉じる・対象と解析設定の変更・連動の組の対象の変更と付け替え・並びの変更・テキストの選択）はすべてコマンドで、Undoが効く
- **保存形式はDockviewの形を持たない。** 並びは自前の小さな木（タブの組と、向きつきの分割。大きさは兄弟どうしの比）で持つ。Dockviewとの変換は `hosts/workspace/layout-adapter.ts` の1か所に閉じる。Dockviewを更新・置き換えても、保存済みのWorkspaceは読める。Dockviewを読むのは `hosts/workspace/WorkspaceDock.tsx` だけ（型だけを読む `layout-adapter.ts` を除く）
- **連動の組**をWorkspaceが1つ以上持つ。画面では「リンク」などの文字の名前を付けず、鎖のアイコンと並びの番号で表す（読み上げ名は「連動 N（対象: …）」）。組ごとに、対象を1つ見るAnalyzer用の1つ（Single）と、集合を見るAnalyzer用の集合（Multi）を別々に持つ。同じ組に従うペインは、組の対象を切り替えると一括で追従する。組の見分けは並びの番号で、対象の色（配列ごとの色）のパレットは使わない（紛れるため）。Workspaceを作る時に、個別画面で今選んでいる対象（Singleの対象・Multiの集合）を最初の組へ写して始める。写した後は個別画面と連動しない。集合の基準は組の集合の中で持つ。色の番号は組にもペインにも持たせず、Workspaceが1つだけ持つ（「表示名と色」）
- **ペインが持つもの**は、Analyzerのid・解析設定・対象の持ち方。持ち方は次の2つで、全ペインがどちらかを明示して持つ（比較中のペインが黙って別の対象を映すことは構造上起きない）
  - **従う**（どの組かを持つ）: 組の対象を読む。新しく足したペインの既定は最初の組（足したペインが黙って別の対象を映さないようにする）。従うペインの見出しで対象を選ぶと、そのペインだけでなく組の対象を書き換える（同じ組の他のペインも変わる）。組の対象を切り替える入口は、従うペインの見出しだけ
  - **固定**: そのペイン専用の対象を持つ。組の対象を切り替えても動かない。固定にした時は、押した瞬間の見た目が変わらないよう、今映している対象をそのペインの対象として持つ。従うへ戻すと固定の対象は捨てる（戻したい時はUndo）
  - 見出しの対象の隣に、持ち方を示すアイコンを置く。連動に従っている間は鎖に組の番号を添え、固定の間はピンにする（ピン留め = 固定）。hoverの説明は、連動が「同じ番号のペインと、配列・Setupが一緒に変わる」こと、固定が「このペインの対象は、他のペインに合わせて変わらない」こと（Setupが変わればそれに付く条件も変わるので、条件が変わらないとは書かない）。押すとメニューが開き、1行1項目で、絵（ピン / 鎖と番号 / 鎖と＋）に続けて「固定」・各組の対象の要約（Multi側は長ければ「他N件」に畳む）・「新しい連動」を出す。項目の読み上げ名は「連動 1（Colemak-DH）」「新しい連動（今の対象で作る）」のように文字で持つ。新しい連動は、そのペインが今映している対象で作る（見た目は変わらない）
  - どのペインも従わなくなった組は消える。ただし組は1つ以上残す（全ペインを閉じても先頭の組と対象は残り、次に足すペインが従う先になる）
  - 組の作成・付け替え・空になった組の削除は1回の操作で、元に戻すも1回で戻る。複製は持ち方を写す
- 読めないペインは失わない。今のアプリが知らないAnalyzerのペイン・対象の形が合わないペインは、使えないことを示して閉じられるようにする。壊れた保存データは壊れた部分だけを捨てて開く
- 1つのペインの失敗（描画の例外）は、そのペインだけに閉じる。他のペインとWorkspaceは動き続ける
- engineのキャッシュは、Workspaceの全ペインで共有する。同じ条件のTrace・抽出は、ペインが増えても1回だけ計算する
- 入力が変わっていないペインは、計算を頼み直さず「計算中」にもならない。Workspaceの保存（アクティブなタブ・連動の組の対象・並び）でテキストの解決結果の参照が変わらないよう、中身が同じ間は同じ参照を保つ（`hosts/shared/stable-resolved-text.ts`）。一度計算した入力へ戻る時（配列の選び直し・タブの切り替え）は、Workerの結果をメインスレッドに写したもの（`EngineComputer` の `peek*`）から同期に引き、Workerへの往復を挟まない
- ペインの並びの変更（境界のドラッグ・タブの移動）は、操作が終わってから書く。ペインの追加・閉じる・Undoで資産が変わった時は、資産に合わせてDockviewを描き直す（既にあるペインの部品は作り直さない）
- タブ（Dockviewのタブの帯）は、**Analyzer名・ⓘ・閉じる（×）を持つペインの名前の行**。ペインの中には名前の行を置かない（読み上げ用のh2は視覚的に隠して残す）。ⓘの説明は帯の外（`body`直下）へ出し、帯の切り抜きに隠れないようにする。閉じるはタブの×と⋯の中の2か所。閉じるボタンの名前など、Dockviewの既定の英語の文言は画面に出さない。見比べるために `?tabs=hide` でタブの帯を出さない表示にでき、その時は枠の中に名前の行が戻る（画面には出さない）。タブが無い縦積み（スマホ幅）も枠の中に名前の行を持つ（#628・#827）
- Workspaceが無い（削除された・別のブラウザで開いた）URLは「Workspaceが見つからない」を出す
- まだ無いもの（#757・#763の続き）: ⋯の「拡大表示」、Workspaceの削除・複製の操作
- 静的配信（GitHub Pages）では `/workspace/<id>` のHTMLをビルドで作れない（idはブラウザの保存先にしかない）。ブラウザで描く枠として `/workspace/_` をビルドし、`404.html` へ複製して、存在しないURLを開いた時にその枠がURLのまま描く（`scripts/write-workspace-fallback.ts`）

### ページの見出し

- 個別画面は、ペインのAnalyzer名がページのh1
- WorkspaceはWorkspace名がh1。Workspaceのペインの名前はDockviewのタブが見た目に出し、ペインの中のh2（Analyzer名）は視覚的に隠して残す。各ペインは読み上げ用の名前（Analyzer名と対象）を持つ

### ペイン

- 見出しは「Analyzer名 ⓘ / 対象 / 解析設定」に、Workspaceのペインだけ⋯が付く。個別画面は⋯を置かない（中身が「解析設定を初期値に戻す」だけで、それは解析設定の小窓のヘッダーへ置くため）。ⓘはAnalyzerの短い説明を出す（hoverとタップ）。対象のフル名だけの行は置かない。フル名はhoverに出す
- スマホ幅（〜760px）の個別画面では、見出しを**1行**にする（ⓘ / 対象 / 解析設定（アイコン））。見出しにAnalyzer名を出さない（ペイン1枚で、サイドバーとページタイトルで分かる。読み上げ用の名前は残す）。空いた幅は対象ボタンに渡す。ペインの幅だけで決まる下の2段は、タブの無い面（`?tabs=hide`・縦積み・個別画面）用に残す
- **板（ペインを並べる面）の高さは自動で伸びる。** 板の高さは「画面の高さ」と「Workspaceに保存した高さ（`boardHeightRem`、rem）」の大きい方で、保存が無ければ1画面。ページは板の高さに合わせて縦にスクロールする（文脈バーは上に貼り付いたまま）。保存を書くのは `engine/workspace-board.ts` だけで、**配置の形が変わった時**（ペインの追加・複製・分割・タブの移動。閉じる操作では板に触れない。閉じても縦の割合は減らず、畳まれた列の人の比を数えると板が際限なく伸びるため）に、どのペインも下限を割らない高さまで伸ばす。サッシのドラッグ（比の変化）は形を変えないので板を動かさず、狭めた分は隣のペインが取る（Dockview標準）。縮めるのは人の操作だけで、自動では縮めない。画素でなくremで持つのは、ペインの下限もremで持つので、文字の大きさを変えても下限との関係が崩れないため。ペインの下限は「見出し・余白（ホストが持つ `hosts/workspace/board-policy.ts`。タブを出す時は見出しが1行なので1つの値）+ 本体の下限（Analyzerが `pane-meta.ts` の `minBodyHeightRem` で宣言。省略で既定。値は `analyzers/min-body-height.ts` に1か所）」で、engineには方針（`BoardPolicy`）として渡す。ペインを足した時の縦の分割の高さは、各ペインの下限に比例させる（等分にしない）。配るのは、形が変わった縦の分割。縦の分割は、子の形が前の配置のどれかの縦の分割の子の形の部分列になっている時（何も変えていない、または段を取り除いただけ）に限り「変わっていない」とし、それ以外（新しいペイン・他所から来たペイン・段の入れ替え・段の中の組み替え。根が縦の配置での移動や入れ子の列への移動も含む）と、それを囲む縦の分割は「変わった」とする。足したペインを含む列の他のペインの比は動き、変わっていない分割（形が同じ・段を取り除いただけ）の比は人が決めたものとして動かさない。板を伸ばす判断にも同じ判定を使い、変わっていない縦の分割は、変わった分割の外では数えず、中では人の比で割らずに下限の和 + 間で数える（人が狭めたペインを、板を伸ばす理由にしない。比で割ると板が際限なく伸びる）。スマホ幅の縦積みでは板の高さを使わない。板の最大幅（`--workspace-board-max-width`）とは独立
- **名前をタブが持つWorkspaceのペインは、見出しを幅によらず1行にする**（対象・連動/固定・条件・状態・解析設定・⋯。名前とⓘはタブ）。幅で段を変えない。狭くなったら、対象は省略し、解析設定と条件は絵だけにする（条件は既定と違う時だけ点を添える）。見出しの上の余白と、見出しと本体の間は8px。条件は広い時（ペインの幅が34rem超）は「条件: 既定値」「条件: 3件変更」のchip、狭い時は一覧の絵（解析設定のスライダーの絵と区別する）で、押すと条件のモーダルが開く。chipの文字は絵だけの時も読み上げ用に残す。変えた項目の中身は、モーダルとhoverの説明が出す
- タブの無い面（縦積み・`?tabs=hide`）のペインは、枠の中に名前の行を持つので、狭い時（ペインの幅が40rem以下）は**2段に固定**する（1段目: 名前とⓘと⋯、2段目: 対象と解析設定）。対象名は省略し、解析設定はアイコンだけにする。名前の長さで段数を変えない。条件の要約は別の行に出す。個別画面は⋯が無く、固定する見出しを薄く保つため、狭いペインでも1行のまま（解析設定はアイコンだけになる）
- 個別画面のペインは枠を付けない。Workspaceのペインは、Dockviewのspacedテーマ（ペインの間の余白・角丸）に寄せる
- スマホ幅（〜760px。見出しを1行にする・サイドバーを引き出しにする境目と同じ）のWorkspaceはDockviewを使わず、ペインを縦に積み、ページを縦にスクロールして見る。積む順は、並びを左→右・上→下に読んだ順（Dockviewの読み順と同じ）。タブでまとめたペインはタブの順に全部を積む。並びは読むだけで書かないので、境目をまたいで広げ直すと、Dockviewの並び・大きさは資産のまま戻る。積む時のペインの本体は、高さが中身で決まるので幅だけのcontainer（個別画面と同じ）にし、高さで描き分ける規則は効かせない
- ⋯の中身
  - 個別画面: ⋯を置かない。「解析設定を初期値に戻す」は解析設定の小窓／シートのヘッダー（タイトルと閉じるボタンの間）に文字ボタン「すべて初期値に戻す」として置く
  - Workspace: 「拡大表示」「複製」「解析設定を初期値に戻す」「閉じる」
  - 拡大表示は、Workspaceの中でそのペインを大きく見せ、元の並びへ戻る操作。別のページへは移らない。モーダルにするかDockviewの最大化にするかは実物を見て決める（#628）
  - 「解析設定を初期値に戻す」（小窓の「すべて初期値に戻す」も同じ）には、対象と条件は変わらないことを説明に添える。「解析設定を既定へ」とは書かない
  - 「解析設定を初期値に戻す」の戻す先はAnalyzerの既定値（`defaultOptions`）。個別画面でもWorkspaceでも同じ。URLで開いた時の値や、Workspaceに保存した値へは戻さない（保存した値へ戻す操作が要るかは #637）
- **「解析設定」は小窓で開く。** パソコン幅では、フローティングの小窓に解析設定のcomponentを出す
  - 非モーダル。背後を暗くせず、開いている間も図や他のペインを操作できる
  - ドラッグで動かせる。図を見ながら値を変えられるように
  - Workspaceでは、どのペインの設定か分かるよう小窓にペインの名前（読み上げ用の名前と同じもの）を出す
  - スマホ幅（〜640px）では、画面の下から出るシートにする。上端の掴みとヘッダー行を下へドラッグして閉じる（×とEscapeでも閉じる。掴みはタッチ専用の見た目で、Tabや読み上げの対象にしない）。シートが「解析設定」ボタンを覆ってもドラッグで閉じられるので、ボタンでの開閉は求めない。閉じたらフォーカスは「解析設定」ボタンへ戻す

### Analyzerがペインに渡すもの

Analyzerはペインの**中身だけ**を渡し、どこに出すかはホスト（ペインの枠）が決める。
個別画面とWorkspaceで同じ部品を使う（#544 完了条件）ために、配置ではなく受け渡しの形を揃える。
Analyzerが見出し・説明・解析設定のパネルを自前で描くと、ペインの見出しと二重になり、
狭いペインでは図に届く前に設定で埋まるため。

Analyzerの結び付け（各Analyzerの `definition.tsx`）が渡すもの:

| 渡すもの | 中身 | ホストが出す場所 |
|---|---|---|
| 名前 | 画面に出すAnalyzer名（「Bigram Flow」「比較表」「N感度」） | ペインの見出し（Workspaceはタブ）、個別画面のh1、読み上げ用の名前、サイドバー |
| 短い説明 | 何を描くかを1〜2文で。操作の説明や経緯は書かない | 名前の横のⓘ（Workspaceはタブ） |
| 本体 | 図・表を描くcomponent。抽出の結果・対象の入力・解析設定を受け取って描く | ペインの残りの領域いっぱい |
| 解析設定 | 解析設定の項目を並べるcomponent。今の値を受け取り、変更を返す | 見出しの「解析設定」ボタンから開く小窓 |
| 対象の選択に差し込む項目（任意） | 対象の集合に属する、そのAnalyzerだけの項目（比較表の「基準にする対象」）。今の値と対象の表示名を受け取り、変更を返す | 対象の選択の中 |
| 解析設定の既定値 | 宣言（`options.ts`）から導いた `defaultOptions`（既存） | 解析設定の各項目の「既定値へ戻す」と、解析設定のヘッダーの「すべて初期値に戻す」（Workspaceでは⋯の「解析設定を初期値に戻す」）の戻す先 |

本体と解析設定のcomponentは、どちらも**置かれる場所を知らない**。

- 見出し（Analyzer名）・説明の段落を持たない。本体の中に図が2つ以上ある時の、図ごとの小見出しは持ってよい
- 自分の外枠（枠線・背景のパネル・カード）を持たない。枠はホストが付ける
- **画面の幅ではなく、置かれた領域の幅で描く。** 幅で切り替える時は container query（ホストが本体と解析設定の領域をcontainerにする）か要素の実寸を使い、幅の `@media`・`vw`・`window.innerWidth` を使わない。自分の最大幅を絞らない（どこまで広げるかはホストが決める）。ただし推奨幅は宣言できる（`pane-meta.ts` の `recommendedWidthRem`。省略で既定。値は `analyzers/recommended-width.ts` に1か所）。縦は別に、本体が読める最小の高さを `pane-meta.ts` の `minBodyHeightRem` で宣言でき、Workspaceの板の高さを決めるのに使う（省略で既定。値は `analyzers/min-body-height.ts` に1か所）。ホストが個別画面とWorkspaceのペインの両方で、中身をその幅で止めて中央へ寄せる。ペインが推奨幅より狭い時は効かず、ペインの幅に縮む（スクロールさせない）。推奨幅はペインの幅を超えて広げる方向には効かない
- **Workspaceのペインでは、置かれた領域は高さも持つ。** ホストが本体の領域に「ペインの残りの高さ」を持たせ、幅と高さの両方のcontainerにする。個別画面の本体は幅だけのcontainerで、高さは中身で決まる。高さや縦横比に合わせて図を縮める・並べ替える時は container query を使い、`@container pane-body (min-height: 1px)` の中に書く（縦横比の問い合わせもこの中に入れる）。ホストは本体の領域を名前つきのcontainer（`pane-body`）にし、Workspaceは幅と高さ、個別画面は幅だけを測れるようにする。個別画面には高さを測れる `pane-body` の祖先が無いので判定は偽になり、何も変わらない（ホストが誰かを知らずに済む）。そのため、ホストは `pane-body` を入れ子にしない（高さを測れる `pane-body` の中に別の `pane-body` を置かない）。名前を付けるのは、名前の無い問い合わせだと、条件を測れる祖先のうち一番近いものを選ぶ際に、個別画面の本体を飛ばして外側の無関係なcontainerの高さを読んでしまうため。名前を付ければ、候補が `pane-body` という名前の祖先に絞られる（名前付きでも、条件を測れないcontainerは飛ばして外側の同じ名前を探す）。縮めすぎて読めなくなる下限はAnalyzerが持ち、下限より低い領域では本体の領域の中でスクロールする。縦横比で並べ替える時は幅の下限も併せて問う（縦横比だけだと幅の狭い低いペインで図が小さく潰れる）。余った高さは枠の中ではなく枠の外に置き、枠は図の縦横比より縦に伸ばさない。描く大きさをJSで決める時は、container queryが効いている印をカスタムプロパティに立て、JSはその計算値を読む。Analyzerは門番 `@container pane-body (min-height: 1px)` の中でだけ宣言し（N感度の `--n-sensitivity-fit`、Bigram Flowの `--flow-repeat-label-max-scale`）、個別画面では宣言が無く値は空になるので、JSは空を「効いていない」として従来の描き方にする（Bigram FlowとN感度が例）
- 解析設定のcomponentは縦1列でも成立させる（狭いペインでも、開いた先の出し方が変わっても崩れないように）
- 状態表示（計算中・古い結果・失敗）・条件の要約・対象の選択・テキストを持たない。ペインの枠が持つ
  - 例外: 集合を見るAnalyzerで、抽出の値として届くメンバー単位の失敗・未着（`AnalyzerSetMemberFailure`。比較表の行の失敗・計算中、N感度の凡例の失敗行）は本体の行に出してよい。一部のメンバーの失敗でペイン全体を失敗にしないため（#544 §8-5）
- 単一対象の配列・物理配列・指の割当の名前を本体で繰り返さない（見出しの対象と条件の要約が出す）。集合を見るAnalyzerも、行ごとの条件は本体に併記しない（条件の要約の「対象ごとの差」が出す）
- 「数値は観測値であり、配列の優劣を判定するスコアではない」の注記を持たない（トップにだけ置く）。表示中のデータに条件付きで付く注記（何を除いたか等）は本体に置いてよい
- 対象の表示名・色を自分で決めない。ホストが集合に対して計算したもの（「表示名と色」）を受け取る
- 戻す操作を自前で作らない。戻す操作は2つあり、どちらもAnalyzerの外が持つ
  - 全部を戻す: ホストが持つ。個別画面は解析設定のヘッダーの「すべて初期値に戻す」、Workspaceは⋯の「解析設定を初期値に戻す」
  - 1項目だけ戻す: 解析設定の各項目に付く小さな操作で、値が既定と違う時だけ出す。Analyzerごとには作らず、項目を描く共通の入力部品（`ui` 側）が持つ形を推奨する。Analyzerは項目ごとの既定値を宣言する（`defaultOptions`）だけ
  - 複数の項目をまとめて戻す操作（旧Bigram Flowの「標準に戻す」）は置かない。項目ごとの操作に置き換える
- 本体は、ペインの解析設定の入力部品（選択・チェックボックス・スライダー）を持たない。ただし**図ごとにしか効かない項目は、その図の見出し行のボタンから図のそばで開く**（Bigram Flowが最初の例。ペインの解析設定には両方の図に効く項目だけを残す）。値の持ち主は1つの `AnalyzerOptions` のままで、本体は変更の通知（`onOptionsChange`）を受け取って返す。展開の状態は保存しない。図そのものへの一時的な操作（hoverでの強調等）は本体が持ってよい
- Router・Dockview・`hosts/` をimportしない。storage・URL・クリップボードを触らない。値の変更は受け取った通知で返し、保存・Undo・URLへの反映はホストが行う
  - URL・クリップボード・`location`・`history` に触らないこと、CSSに幅の `@media`・`vw` が無いことは `test/architecture-layers.test.ts` が検査する

ホストの責任:

- ペインの見出し（名前・対象・「解析設定」。Workspaceのペインは⋯も）、条件の要約、状態表示、error boundary、診断の表示
- 解析設定を小窓で開閉し、解析設定のcomponentを置く。値の保存はコマンドを通す（#544 §8-2）
- Analyzerが差し込む項目を対象の選択の中に置く
- 短い説明を名前の横のⓘで出す（Workspaceのペインはタブが出す）
- 本体の領域をペインいっぱいに取り、containerにする（Workspaceのペインは、見出しなどを引いた残りの高さも渡して、幅と高さのcontainerにする）
- ペイン全体の計算中・失敗・対象が空の時の表示。本体は描ける値がそろってから呼ばれる（集合のメンバー単位の失敗・未着は上の例外どおり本体が出す）
- 共有（URL）。個別画面の「今の設定のURLをコピー」のような導線は文脈バーの共有に寄せる

### 条件の要約

- 閉じた状態は1行。変えた項目の先頭2件（項目の定義順）と「他N件」を出す。何も変えていなければ「すべて既定値」
- 変えた項目は、既定値から上書きされていて、その対象に効くもの。効かない上書きは数えない（その条件で測ったように読めるため）
- 押すと**条件のモーダル**を開く（どの画面でも同じ器。スマホ幅は下からのシート）。先頭に対象の実体（配列 / 物理配列 · 指の割当）を1行、その下に条件の行を群ごとに並べる。対象のフル名（既定と違う条件つき）は出さない。各行の札に、この画面で効いている値の出どころ（既定値 / 全体で変更 / 配列「X」で変更）を出す
- **モーダルの行は全体（グローバル）のレベルを編集する。** 行の値は全体のレベルの値（上書きが無ければ既定値）で、この画面で効いている値ではない。書き込みはコマンド（`setCascadeOverrideCommand` / `resetCascadeItemCommand`）を通すので文脈バーの元に戻す／やり直すが効く。既定と同じ値を書くと上書きを消す
- 行は、カスケードでグローバルに置ける項目（先読みN・同指連続のホーム復帰距離・親指シフトの振り替え・シフト系キーの押し続け・動作数の扱い・既定の物理配列・指の割当・ローマ字規則・チェーンの区切り・アルペジオの数え方）。既定の物理配列は文脈バーのチップと同じ値を書く（チップは残す）。ローマ字規則は、かな配列には効かないだけで全体の値は1つ。推奨を持つ配列（大西配列・TK音直入力法）は、全体を変えても推奨のままで、その理由を行の下に出す（出どころは既定値のまま。変えた項目には数えない）
- 「動作数の扱い」は「Shift+A で1動作」/「Shift→A で2動作」。2動作の時だけ、キーの種類ごとの例外（先に押しておくキー・押す順を問わないキー）を畳んで出す
- 全体で変えても下のレベル（配列・Setup）の値が勝って画面が変わらない行は、編集できるまま理由を添える。配列を問わず出す
- ペインが自分で動かす項目（N感度の先読みN）は行に出さない
- 値は短く要約する。効いていない値の一部（Shift+A で1動作の時の例外）は出さず、それだけが違う上書きは変えた項目に数えない。
- チェーンの区切り・アルペジオの数え方はモーダルの行としてだけ編集できる。今の画面にこれらを読む数値が無いので、閉じた1行の件数にも対象名の差分にも数えない（効かない上書きは数えない）。これらを読む画面ができたら要約の項目に足す
- モーダルの見出しの「すべて既定値に戻す」は、モーダルに行がある項目の全体の上書きだけを1コマンドで消す（行の無い項目は消さない。元に戻すの1回で全部戻る）
- 個別画面とWorkspaceで同じ部品を使う（`hosts/shared/ConditionSummary.tsx`）
- 複数の対象を持つペイン（比較表・N感度）は、**共通の条件 + 差のある対象だけ**を出す。単一の対象のペインは変えない
  - 共通の行は**この画面で効く値**（対象ごとの上書きも、配列・物理配列ごとの既定も受けない時の値。全体のレベルの値、それも無ければ項目の既定値。指の割当は列固定）。対象の並びに依らず、最初の対象の値を共通として採らない。閉じた1行はこの共通の行だけを、上と同じ規則で数える。効く値が共通の行と違う対象があれば、末尾に「対象ごとに差あり」を添える
  - モーダルの中で、共通の行（出どころ付き）の下に「対象ごとの差」の節を置き、**効く値が共通の行と違う対象だけ**を、違う項目だけで並べる（例: 共通「ローマ字規則 訓令式（既定値）」に対し `大西配列: ローマ字規則=大西式`。全体をAZIKにしても大西配列は大西式のままなので、共通「AZIK（全体）」に対して差に出る）。全対象が共通の行と同じなら節を出さない。全対象が同じ値へ上書きしても、共通の行は画面の値のまま、全対象が差に出る。その項目が効かない対象は数えない
  - ペインが自分で掃引する項目（N感度の先読みN）は、共通の条件にも差にも出さない
  - 対象ごとの条件を表や凡例の行へ併記しない（要約の「対象ごとの差」が同じ情報を出す）。比較表に「条件」の列は置かない

### 対象の選択

- 絞り込み欄と、区分（組み込み・英字 / 組み込み・かな / 自作の配列 / Setup）ごとのチェックリストで選ぶ
- **選んだ瞬間に反映する。決定ボタンは置かない**（戻したい時はUndoで戻す）
- 1つだけ選ぶAnalyzerは、同じ部品をラジオで使う
- パソコン幅は見出しの対象ボタンから開くポップオーバー（非モーダル。外を押すかEscapeで閉じる）、スマホ幅は画面下からのシート。個別画面とWorkspaceで同じ部品を使う（`hosts/shared/TargetSelection.tsx`）
- 見出しでの表示は、入り切らなければ「先頭 他N件」に畳む。全件はhoverに出す
- 集合の対象は、付けた順ではなく一覧の順（組み込みの定義順 → 自作の配列 → Setup）に並べる。色は並びと別で、加えた順に配る（「表示名と色」）。並べ替えは将来、手持ちの配列の画面で一覧の順を変える形で持つ（#642）
- 対象が空のペインには説明文を置かず、「配列・Setupを選ぶ」ボタンだけを置く（押すと見出しから開くのと同じ選択が開く）。パソコン幅では、空のペインを開いた直後に選択を自動で開く。フォーカスは奪わず、一度閉じたらそのペインでは出し直さない。スマホ幅のシートは画面を覆うので自動では出さない
- Analyzerは、対象の選択に自分だけの項目を差し込める（「Analyzerがペインに渡すもの」）。比較表の「基準にする対象」がこれで、値の持ち主が対象の集合なので、解析設定ではなく対象の選択の中に置く

#### 個別画面どうしで共有する対象

- **個別画面が持つ対象は2つだけ。** Singleの対象1つと、Multiの集合1つ。同じ区分のAnalyzerはどれも同じ値を読み書きし、Analyzerごとには持たない。1つの配列（や集合）を選んで、いろいろな解析を見るため。Analyzerを移るたびに選び直させない
- Multiの集合は、選んだ対象（加えた順に持つ。表示の並びは上のとおり一覧の順で、ここに持つ順ではない）・色の番号・基準をまとめて1つの値として持つ。比較表の「基準にする対象」も集合の値で、基準を使わないAnalyzer（N感度）でも集合から消さない。基準は「集合に含まれる時だけ効く値」で、基準の対象を集合から外しても記録は消えず、効く基準が「なし」になる（同じ対象を付け直すと戻る。基準を選び直すと記録も上書きする）。不変条件は「効く基準 ∈ 選択」で、比較表は効く基準だけを読む
- **SingleとMultiは連動させない。** 片方で選び直しても、もう片方は変わらない
  - 例外は1つ: Singleの対象がまだ選ばれていない時にMultiで基準を選ぶと、同じ操作でSingleにもその基準を一度だけ書く（1操作・1履歴なので、Undoで基準とSingleが一緒に戻る）。Singleに値が入った後は、基準を変えてもSingleは変わらない
  - Singleの対象がまだ選ばれていない間は、既定の配列（QWERTY）を出す。表示中のQWERTYを押しても「選んだ」になる（キーボードで選ばれているラジオにSpace・Enterを押した時も同じで、書き込んで閉じる。矢印キーで送る間は閉じない）
- Workspaceのペインの「従う / 固定」（#544 §6）で「従う」の先になるのは、Workspaceの連動の組の対象。この共有の値ではなく、Workspaceを作る時にここから最初の組へ写して始める（写した後は連動しない）
- 保存の形は区分ごとに1つ（Analyzer idで引かない）。この形に変えた時、それまでのAnalyzerごとの選択は読み込まない（互換は守らない）

### 表示名と色

- **表示名は常に、同じ画面に並ぶ集合に対して計算する。** 集合の中で共通な部分は落とし、違う部分だけを出す（`{QWERTY/row-staggered, Colemak-DH/row-staggered, QWERTY/row-staggered・指割当JIS}` → `QWERTY` / `Colemak-DH` / `QWERTY · 指割当JIS`）。**集合が1件（Singleの対象）なら共通部分は全部なので、名前だけを出す**（条件を変えたSetupでも `QWERTY`。条件の差分は直下の条件の要約で見る）。フルの名前はhoverに出す。それでも同じ名前になる対象（配列と、上書きの無い同じ配列のSetup等）は、その対象だけに種類（`配列` / `Setup n`）を添えて区別し、内部のidは出さない
- **色も同じ画面に並ぶ集合の中で、パレット（#601）から加えた順に配る**（見分けられる色は10〜12色が上限で、組み込み配列の数より少ないため、対象ごとに固定すると必ずどこかで重なる）。1つ外しても他の対象の色は動かさず、空いた色は次に加えた対象が使う。並び替えでも色は対象に付いて動く。同じ配列が画面によって違う色になることは受け入れる
- **Workspaceでは画面全体（全ペインの対象の和）を1つの集合として色を配る。** 同じ画面では、同じ対象はどのペインでも同じ色になる
  - 色の番号は対象ごとに1つで、Workspaceが持つ（`Workspace.colorSlots`。純粋な部分は `engine/workspace-colors.ts`）。集合を持つ組・固定のペインは番号を持たない。個別画面の集合は、ペインが1枚なのでペインの集合＝画面の集合で、番号を集合に持つ
  - 配るのは、組・ペインの対象が変わりうる書き込みの後（`updateWorkspace` が毎回通す）。和に残る対象は今の番号のまま、新しく和に入った対象にだけ加えた順（組 → 固定のペイン、それぞれ並び順）で配る
  - 別のペインにも居る対象は、片方のペインから外しても色を失わない。ペインを閉じた時も同じで、そのペインだけに居た対象の番号が空き、次に加えた対象が使う
  - Workspaceを作る時は、個別画面の集合で配っていた番号を引き継ぐ（見ていた対象の色が変わらないように）

### 条件の編集とURL

- **条件の編集は条件のペインで行う。** 書き込むレベルの既定は対象のレベル（配列を対象にしていれば配列、Setupならそれ）。「この条件だけ別にしたい」は、その場でSetupを作る操作として出す。上位への適用（この配列全部・全体）は昇格の操作として出す。今書けるのは全体のレベルだけ（上の「条件の要約」のモーダル）で、配列・Setupのレベルへの書き込みは後の段
- **URL**: 個別画面は `/analyzer/<analyzer>`。URLで固定された1ペインで、URLはペインの初期値（対象・解析設定）を運ぶ。3つの単体ページの「共有」は、対象と解析設定をURLに載せ、開いた側が取り込む（解析設定は`hosts/standalone/use-url-options.ts`、対象は`use-url-targets.ts`。読み書きの純粋な部分は`target-share.ts`）。
  - **対象の載せ方**: 組み込みの配列は id（`layout:<id>`）で載せ、受け取った側でそのまま開く。自作の配列・Setup は名前だけ（`user-layout:<名前>` / `setup:<名前>`。Setup は付けたラベル、無ければ「配列名/物理配列名」）で載せる。端末ごとの id は運ばない。受け取った側に同じ名前が無ければ、名前を添えて「見つからなかった」と示す（同じ名前が複数ある時は一覧の先頭）
  - **画面ごと**: Single（Bigram Flow）は `target`、Multi（比較表・N感度）は `targets`（対象ごとに繰り返す。並び順ごと運ぶ。色の番号は運ばず、受け取った側で配る。元から持っていた対象の色は持ち越し、新しい対象にだけ配る）と `baseline`（効いている基準だけ。比較表の基準は集合の値の一部で、受け取った側で見え方が変わるため、基準を使わないN感度のリンクにも載せる）
  - **取り込み**: 資産の読み込み後に1回だけ、手持ちで引けた対象でその画面の対象（Single / Multiの集合と基準）を置き換える。1操作なのでUndoで受け取る前へ戻る。1つも引けなければ今の対象を変えない。取り込んだらURLから消す
  - 外から来る値なので、資産と同じcodecの境界（valibot）を通し、対象は40件まで・1件200文字までに絞る（共有リンクのサイズ上限）
  - 取り込めなかったものは、保存済みの設定の読み直し（「既定値へ戻した」）とは別の文でペインに出す（`PaneFrame`の`linkNotices`）。URLでは、集合の要素を落とした時は残りを取り込み、値全体を捨てた時は今の値が残るので、どちらにも当てはまる「取り込まなかった」と書く。
- **プリセットは条件のモーダルの上部**（閉じたまま開く折りたたみ）で、保存・流し込み・名前の変更・削除をする。流し込みの先は今は全体のレベルだけ。モーダルは背後の文脈バーを操作できなくするので、保存・流し込み・削除の直後の結果の行に「元に戻す」を置く（`ConditionEditorContext`の`undo`。文脈バーと同じ履歴）。書き出し・読み込みも同じ節にある（`hosts/shared/PresetSection.tsx`）。
  - ファイルは`{ format: 'keydist-presets', version, presets }`。`version`と`presets`は資産のcodecの出力そのままで、`format`だけを`platform/browser-download.ts`が書く直前に付ける。読む時は`format`を見てからcodecへ渡す（旧画面の条件ファイルも`version: 4`を持ち、印が無いと新しい版と取り違えるため）。同じ封筒に`workspaces`を足して`version`を上げられる
  - 読み込みは追加だけ（常に新しいid、同名は「名前 2」）で、読み込んだだけでは条件は変わらない。上限は1MB・100件。分類と文言は純粋な`hosts/shared/preset-file.ts`、ファイルの保存・読み取りは`platform/`で、`app/shell/AppShell.tsx`が`PresetFileIoContext`で渡す。参照先の資産（自作の指の割当等）は同梱せず、この端末に無いものを指す値は残して注記する
- 保存したWorkspaceは `/workspace/<id>` で、URLは識別子だけ（#544 非目標「URLをWorkspaceの保存先にしない」）

## 依存の規則

どの層も自分の層の中は import してよい。表はそれ以外の行き先。

| from | import してよい先 |
|---|---|
| `input` | — |
| `trace` | input |
| `interpretation` | input, trace |
| `analyzers/<name>` の `.ts` | input, trace, interpretation, `analyzers/` 直下（契約）, 自分の `.ts` |
| `analyzers/<name>` の `.tsx` | 上に加えて、自分の `.tsx`, ui |
| `analyzers/` 直下 | input, trace, interpretation。個別のAnalyzerは不可 |
| `engine` | input, trace, interpretation, `analyzers/` 直下（契約） |
| `hosts/<name>` | engine, analyzers, ui, input, trace, interpretation, `hosts/shared`。他のhostは不可 |
| `editors` | input, ui |
| `tester` | input, ui, platform（当面の例外） |
| `ui/primitives` `ui/theme` | — |
| `ui/keyboard` `ui/charts` | ui/primitives, ui/theme, input |
| `platform` | input |
| `app` `routes` | すべて |
| `legacy` | すべて |

- Analyzer同士は import しない。個別のAnalyzerから別のAnalyzerへも、契約から個別のAnalyzerへも向かない
- host同士は import しない。共有物は `hosts/shared/` に置く。`hosts/` 直下にはファイルを置かない

- `legacy` と移行中の `features/analyzer-next` を import してよいのは app・routes・legacy・`features/analyzer-next` だけ
- **純粋な層**（input / trace / interpretation / engine、`analyzers/**/*.ts`、`tester/engine/`）は React・描画ライブラリ・Router・Dockview・DOM・storage・ブラウザAPIを使わない。`import type` も含めて使わない
  - **純粋さは推移的に守る。** 純粋なファイルは純粋なファイルしか import できない。抽出が表示用の型を借りたくなったら、その型を input か interpretation に置く
  - unit testの `node --experimental-strip-types` は `.tsx` を読めない。計算がReactのファイルを1つでもimportするとテストできなくなる
  - 重い計算をWeb Workerへそのまま移せる
  - キャッシュが描画のタイミングに縛られない
- **可視化は計算しない。** engineが抽出を実行し、hostが結果をcomponentへ渡す
- **Analyzerの契約は純粋な部分だけを `analyzers/contract.ts` に置く。** 名前・短い説明・本体と解析設定のcomponentとの結び付けは各Analyzerの `definition.tsx` で行う（「Analyzerがペインに渡すもの」）。結び付けは `analyzers/pane-parts.tsx` の `AnalyzerPaneParts` の形のオブジェクト（`bigramFlowAnalyzer` 等）で、ペインの見出し・個別画面のh1・routeの `<title>` はここから名前を読む。名前と短い説明はReactに依存しない `analyzers/<name>/pane-meta.ts` に置き、routeはそちらを読む（`definition.tsx` をimportすると本体のcomponentとCSSが全ページの初期読み込みに入るため）。engineは純粋な部分しか知らないので、engineの型にReactが現れず、Workerへそのまま移せる
  - 抽出のキャッシュキーは「解釈のキー + Analyzer id + 抽出に効くoptions」（`AnalyzerDefinition.extractKeyOf` が返す値。`engine/keys.ts` の `analyzerExtractionKeyOf`）。見た目だけの解析設定はここで除かれるので、見た目だけの変更ではextractが走らない
  - 単体ページの計算は、ブラウザでは Web Worker で走らせる（長いテキストで入力とスクロールが止まらないため）。ペインが頼む窓口は `engine/computer.ts` の `EngineComputer` で、メインスレッドの `EngineCache` と Worker 越しの `engine/worker-client.ts` のどちらも満たす。Worker の入口は `app/standalone/engine-worker.ts` で、そこに載せた Analyzer の定義だけが Worker で計算できる（Analyzer を足す時は、ここにも足す）。数値は変わらない（Worker の中も同じ `EngineCache` と同じ純関数で、メッセージは値の複製だけ）。Worker から受け取った結果は、メインスレッド側にも同じキー（`engine/keys.ts` の共通の入口）で写しておき、計算済みの入力は `peek*` で同期に引ける
  - 集合対象とN感度の例外向けに、抽出は「Traceを依頼する窓口」（`TraceRequester`、`analyzers/contract.ts`）を受け取れる。窓口の実装（キャッシュ経由でTraceを共有する）は `engine/trace-requester.ts` が持つ
- **storageを直接触るのは platform と app だけ。** 保存が要る層（hosts・editors等）は、appが組み立てたアダプタを注入して使う。Testerは当面の例外
- **import の書き方。** 別のトップディレクトリへは `#<dir>/...`（`package.json` の `imports`）、同じトップディレクトリの中は相対パス。ディレクトリを import しない（`index.ts` の暗黙解決はNodeのstrip-typesで動かない）。拡張子を付けて書く
- 外部ライブラリ: Dockview は `hosts/workspace/` だけ（実行時に読むのは `WorkspaceDock.tsx` だけで、並びの変換 `layout-adapter.ts` は型だけを読む。`test/architecture-layers.test.ts` が検査する）、TanStack Router / Start は routes・app・`hosts/standalone/` だけ（legacy と `features/analyzer-next/` は旧実装なので除く）。描画ライブラリ（motion等）は純粋な層以外で使ってよい
- 部品は最初は使う場所に置き、2つ目の使い手が現れた時に ui へ下ろす。Analyzer同士で共有したくなったら ui か interpretation へ下ろす
