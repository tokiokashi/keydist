# 境目の直後の1文字と、境目のまわりの並びを揃えたランダムな区切り

文節の区切りの直後の1文字の量（`docs/segment-metrics.md` の「区切りの直後の1文字」）が、ランダムな区切りと違う時に、その違いが区切りのまわりの1〜3文字の並びの出現頻度だけで説明できるかを調べる定義。
あわせて、境目の打鍵が全体の距離と文字数に占める割合を出す。
実装は `src/interpretation/boundary-context.ts`、実行は `scripts/kana-chain-comparison.ts` の `--stage boundary`（結果をMarkdownの表で出す）。画面には出さない。
距離モデルの値（`spec/distance-model.md`）は変えない。区間の集計は `docs/span-metrics.md` の分子と分母、ステップの帰属の規則をそのまま使う。

## 並びの型

区切りの位置 `p` は、評価に渡したテキストの文字 `p − 1` と文字 `p` の間を指す。位置 `p` の並びは、文字 `p` で終わる長さ `L` の文字列（`L` は1・2・3）。
その文字列を並びの型と呼ぶ。

| 並びの長さ `L` | 並び |
|---|---|
| 1 | 文字 `p` |
| 2 | 文字 `p − 1`、`p` |
| 3 | 文字 `p − 2`、`p − 1`、`p` |

前の文字が足りない区切り（`p < L − 1`）は、その長さの比較から除く。文節の値にも、ランダムな区切りにも入れない。

## 並びを揃えたランダムな区切り

並びの長さごと、乱数の種ごとに、区切りの組を1つ作る。

1. 比べる文節の区切りを、並びの型ごとに数える。型 `t` の文節の区切りの数を `k` とする
2. 評価に渡したテキストの位置 `[max(1, L − 1), 末尾)` のうち、型 `t` の並びが現れる位置の数を `m` とする（`k ≤ m`。文節の区切りの位置を含む）
3. 型 `t` の `m` 個の位置から、`k` 個を重複なしに一様に選ぶ（部分的な Fisher-Yates）
4. 全部の型について選んだ位置を集めたものを、その種の区切りとする

型は文字列の昇順に辿るので、同じテキスト・同じ種からは同じ区切りが出る。乱数は mulberry32（`src/interpretation/prng.ts`）、種は始まりの値 `s` から `s, s+1, …, s+19` の20個で、`docs/segment-metrics.md` のランダムと同じ。
区間の長さの分布は揃えない。比べる量は区間の値ではなく、区切りの直後の1文字の量だけなので、区間の長さが入らない。

この区切りの組は、文節の区切りと次を満たす。

- 型ごとの区切りの数が文節と一致する。区切りの総数も一致する
- 区切りのまわりの `L` 文字の並びの出現頻度は文節と同じになる。区切りの位置だけが、同じ型の別の出現位置に置き換わる

### 選ぶ余地が無い区切り

`m = k` の型では、その型の位置が全部選ばれるので、ランダムな区切りの位置が文節の区切りと同じになる。この型に入る文節の区切りを、選ぶ余地が無い区切りと呼ぶ。

選ぶ余地が無い区切りの割合は、`選ぶ余地が無い区切りの数 / 比べる文節の区切りの数`。並びの長さ・配列ごとに出す。

選ぶ余地が無い区切りは、順位を偏らせはしないが、文節の値とランダムな値の同点を増やして順位が端に来にくくする。そのため、判定が違いを見つけられなくなる。
割合が上限の10%を超える並びの長さ・配列では、判定を出さず、値と割合だけを示す。
上限は実装の前に固定した値で、結果を見て動かさない。`docs/kana-chain-comparison.md` の候補が1つの段の割合の上限と同じ10%だが、量は別（こちらは区切りあたりの割合）。
並びが長いほど型が細かくなり、割合は大きくなる。全文でも2文字・3文字の並びで10%を超え、判定が出ないことがありうる。その時は判定なしと出す。

## 比べる量と順位

比べる量は、1文字あたりの距離 `perCharUnits` [u] の「区切りの直後の1文字」。全区切りについて、範囲 `[p, p + 1)` の分子の和 / 分母の和（`docs/segment-metrics.md`）。
区間の値の分位点は比べない。

文節の値（前の文字が足りない区切りを除いたもの）が、ランダムな区切り20個と合わせた21個の中で何番目かを、`rankAmong`（`src/interpretation/segments.ts`）で出す。同点は幅で示し、端に数えるのは厳密に小さいか大きい時だけ（`docs/segment-metrics.md`「文節の値の順位」と同じ）。
順位は並びの長さ・配列ごとに別々に出す。

| 場合 | 判定 |
|---|---|
| 選ぶ余地が無い区切りの割合が上限を超えた | 判定なし |
| 端に来た | 境目のまわりの◯文字の並びでは説明できなかった（並びの外の打鍵を含む） |
| 端に来なかった | 説明できなかったとは言えない |

- 「説明できた」とは書かない。端に来ないことは、ランダムな区切りの値のばらつきが大きいほど起きやすい
- 並びの外の打鍵を含むと書くのは、境目の量が境目のまわりの文字の並びだけでは決まらないため。境目の量は `kanaEnd` が文字 `p` のステップの距離の和で、ローマ字の促音のように1つの入力が文字 `p − 1` と `p` にまたがる時は、文字 `p − 1` から始まる打鍵も入る。
  打鍵の距離は同じ指の直前の打鍵との間隔 `ΔI` が窓幅 `N` 以下かで決まり、既定の `N = 3` では3文字の並び（文字 `p − 2`〜`p`、`ΔI ≤ 2`）の外にある `ΔI = 3` の打鍵（文字 `p − 3`）も入る。
  担当する指が2本以上のキーを打つ配列では、指の選択が先の `N` 入力にも依る（`spec/distance-model.md` §9.1）。
  並びを揃えても違いが残る時、原因が文節の境目に固有の性質か、並びの外の打鍵かは区別できない
- 特徴が無くても、1つの判定が端に来る確率は最大で2/21（約9.5%）。判定は並びの長さ3通り×配列の数だけ並ぶ。有意とは書かない
- 配列や並びの長さをまとめた結論、配列の優劣の判定・順位・合成スコアは出さない
- 文節の区切りは BudouX の出力（`docs/segment-metrics.md`）。結果は人が付けた文節の区切りではなく、BudouX の区切りについてのもの

あわせて、`docs/segment-metrics.md` のランダム（区間の長さの並べ替え）を同じ全文で作った値と順位を並べる。こちらは全区切りを使い、前の文字が足りない区切りを除かない。

## 境目の打鍵が占める割合

配列ごとに次の2つを並べて出す。順位・判定は付けない。

| 量 | 定義 |
|---|---|
| 区切りの直後の1文字が文字数に占める割合 | 文節の区切りの数 / 全文の文字数（評価に渡したテキスト） |
| 区切りの直後の1文字に帰属する距離が距離に占める割合 | 全区切りについて範囲 `[p, p + 1)` の距離の和 / 全文の距離の和 |

分子の距離はステップの帰属（`docs/span-metrics.md`）で決まる。前の文字から始まる打鍵が文字 `p` に帰属する場合は、その打鍵の距離が入る。
前の文字が足りない区切りも除かない（並びの長さに依らない量）。

## 文節の内側と境目の距離

文節は、隣り合う区切りの間（テキストの先頭と末尾を含む）の文字の並び。文字を次の3つに分ける。

| 分け方 | 文字 |
|---|---|
| 境目の文字 | 文節の区切りの直後の1文字。全区切りを使い、前の文字が足りない区切りを除く規則は当てない |
| 文節の内側の文字 | 各文節の先頭の1文字を除いた文字 |
| テキストの先頭の文字 | 最初の文節の先頭。どちらにも入れない |

3つの文字に帰属する距離の和を足すと、全文の距離の和に戻る。配列ごとに、境目の文字と文節の内側の文字それぞれについて、帰属する距離の和を文字数で割った値（1文字あたりの距離）を出す。
境目の文字の値は、`docs/segment-metrics.md` の「区切りの直後の1文字」を全文で求めた値と同じ。文字数は `docs/span-metrics.md` と同じく、打鍵できなかった文字（`skipped`）も1文字に数える。
実装は `boundaryInterior`（索引と区切りの列を受け取る）と `boundaryInteriorOfTrace`（Traceと区切りの列を受け取る）。

文節ごとの内側の値は、その文節の内側の文字に帰属する距離の和を、内側の文字数で割った値。文字数（`skipped` を含む）が2以上の文節だけで求め、その数・中央値・90%点（`quantileNearestRank`）を出す。
内側の値は、`docs/segment-metrics.md` の区間の値（先頭の文字を含む）とは別の量。短い文節の内側の値はばらつきが大きく90%点を押し上げうるが、文節の長さでは分けない。

- 順位・判定は付けない。配列は組み込みの並び順のまま並べ、距離の小さい順などに並べ替えない。配列どうしを比べた結論は出さない
- 距離は指の移動距離から見た量で、打ちやすさそのものではない
- 境目の文字と文節の内側の文字では、かなの構成が違う（境目の直前に助詞・活用語尾が多い）と見込まれる。2つの1文字あたりの距離の差は、配列の性質と文字の構成の違いを区別できない
- 境目の打鍵が占める割合と、境目の文字・文節の内側の文字の1文字あたりの距離は、同じ距離の和から導く量で、互いに独立ではない

## 対象のテキスト

『吾輩は猫である』の全文（`docs/kana-chain-comparison.md` の標準のコーパス）を、アプリと同じ経路で評価に渡すテキストにする。
配列ごとに全文の Trace を1回作り、文節の区切りとランダムな区切りを同じ Trace に当てる。範囲を抜き出さないのは、区切りの位置を選ぶ元の集合を広くし、並びの型の多くが複数回出るようにするため。

文節の区切りは、改行を含む原文の全文に BudouX を1回当て、`docs/segment-metrics.md` の写しで評価に渡すテキストの位置へ写す。
語の列は段落ごとに解析した結果を全文のバイト位置へずらしてつなぐ。段落の先頭（改行の直後）に載った区切りの数は、結果の再現の条件に記録する。

## 再現の条件

結果に次を併記する。

- コーパスの版（zipのファイル名とsha256）と、記法を除いた全文のsha256
- 読みの辞書と解析器の名前と版。評価に渡す全文の文字数
- 配列・綴り・`N`・物理配列・指の割り当て・前処理
- 文節の分割器の名前と版。区切りの数。段落の先頭に載った区切りの数
- ランダムな区切りの乱数生成器の名前、種の始まりの値と個数。並びの長さ
- 選ぶ余地が無い区切りの割合の上限
- 判定を出さなかった並びの長さ・配列の数

## 計算量

型ごとの位置は全文の走査1回で集める。種1つあたりの時間は、全文の文字数と区切りの数に比例する。
値の集計は累積和から求めるので、区切り1つあたり一定の時間で済む。主な時間は配列ごとの全文の Trace 生成にかかる。
