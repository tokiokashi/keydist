# 追加する入力方式の候補と、入力原理ごとの表現の範囲

keydistが配列として追加を検討する日本語入力方式の調査と、入力原理ごとに今のモデルで表現できる範囲の分類。
出典に書かれていない項目、読めなかった項目は「確かめられなかった」と書き、推測で埋めない。
分類は、出典を確かめた方式だけを確定とし、確かめていない・一部しか確かめていない方式には「暫定」を付ける。
配列を組み込みに足す・足さないの判断はここに書かない。候補を実装する時は、1配列ずつ別に起こす。

## 分類

入力方式を、今の入力の認識（`src/tester/engine/`）と配列定義（`src/input/layouts/`・`src/input/romaji/`）で扱えるかで3つに分ける。

| 分類 | 意味 |
|---|---|
| 表現できる | 今の面・順次打鍵・同時打鍵・ローマ字規則の組み合わせで書け、入力の認識を通る |
| 新しい意味の表現が要る | 配列定義かモデルに、まだ無い意味（押下時間・文字以外の出力・標準外の物理配列など）を足す必要がある |
| 入力系のモデルが要る | IMEの状態・辞書・漢字への変換を含み、かなを1つずつ打つ前提の外にある |

### 新しい意味の表現が要る入力原理

| 入力原理 | 該当する方式 | 足りないもの |
|---|---|---|
| 押下時間・連打回数で意味が変わる入力 | Home Row Mod、tap dance、Leia配列のスペースとTabの長押しShift、ロゴス配列の素早い連続打鍵と同時押しの判別（QMKのコンボ判定の問題） | 時間を持つ入力の意味。入力の認識が時間の閾値を持たない |
| 押している間だけ別の配列になる状態の遷移 | DvorakJのmodifier | 配列の切り替えを、面の押下とは別に表す意味 |
| 文字以外の出力 | メビウス式のBS・Enter・変換、薙刀式の編集モード | 出力の単位を文字以外へ広げる意味 |
| 標準外の物理配列 | いろは坂（57の単打キー）、Leia配列（3×3ずつの配置）、mato式（24キーと親指4キー） | 物理配列の拡張。組み込みの物理配列は格子の外のキーを左端の3キーだけ持つ。自作の物理配列は `extraKeys` で足せるが、キーidはQWERTYの刻印のまま（`spec/distance-model.md` §3） |
| 親指レイヤーに子音を置く配置 | mato式（暫定） | 英字配列の面で表せるかを確かめていない |

### 入力系のモデルが要る入力原理

| 入力原理 | 該当する方式 | 足りないもの |
|---|---|---|
| IMEの状態に依る入力 | SKKの送り仮名境界、句読点での確定、連文節変換 | IMEの状態を持つモデル |
| 辞書・語句単位の同時打鍵 | ステノワード、ソクタイプ、はやとくん、メジロ式速記の略語 | 語句の辞書と、評価するテキストを語句に分ける前処理 |
| 漢字を直接打つ入力 | T-Code、TUT-Code、G-Code、和音漢直、のにいると（出典を読んでいないので暫定） | 入力の単位を漢字へ広げ、評価するテキストの前処理を方式ごとに変える仕組み |
| 漢字を部品に分けて打つ入力 | 倉頡、葦手（出典を読んでいないので暫定） | 漢字の分解表と、入力の単位の拡張 |

メジロ式速記は、規則で作る部分（子音・母音・追加音の同時打鍵）を「表現できる」、略語の部分を「入力系のモデルが要る」に分ける。
ロゴス配列は、同時押しの集合としては「表現できる」。素早く連続して打った2キーを同時押しと誤判定する問題が出典で課題に挙げられていて、この判別は「新しい意味の表現が要る」の押下時間の行に置く。

### 暫定の分類

次の方式は、出典を確かめていない部分があるので、分類を暫定とする。

- M式: 出典（https://jisx6004.client.jp/layout-gyoudan.html）は専用キーボードで、拡張に親指シフトを使い、クロスシフトしか使わない（?）と書く。親指シフトの扱いを確かめていない
- チーズタイピング: ローマ字規則としては「表現できる」。「ツェージック」の段階は、MS-IMEのローマ字カスタマイズで実装できないと出典に書かれていて、規則を確かめていない
- TRON配列: 出典が「親指2シフト通常(?)」「親指でシフトだが同時打鍵ではないらしい」と疑問形で書く。同手・逆手シフトの扱いを確かめていない
- 片手SKY TOUCH: 親指でスペースキーを打鍵して裏側の文字を出す。押したままの面の切り替えとして「表現できる」見込みだが、定義ファイルを読んでいない
- いろは坂: 57の単打キーを持つ。配列図を読んでいないので、物理配列の要件を確かめていない
- mato式、漢字を直接打つ入力、漢字を部品に分けて打つ入力: 上の表のとおり

### 組み込みに無い配列

各項目の「版」は出典に書かれた事だけを書く。

#### 姫踊子草かな配列

- 出典: https://jisx6004.client.jp/layout-kana.html（文字コードはCP932）
- 版: 記載なし。作者は鈴見咲君高氏
- 入力方式: 親指との同時打鍵（シフトキーは1つ）と、文字キー2つの同時打鍵。親指と文字キーの同時打鍵のほかに、中指と反対の手の文字キーとの同時打鍵、隣り合う2キーの同時打鍵にも文字を割り当てる。例は `d`=け、`f`=と、`d`+`f`=っ、`d`+`k`=ら。3段を使う。配列変更アプリケーション「姫踊子草」「繭姫」に入っている。参考ページはWikipedia
- 清濁・拗音: 確かめられなかった。促音は、例の `d`+`f`=っ だけ読めた
- 設計思想: 親指シフトの形で、シフトキーが1つなのでキーボードを選ばない
- 実装上の注意: 配列変更アプリケーションで使う
- ライセンス: 記載なし
- 分類: 表現できる。親指との同時打鍵と文字キーどうしの同時打鍵は入力の認識を通る。配置の全体は確かめていない

#### 花配列

- 出典: https://jisx6004.client.jp/layout-kana.html（文字コードはCP932）
- 版: 記載なし。作者は冨樫雅文氏。全キーの配置が載っている
- 入力方式: 中指前置シフト。3段を使う。配列変更アプリケーションとローマ字カスタマイズで実装できる。配列変更アプリケーション「菱」の標準配列
- 清濁・拗音・促音: 配置表に濁点・半濁点のキーと、シフト側の ゃ ぃ ぁ ゅ ぅ などがある。規則の説明は記載なし
- 設計思想: 英語やローマ字と似た感覚で打てる。左右の手と各指の使用頻度のバランスと、左右交互打鍵を重視する。特に小指の負担が軽く、その分下段の使用率が高い
- ライセンス: 記載なし
- 分類: 表現できる（前置シフト）

#### TRON配列

- 出典: https://jisx6004.client.jp/layout-kana.html（文字コードはCP932）
- 版: 記載なし。作者はBTRON project
- 入力方式: 出典の表記は「親指2シフト通常(?)」。同手シフトと逆手シフトの配置表がある。3段を使い、カギ括弧は最上段を使う。専用キーボードか配列変更アプリケーションで実装する。出典は「親指でシフトだが同時打鍵ではないらしい」と疑問形で書き、専用キーボードは事実上入手不可なので文字部分だけエミュレートする形になると書く
- 清濁: 濁音は逆手（クロス）シフトで、NICOLAと同じと書かれている
- 拗音・促音: 配置表にシフト側の ゃ ゅ ょ っ があるが、規則の説明は記載なし
- 設計思想: 文字の配置は新JISと共通する部分がある。それ以外は記載なし
- ライセンス: 記載なし
- 分類: 暫定（上の「暫定の分類」）

#### ロゴス配列

- 出典: https://kgnwsknt-chef.hatenablog.com/entry/2026/07/26/093055
- 版: 記事の配列図はv0.2
- 入力方式: 30キー。青と赤の2種類のシフトキーと、その同時押しで文字を出す。シフトキーは左右対称に置く
- 清濁・拗音・促音: 濁音は例として「ぎ」がD+R、「ぜ」がD+Tとある。拗音・促音は記載なし
- 設計思想: 計算配列。独自のスコアで、3gramと同じ手で指が折り返す運指（Redirect）を考える
- 実装上の注意: QMKのコンボ判定を前提に書かれている。素早く2キーを連続で打つと同時押しと誤判定され、別の文字が出る。作者がこの問題を課題に挙げている
- ライセンス: 記載なし
- 分類: 部分に分ける。同時押しの集合は「表現できる」、素早い連続打鍵との判別は「新しい意味の表現が要る」

#### 水草配列

- 出典: https://omonomo.github.io/Mizukusa/
- 版: 記載なし
- 入力方式: 中指と薬指のホームキーを前置シフトに使う。ローマ字定義のカスタマイズで実装でき、Mozcとかわせみで確認済みと書かれている。英数入力はColemakを想定し、QWERTYでも使える
- 清濁・拗音・促音: 水草配列に独自の規則は記載なし。「ji」「sha」などはヘボン式を優先している。「ん」は基本的に `n` 1つで、状況に応じて `nn` を使う。促音は記載なし
- 設計思想: 小指が担当するキーを極力減らす。モード切り替え・文字種変換・ショートカットなしで多くの記号を入力できることを重視する。月配列などと比べて評価している
- 実装上の注意: MS-IME用のレジストリファイルは、誤った情報を登録するとシステムの起動に支障が出うると書かれている。Windows 10 21H2とWindows 11 24H2（MS-IME 15.0）で動作を確認している。「以前のバージョンのMicrosoft IME」を使い、登録前にバックアップを取るよう案内されている
- ライセンス: 明示なし。ファイルの使用は自己責任とある
- 分類: 表現できる（前置シフト）

#### New Stickney

- 出典: https://github.com/esrille/new-stickney
- 版: ページで最新とされるのは第12案
- 入力方式: 3段10列。小書き文字は、「や」などを打った後に濁点キーを打つ後置の小書き化キーで出す。センターシフトは、スペースを単独で押してから文字キーを押す前置でも、押したままにして続けるシフトでも使える
- 清濁: 濁点のつくかなを左手側に、濁点キーを反対側に置く。濁音の具体的な打鍵手順は記載なし
- 拗音: 小書き化キーで出す
- 促音: 記載なし
- 設計思想: スティックニー配列の原則を尊重し、かなをなるべく行ごとにまとめる。日本人が覚えやすいことを重視する
- 実装上の注意: Windows用のAutoHotkeyスクリプトが `NewStickney.ahk`（ANSI用）と `x6004.ahk`（JIS用）で提供される。Windows 10とMicrosoft IMEで動作を確認している。`x6004.ahk` の使用中は変換キーがスペースキーになる。IBus用の日本語入力メソッドもある
- ライセンス: Apache-2.0
- 分類: 表現できる（後置の小書き化キー、スペースの単打と押したままの前置シフト）

#### よだか配列

- 出典: https://semialt.hatenablog.com/entry/2016/05/29/022131
- 版: 記載なし
- 入力方式: 行を示すキーと段を示すキーの同時打鍵。かなの約6割は単打。拗音は3キーの同時打鍵。シフトとキーボードの切り替えは使わない
- 清濁・促音: 記載なし
- 撥音: 「かん」「しん」「つん」のように、かなと撥音を2キーの同時打鍵1動作で出す
- 設計思想: 50音の並びに基づいて規則的に作り、覚えやすさを重視する。数字段を使わず、現代日本語のカナは上段と中段だけで1動作で出せる
- 実装上の注意: 同時押しにはキー入れ替えソフトが要る。WindowsはDvorakJ、MacはKarabinerの設定ファイルがある。連続入力の効率はあまり考えられておらず、出典が欠点に挙げている
- ライセンス: 記載なし（GitHubのリポジトリへのリンクはあるが、ライセンスの説明は読めなかった）
- 分類: 表現できる

#### いろは坂

- 出典: https://menmentsu.hateblo.jp/entry/2019/12/22/030424
- 版: 記載なし
- 入力方式: かな入力。57の単打キーを持つ。出典の本文には物理配列の図が無く、キーの配置は確かめられなかった。4段でも使えると書かれている
- 清濁・拗音・促音: 確かめられなかった
- 設計思想: シフトにほとんど頼らない。JISかな配列より打鍵数を約13%減らすことを目指す
- 実装上の注意: 記載なし
- ライセンス: 記載なし
- 分類: 暫定（上の「暫定の分類」）。物理配列が標準外なら「新しい意味の表現が要る」

#### つばめ配列

- 出典: https://jisx6004.client.jp/layout-gyoudan.html（文字コードはCP932）
- 版: 記載なし。作者はmikado氏
- 入力方式: 行段系。中段だけを使う。シフトはしない。拗音は間にスペースを挟む3打で、数字も中段の2打で入力する。配列変更アプリケーション「菱」用の定義ファイルがある
- 連母音拡張・撥音拡張: 無し
- 清濁・促音: 確かめられなかった
- 設計思想: 確かめられなかった
- ライセンス: 記載なし
- 分類: 表現できる（行・スペース・段の3打）。行と段の具体の割り当ては確かめていない

#### SKY・片手SKY TOUCH

- 出典: https://skytouch.stars.ne.jp/（文字コードはCP932）、https://jisx6004.client.jp/layout-gyoudan.html
- 版: SKY配列を用いた入力方式の名前がSKY TOUCH。サイトの更新は2024年9月（プログラマブルキーボードへの適用）。パンフレットは2014年版。SKY配列の作者は白鳥嘉勇氏・小橋史彦氏（NTT）ら。SKY!・SKY+・SKY++・SKY#・SKYuの派生がある
- 入力方式: 3段10列の30キー。シフト操作は無い（シフトを使う拡張もある）。左に子音、右に母音を置く。連母音（UU・AI・OU・EI）と撥音（UN・AN・ON・IN・EN）のキーを持つ。母音は5つ。MS-IME・ATOKでは実装できない。配列変更ソフトはかんな・DvorakJで使う
- 片手SKY TOUCH: 3段5列の片手キーボード。DvorakJで、親指でスペースキーを打鍵して裏側の文字を出す形で実現できると書かれている。定義ファイルは右手用・左手用がある
- 清濁・拗音・促音: 記載なし
- 設計思想: ホーム段の使用率69%（QWERTYは29%）、左右交互打鍵率93%（同73%）、かな1文字に要する打鍵数1.35（QWERTYの約10%減）をサイトが示す
- ライセンス: 記載なし
- 分類: SKYは表現できる（ローマ字規則）。片手SKY TOUCHは暫定

#### M式・Km式

- 出典: https://jisx6004.client.jp/layout-gyoudan.html、https://www.asahi-net.or.jp/~dy5h-kdm/end.htm（主題はKodamak英字配列）
- M式: 作者は森田正典氏（NEC）。専用キーボードで実装し、シフトは拡張で使う。連母音拡張・撥音拡張・拗音拡張がある。左に母音、右に子音を置く。連母音などは親指シフトで出し、クロスシフトしか使わない（?）と出典が書く。特許が成立している。MS-IME・ATOKでは実装できない

#### DvorakJP・ACT・JLOD

#### あかならべ

#### ベルダ配列

#### メジロ式速記

- 出典: https://github.com/JEEBIS27/Plover_Mejiro
- 版: ページの見出しはv2.8.4。導入例のwheel名は `mejiro-2.8.1` で、見出しの版と一致しない
- 入力方式: 子音・母音・追加音の組み合わせ。片手で1音節、両手で2音節を1ストロークで出す。母音はあ段が `A`、い段が `I`、う段が `U`。追加音は ん=`n`、つ=`t`、く=`k`、ち=`nt`、き=`nk`、っ=`tk`、ー=`ntk`。二重母音・助詞・取り消し（`-U`）・繰り返し（`#`）・マクロ・略語・タイピングモード・片手モードも定義されている。対応するキーボードは、メジロ式専用のMejiro31、親指シフト用のキーボード、スペースバーが2つあるキーボード

- 分類: 部分に分ける。規則で作る部分は「表現できる」、略語は「入力系のモデルが要る」
