# 追加する入力方式の候補と、入力原理ごとの表現の範囲

keydistが配列として追加を検討する日本語入力方式の調査と、入力原理ごとに今のモデルで表現できる範囲の分類。
出典は2026-11-11に読んだ。読めなかった項目は「確かめられなかった」と書き、推測で埋めない。出典が文字化けして読めなかった項目も同じ扱いにする。
配列を組み込みに足す・足さないの判断はここに書かない。候補を実装する時は、1配列ずつ別に起こす。

## 分類

入力方式を、今の入力の認識（`src/tester/engine/`）と配列定義（`src/input/layouts/`・`src/input/romaji/`）で扱えるかで3つに分ける。

| 分類 | 意味 |
|---|---|
| 表現できる | 今の面・順次打鍵・同時打鍵・ローマ字規則の組み合わせで書け、入力の認識を通る |
| 新しい意味の表現が要る | 配列定義かモデルに、まだ無い意味（押下時間・文字以外の出力・標準外の物理配列など）を足す必要がある |
| 入力系のモデルが要る | IMEの状態・辞書・漢字への変換を含み、かなを1つずつ打つ前提の外にある |

### 新しい意味の表現が要る入力原理

| 入力原理 | 該当する方式 | 足りないもの |
|---|---|---|
| 押下時間・連打回数で意味が変わる入力 | Home Row Mod、tap dance、Leia配列のスペースとTabの長押しShift | 時間を持つ入力の意味。入力の認識が時間の閾値を持たない |
| 押している間だけ別の配列になる状態の遷移 | DvorakJのmodifier | 配列の切り替えを、面の押下とは別に表す意味 |
| 文字以外の出力 | メビウス式のBS・Enter・変換、薙刀式の編集モード | 出力の単位を文字以外へ広げる意味 |
| 文脈で同じキーを別の指で押す運指 | （該当する配列を確かめられなかった） | 運指を前後のキーで決める規則 |
| 標準外の物理配列 | いろは坂（57の単打キー）、Leia配列（3×3ずつの配置）、mato式（24キーと親指4キー） | 物理配列の拡張。物理キーのidがQWERTYの刻印を使っているので、格子の外のキーは左端の3つしか置けない |
| 親指レイヤーに子音を置く配置 | mato式 | 英字配列の面で表せるかを確かめていない。暫定でここに置く |

### 入力系のモデルが要る入力原理

| 入力原理 | 該当する方式 | 足りないもの |
|---|---|---|
| IMEの状態に依る入力 | SKKの送り仮名境界、句読点での確定、連文節変換 | IMEの状態を持つモデル |
| 辞書・語句単位の同時打鍵 | ステノワード、ソクタイプ、はやとくん、メジロ式速記の略語 | 語句の辞書と、評価するテキストを語句に分ける前処理 |
| 漢字を直接打つ入力 | T-Code、TUT-Code、G-Code、和音漢直、のにいると | 入力の単位を漢字へ広げ、評価するテキストの前処理を方式ごとに変える仕組み |
| 漢字を部品に分けて打つ入力 | 倉頡、葦手 | 漢字の分解表と、入力の単位の拡張 |

メジロ式速記は、規則で作る部分（子音・母音・追加音の同時打鍵）を「表現できる」、略語の部分を「入力系のモデルが要る」に分ける。
ロゴス配列は、同時押しの集合として「表現できる」が、素早く連続して打った2キーを同時押しと誤判定する問題が出典で課題に挙げられている。入力の認識は時間の閾値を持たないので、この誤判定は再現しない。

### 組み込みに無い配列

各項目の「版」は出典に書かれた事だけを書く。

#### 姫踊子草かな配列

- 出典: https://jisx6004.client.jp/layout-kana.html（文字化けが多く、判読できた範囲）
- 版: 確かめられなかった
- 入力方式: 親指シフトに近い。親指1キーとの同時打鍵と、2キーの同時打鍵を組み合わせる。3段を使う。文字キーどうしの同時打鍵の内訳（隣接2キー、反対側の文字キー）は、出典から確かめられなかった
- 清濁・拗音・促音: 確かめられなかった
- 設計思想: 2キーの同時打鍵の組み合わせで多くの文字を置く
- 実装上の注意: 配列変更アプリケーションで使える。親指シフト系の仕組みなので、キーボードを選ばない
- ライセンス: 記載なし

#### 花配列

- 出典: 姫踊子草かな配列と同じページ
- 版: 確かめられなかった
- 入力方式: 中指の前置シフト。3段を使う
- 清濁・拗音・促音: 確かめられなかった
- 設計思想: 指ごとの使用頻度と左右の打ち分けのバランスを考え、小指の負担を軽くする
- 実装上の注意: 配列変更アプリケーションとローマ字のカスタマイズで実現する
- ライセンス: 記載なし

#### TRON配列

- 出典: 確かめられなかった（読める出典を持っていない）
- そのほかの項目: 確かめられなかった

#### ロゴス配列

- 出典: https://kgnwsknt-chef.hatenablog.com/entry/2026/07/26/093055
- 版: 記事の配列図はv0.2
- 入力方式: 30キー。青と赤の2種類のシフトキーと、その同時押しで文字を出す。シフトキーは左右対称に置く
- 清濁・拗音・促音: 濁音は例として「ぎ」がD+R、「ぜ」がD+Tとある。拗音・促音は記載なし
- 設計思想: 計算配列。独自のスコアで、3gramと同じ手で指が折り返す運指（Redirect）を考える
- 実装上の注意: QMKのコンボ判定を前提に書かれている。素早く2キーを連続で打つと同時押しと誤判定され、別の文字が出る。作者がこの問題を課題に挙げている
- ライセンス: 記載なし

#### 水草配列

- 出典: https://omonomo.github.io/Mizukusa/
- 版: 記載なし
- 入力方式: 中指と薬指のホームキーを前置シフトに使う。ローマ字定義のカスタマイズで実装でき、Mozcとかわせみで確認済みと書かれている。英数入力はColemakを想定し、QWERTYでも使える
- 清濁・拗音・促音: 水草配列に独自の規則は記載なし。「ji」「sha」などはヘボン式を優先している。「ん」は基本的に `n` 1つで、状況に応じて `nn` を使う。促音は記載なし
- 設計思想: 小指が担当するキーを極力減らす。モード切り替え・文字種変換・ショートカットなしで多くの記号を入力できることを重視する。月配列などと比べて評価している
- 実装上の注意: MS-IME用のレジストリファイルは、誤った情報を登録するとシステムの起動に支障が出うると書かれている。Windows 10 21H2とWindows 11 24H2（MS-IME 15.0）で動作を確認している。「以前のバージョンのMicrosoft IME」を使い、登録前にバックアップを取るよう案内されている
- ライセンス: 明示なし。ファイルの使用は自己責任とある

#### New Stickney

- 出典: https://github.com/esrille/new-stickney
- 版: ページで最新とされるのは第12案
- 入力方式: 3段10列。小書き文字は、「や」などを打った後に濁点キーを打つ後置の小書き化キーで出す。センターシフトは、スペースを単独で押してから文字キーを押す前置でも、押したままにして続けるシフトでも使える
- 清濁: 濁点のつくかなを左手側に、濁点キーを反対側に置く。濁音の具体的な打鍵手順は記載なし
- 拗音: 小書き化キーで出す
- 促音: 記載なし
- 設計思想: スティックニー配列の原則を尊重し、かなをなるべく行ごとにまとめる。日本人が覚えやすいことを重視する
- 実装上の注意: Windows用のAutoHotkeyスクリプトが `NewStickney.ahk`（ANSI用）と `x6004.ahk`（JIS用）で提供される。Windows 10とMicrosoft IMEで動作を確認している。`x6004.ahk` の使用中は変換キーがスペースキーになる。IBus用の日本語入力メソッドもある
- ライセンス: Apache-2.0

#### よだか配列

- 出典: https://semialt.hatenablog.com/entry/2016/05/29/022131
- 版: 記載なし
- 入力方式: 行を示すキーと段を示すキーの同時打鍵。かなの約6割は単打。拗音は3キーの同時打鍵。シフトとキーボードの切り替えは使わない
- 清濁・促音: 記載なし
- 撥音: 「かん」「しん」「つん」のように、かなと撥音を2キーの同時打鍵1動作で出す
- 設計思想: 50音の並びに基づいて規則的に作り、覚えやすさを重視する。数字段を使わず、現代日本語のカナは上段と中段だけで1動作で出せる
- 実装上の注意: 同時押しにはキー入れ替えソフトが要る。WindowsはDvorakJ、MacはKarabinerの設定ファイルがある。連続入力の効率はあまり考えられておらず、出典が欠点に挙げている
- ライセンス: 記載なし（GitHubのリポジトリへのリンクはあるが、ライセンスの説明は読めなかった）

#### いろは坂

- 出典: https://menmentsu.hateblo.jp/entry/2019/12/22/030424
- 版: 記載なし
- 入力方式: かな入力。57の単打キーを持つ。出典の本文には物理配列の図が無く、キーの配置は確かめられなかった。4段でも使えると書かれている
- 清濁・拗音・促音: 確かめられなかった
- 設計思想: シフトにほとんど頼らない。JISかな配列より打鍵数を約13%減らすことを目指す
- 実装上の注意: 記載なし
- ライセンス: 記載なし

#### つばめ配列

- 出典: https://jisx6004.client.jp/layout-gyoudan.html（文字化けが多く、判読できた範囲）
- 版: 記載なし。作者はmikado氏と読めた
- 入力方式: 中段・下段を主に使い、シフトキーは使わない。一部のかなの入力にスペースを挟む。1打目で行、2打目で段を指定する点と、拗音が3打である点は、出典から確かめられなかった
- 清濁・拗音・促音: 確かめられなかった
- 設計思想: 確かめられなかった
- 実装上の注意: 専用の設定ファイルが用意されている。対象のソフトは確かめられなかった
- ライセンス: 記載なし

#### SKY・片手SKY TOUCH

- 出典: https://skytouch.stars.ne.jp/（文字化けが多く、判読できた範囲）
- 版: 2014年の新版パンフレット、2017年（2017.3）の片手用配列の改訂、2011年のDvorakJ用の図が見つかった
- 入力方式: 両手用と片手用がある。主要な配列は30キー前後（3段×10列）と読めた。片手用はシフトに右手の上部のキーなどを使う
- 清濁・拗音・促音: 記載なし。連母音と撥音は「Ai ei」「Ou uu」「A an」「O on」の組み合わせを特定のキーへ置く改訂が示されている。左に子音、右に母音を置く点は、出典から確かめられなかった
- 設計思想: 日本語の構造・出現頻度・入力の知見から最適な配列を作る
- 実装上の注意: DvorakJなどの配列変更ソフトで使う。片手用はシフトの認識時間を短く（2秒以内など）設定する
- ライセンス: 記載なし

#### M式・Km式

- 出典: https://www.asahi-net.or.jp/~dy5h-kdm/end.htm（主題はKodamak英字配列）
- M式: ローマ字入力の方式として挙げられている。版・親指シフトの有無・連母音と撥音と拗音の拡張は確かめられなかった。左に母音、右に子音を置くことも、この出典では確かめられなかった
- Km式: 出典はKodamak英字配列の別名として触れている。き・く・ち・つ・っ・んを単打で持つ点は確かめられなかった
- Kodamak配列の設計: 母音を右側に並べて二重母音を打ちやすくする、指使いを変えない、長音符を最上段から1段下げる、Colemakを着想の元にして問題のある部分だけを変える
- 実装上の注意: パッチソフトは配布していない
- ライセンス: All rights reserved（著作権表示のみで、利用条件は記載なし）

#### DvorakJP・ACT・JLOD

- 出典: https://github.com/shinespark/dvorakjp-roman-table
- DvorakJP: 版はv1.0正式版のローマ字テーブル。このリポジトリは本家と完全に同じではなく「DvorakJP Prime」と名付けられている。本家のサイトは404
- ACT・JLOD: この出典には記載なし。確かめられなかった
- 入力方式: Dvorak配列の左手のホームに母音、右手に子音を置く。か行を右手の `c*` でも入力できる。拗音は `y` の代わりに `h` か `n` でも入力できる
- 清濁・拗音・促音: 清濁に固有の規則は記載なし。ざ行はGoogle日本語入力の `z*` の記号入力と競合するので、`z` を `;` に変えている。拗音は `ch`・`tw` などにも二重母音の拡張を足している。促音は、DvorakJP 0.2βの `p` キーの `uu` を復活させている
- 設計思想: 交互打鍵のしやすさを重視する。二重母音の拡張と撥音の拡張で、同じ手での連続した母音の入力を減らす
- 実装上の注意: Google日本語入力の既定のテーブルを元に `t'u` 系の入力を削除している。絵文字に対応した版はazooKeyで使えない
- ライセンス: MIT License

#### あかならべ

- 出典: https://github.com/toriwasa/akanarabe
- 版: 記載なし
- 入力方式: ローマ字入力を改良したかな入力。子音キーと母音キーの組み合わせで出す。単打キー・拡張母音キー（拗音・長音）・外来音の子音のレイヤー（切り替えキーは `A`）・小書きと記号のレイヤー（切り替えキーは `C`）がある。3段×10キーの30キー。Google日本語入力のローマ字テーブルとして実装されている
- 清濁: 濁音・半濁音は各清音の上下に置く。が行・ざ行・だ行は上段、ば行は下段
- 拗音: 拡張母音キー「ゃゅょ」を使い、「きゅ」は `K` + `yu`。「や・ゆ・よ」は単打
- 促音: 子音キーの連打。単打の「っ」もある
- 設計思想: 頻出する子音をホームの近くに置き、「ai」「ei」「ou」などの二重母音を打ちやすくする。QWERTYの配置をできるだけ残して学習コストを下げる
- 実装上の注意: `akanarabe_jis_us.txt` はJISとUSの両方に対応する。`akanarabe_corvus_skk.txt` はCorvusSKK用。`Q` キーは使っていない
- ライセンス: CC BY 4.0

#### せおと配列の出典

組み込みにある。出典（https://note.com/firstyear_dev/n/ne4aedaad09b2）の `c=k` `x=ya` `j=yu` `q=yo` のローマ字拡張と、子音の連続で語句を出す短縮は、組み込みのローマ字規則が持つかを確かめていない。

#### mato式

- 出典: https://note.com/mato_kb/n/nf57efe5d6ca0
- 版: 記載なし
- 入力方式: 日本語ローマ字入力向け。左手に子音、右手に母音とその他の機能を置く2段の行段分離型。24キーで、親指担当に左右2キーずつ計4キーが要る
- 清濁・拗音・促音: 記載なし。撥音は、レイヤー1を変えると撥音拡張を実装できる。デフォルトのレイヤーとレイヤー1の切り替えを厳密に行う必要がある
- 設計思想: 各指の担当キー数を減らして指の移動距離を抑える。キー数が少なく小型のキーボードを作れる。覚えやすさを重視する
- 実装上の注意: 修飾キーを縦2キーのコンボに割り当てるので、ロウスタッガード配列に合わない。Shiftは小指のコンボキーに割り当てる。使わないキーが出るので、ホットスワップ対応のキーボードが望ましい
- ライセンス: 記載なし

#### ベルダ配列

- 出典: https://itouhiro.hatenablog.com/entry/20080512
- 版: 記載なし。2008年5月22日にファイルを更新したと書かれている
- 入力方式: ポケベル入力（ベル打ち）のキー配置に互換する。主に片手で使い、数字キー1〜9・0・`*` に対応するPCのキーを使って2打鍵で1文字を出す。両手でも使え、左手で母音、右手で子音を担当する。MS-IMEのローマ字設定への追加と、ATOKのSTYファイルで使う
- 清濁: 濁点は直前の文字に続けて `G` + `S` か `Z`、半濁点は `G` + `D` か `T` を打つ（両手用は `N` `P` も使う）
- 拗音: 1打目に `A`、2打目に該当のキー
- 促音: 拗音と同じく `A` を使う
- 設計思想: ポケベル入力との互換を重視し、効率より互換を優先する。頻出の文字が打ちやすい位置に無いことがある
- 実装上の注意: MS-IMEは子音を重ねると「っ」の代わりに「・」が出る。ATOKは対策していない。片手の入力は1打鍵でも押し間違えると以降の入力がずれる
- ライセンス: 記載なし

#### Leia配列

- 出典: https://tokyotanuki.jp/keyboards/leia_layout.htm
- 版: ver1（2020年10月の最終修正版）とver2。DVORAK_TTT配列を改定した配列
- 入力方式: 1キーに1文字を置き、レイヤーも同時押しも使わない。ローマ字ルールを改変して複合母音（`AI` など）と撥音（`AN` など）に対応する。macOSでは「かわせみ2」で実装している。スペースとTabは長押しでShiftを兼ねる
- キー数と物理配列: ver2は左右3×3に主要文字を置き、1キーの空白がある。格子配列か縦ずれ配列に向く。全体のキー数は記載なし
- 清濁・拗音・促音: 記載なし
- 設計思想: 日本語入力で使いやすいことを目標にする。1983年の日本語キーボードM式の思想を部分的に取り入れる。左手に母音、右手に子音を置く。「OU」「AI」「EI」「YOU」を打ちやすい配置にする
- 実装上の注意: ver2ではAZIKを取り除いたが、子音2文字をかな2文字にする「特殊拡張」は一部残している。矢印キーは文字キーの中に食い込ませて置く。数字と記号は好みで置く前提
- ライセンス: 記載なし

#### ヤウ配列・ニャウ配列・カナガワ配列

- 出典: https://yau-keyboard.webnode.jp/（ニャウ配列とカナガワ配列はこのページに記載なし。確かめられなかった）
- 版: 定義ファイル名に「ヤウ配列10.2」とある
- 入力方式: 行段入力。行キーと段キーを組み合わせる。段キーとそのほかのキーは押すとそのまま入力される。あ段省略は、行キーのあ段の文字の後に段キーが続かない時に、あ段の入力を省く。「カラオケ」はあ段省略ありで6打になる
- 清濁・拗音・促音: ば行のぁ〜ぉ段で「ゔぁ」「ゔぃ」「ゔ」「ゔぇ」「ゔぉ」を出す。ぱ行は撥音の拡張に使う。だ行のゅ段は「でゅ」、は行のぅ段は「ふゅ」になる。た行のぃ段とぇ段は「てぃ」「ちぇ」になる。「つぃ」「つぇ」は「つ」の後に「ぃ」「ぇ」を入力する。促音は記載なし
- 設計思想: かなを使った行段系の配列としてQWERTYと共存する。簡単で覚えやすく、できるだけ速く打てることを重視する
- 実装上の注意: Google日本語入力のローマ字テーブルのカスタマイズで使う定義ファイルがある。行キーをカタカナで入力する版もあり、確定するとひらがなになる
- ライセンス: 定義ファイルは再配布と改造・改良が認められていると書かれている。ライセンスの名前は記載なし

#### ステノワード

- 出典: https://www.speed-wp.co.jp/speed-wp-stenoword/
- 入力方式: 10個の文字キーの同時打鍵。右側5個に母音、左側5個に子音を割り当てる。「あ」と「い」を同時に押すと「あい」が1アクションで出る。よく使う語句のパターンも同時打鍵で出せる
- 拗音などの扱い: 記載なし
- 設計思想: 指を上下左右に動かさず、ホームに置いたまま打てる。1アクションで2〜20文字ほど出せる
- ライセンス・利用条件: 記載なし

#### ソクタイプ・はやとくん

- 出典: https://www.hayatokun.com/cont11/24.html
- 入力方式: 複数のキーを組み合わせ、言葉のまとまり単位で入力する。20個のキーを使い、両手用の対称な部分と親指用の部分がある。打ち方は「基本」（音）、「略語」（定型の言葉）、「きまり」（言葉の一部を省く約束）の3種類。略語は必須が500〜600、任意が500
- 設計思想: 指の形に合わせてキーを前後にずらして高低をつけ、指の動きを最小にして疲れにくくする。1950年から1998年まで速記者の養成に使われた
- ライセンス・利用条件: 記載なし

#### メジロ式速記

- 出典: https://github.com/JEEBIS27/Plover_Mejiro
- 版: ページの見出しはv2.8.4。導入例のwheel名は `mejiro-2.8.1` で、見出しの版と一致しない
- 入力方式: 子音・母音・追加音の組み合わせ。片手で1音節、両手で2音節を1ストロークで出す。母音はあ段が `A`、い段が `I`、う段が `U`。追加音は ん=`n`、つ=`t`、く=`k`、ち=`nt`、き=`nk`、っ=`tk`、ー=`ntk`。二重母音・助詞・取り消し（`-U`）・繰り返し（`#`）・マクロ・略語・タイピングモード・片手モードも定義されている。対応するキーボードは、メジロ式専用のMejiro31、親指シフト用のキーボード、スペースバーが2つあるキーボード
- 清濁: `N` との同時押しで濁音になる。例は `K` + `N` が「が」、`K` + `N` + `I` が「ぎ」
- 拗音: 独立した規則は見当たらない。や段・ゆ段・よ段は母音キー `YA`・`YU`・`YAU` で出す
- 促音: 追加音 `tk`。タイピングモードでは、末尾の促音を保留して次の出力の先頭に含める
- 設計思想: 直観的な子音・母音・追加音の組み合わせで、両手の10本指を使う効率的な日本語入力を目指す
- 実装上の注意: 実行にはPloverが要る。Windows 64bit用のビルド済みwheelはRustエンジンのDLLを含み、Windows 32bitとARM64では使えない。更新後はMejiroパッケージを再インストールしてPloverを再起動する。ユーザー略語は `Mejiro/engine.py` の `USERS_MAP` か `mejiro_users.json` に登録する。undoは未確定のかな入力を前提にする
- ライセンス: GPL-3.0
