# かな3文字までの並びの統計で説明できるかの比べ方

文章の中で指標が局所的に大きくなる箇所や、変動の大きさが、かな3文字までの並びの統計で説明できるかを調べる定義。
元のテキスト、かなの2次マルコフ連鎖の生成文、対照テキストを同じ指標で評価し、元のテキストの値が生成文の中で何番目かを出す。
実装は `src/interpretation/ngram-table.ts`（数え方）、`src/interpretation/markov-text.ts`（生成文）、`src/interpretation/chain-comparison.ts`（比べ方）、
実行は `scripts/kana-chain-comparison.ts`（結果をMarkdownの表で出す）。画面には出さない。
距離モデルの値（`spec/distance-model.md`）は変えない。区間の集計は `docs/span-metrics.md` の分子と分母、ステップの帰属の規則をそのまま使う。

## 言葉

- **文字の列**: 評価に渡すテキスト（読みに直し、`spec/distance-model.md` §4.6 の前処理を通した後）のコードポイントの列。句読点・長音・打鍵できない文字も、評価に渡すとおりに含める。
  「かな3文字の並び」は、この列で連続する3コードポイントを指す
- **n-gramの表**: 次数 `r` の表は、連続する `r + 1` 文字の並びと出現回数を持つ。0次は1文字、1次は2文字、2次は3文字。表の形は次数で一般化してあり、2次までを作る
- **連鎖**: 2次の表から作る、直前の2文字（文脈）から次の1文字への出現回数。文脈ごとに、続く文字の種類と出現回数を持つ

## 連鎖の表

評価に渡すテキストは、前処理の3〜4段目の結果が配列で変わりうる（`,` `.` を直接持つ配列では半角のまま打ち、片仮名を見出しとして持つ配列では書き換えない）。
そのため連鎖は、配列ごとに、その配列の評価に渡すテキストの全体から作る。生成文は、そのまま評価に渡せる文字列になる。

比べるテキストを全体から抜き出した範囲 `[a, b)`（評価に渡す全体の文字列の位置）は、連鎖から除く。
連鎖に使う表は「全体の表 − 範囲の文字を1つでも含む並びの表」で、範囲の前 `[0, a)` と後 `[b, 末尾)` を別々に数えて足した表と一致する。

- 次数 `r` の表で引く並びは、開始位置が `[a − r, b)` にある並び（文字列 `[a − r, b + r)` の中の並びを端で切ったもの）。2次なら `[a − 2, b + 2)` の3文字組にあたる
- 範囲の前と後をつないだ所に、新しい並びは作らない
- 抜き出した範囲を含めると、連鎖が元のテキストに合わせて作られ、元のテキストが生成文より連鎖の典型に近くなる。範囲だけから作ると統計が薄く、生成文が元の文の写しに近づく。このため、全体から範囲を除いて作る

## 生成文

元と同じ文字数で作る。最初の2文字は元のテキストの最初の2文字を使い、3文字目から1文字ずつ続ける。3文字目以降の、次の文字を決める操作1回を1段と数える。

1. 文脈（直前の2文字）に続く文字があれば、出現回数の重みで1つ引く
2. 無ければ、直前の1文字から始まる文脈を、文脈の出現回数の重みで1つ引き、その2文字目を続ける。直前の文字と続く文字の組は連鎖の元の列に出た組になるので、小書き文字や促音が孤立しない
3. それも無ければ、文脈を全体から出現回数の重みで1つ引き、その2文字を続ける（文字数を超える分は切る）

候補は文字の昇順に並べてから重みで引くので、表の作り方によらず、同じ乱数から同じ候補を引く。乱数は mulberry32（`interpretation/prng.ts`）。種は、始まりの値 `s` から `s, s+1, …, s+19` の20個で固定する。
同じ表・始まり・文字数・種からは同じ生成文が出る。

統計が足りているかの量は、生成文20個を合わせた全部の段で数える。

| 量 | 定義 |
|---|---|
| 段の数 | 生成した段の総数（手順2と3で続けた段を含む） |
| 候補が1つの段 | 手順1で、文脈に続く文字の種類が1つだけだった段 |
| 候補が1つの割合 | 候補が1つの段 / 段の数 |
| 直前の1文字から続けた回数 | 手順2で続けた段の数 |
| 全体から引いて続けた回数 | 手順3で続けた段の数 |

生成文が元の文の写しに近づく現象は、候補が1つしか無い段が多いことに表れる。割合が上限（10%）を超える配列×範囲では、判定を出さず、割合だけを示す。
上限は順位を見る前に固定した値で、結果に合わせて動かさない。

## 判定の量と順位

見る量は、1文字あたりの距離 `perCharUnits` [u] の1つだけ。

- テキストを先頭から重ならない50文字の区間に切り、区間ごとの値（`docs/span-metrics.md` の範囲の値）の90%点を取る。補間しない最近順位で、小さい方から `⌈0.9n⌉` 番目の値（`interpretation/segments.ts` の `quantileNearestRank`）
- 末尾の50文字に満たない区間は、90%点・中央値・最大から除く。除かない分割では、区間の分子と分母を足すとテキスト全体の値に戻る
- 区間の長さ50文字は、Run Chartの集計窓の既定と同じ値で固定する。区間の数は文字数だけで決まるので、元のテキストと生成文で同じになる
- 上側の分位点を見るのは、局所的に大きくなる箇所を調べるため。区間の値の中央値・最大は、表に並べるだけで判定に使わない

元のテキストの90%点が、生成文20個と合わせた21個の中で何番目かを出す（`rankAmong`。`docs/segment-metrics.md`「文節の値の順位」と同じ規則）。

- 同じ値がある時は、順位を幅で示す。値が同じかは、相対誤差1e-12以内で判定する
- 元の値が生成文20個のどれよりも厳密に大きいか小さい時だけを端とし、その時を「かな3文字までの並びでは説明できなかった」とする。同点があれば端に数えない
- 端でない時は「説明できなかったとは言えない」とする。「説明できた」とは書かない。範囲の中に入ったことは、説明できたことの根拠にならない（生成文の値のばらつきが大きいほど入りやすい）
- 元のテキストが生成文と入れ替えても区別できないなら、元の値が端に来る確率は最大で2/21（約9.5%）。ただし、元のテキストは連鎖の標本ではなく実際の文で、作品の中で文体が変わる箇所もある。
  生成文は元の最初の2文字を使い、候補が無い文脈では上の規則で続けるので、連鎖の分布からも少しずれる。端の順位は統計的な有意と書かない
- 判定は、配列×範囲ごとの別々の判定。複数の配列や範囲をまとめた結論は出さない。配列の優劣の判定・順位・合成スコアは出さない

判定を出すのは、標準のコーパスから抜き出したテキストだけ。利用者のテキストでも値は並べて出せるが、連鎖をコーパスから作るので、端の順位は「テキストとコーパスの違い」も含んでしまう。そのため利用者のテキストには判定を出さない。

## 対照テキスト

順序破壊と一様ランダム（`interpretation/control-texts.ts`）を、生成文と同じ種 `s` から `s+19` の20個ずつ作り、同じ指標の最小〜最大を表に並べる。判定には使わない。

## コーパスの範囲

スクリプトは、標準のコーパス（青空文庫『吾輩は猫である』の全文。取得と記法の除去は `scripts/generate-neko-sample.ts` と同じ）から範囲を抜き出す。

1. 原文を段落（改行）ごとに読みに直してつなぎ、全体の文字列を作る。読みは辞書（IPADIC）と解析器で決まる
2. 範囲は原文の上で、段落の境目から選ぶ。評価に渡すテキストの文字数が2000を超える最初の段落の境目までを取る
3. 範囲の候補から、既定の日本語サンプル（第一章の先頭）と重なるものを除き、種で選んだ開始位置から取る。範囲どうしは重ならない。乱数はmulberry32
4. 範囲の原文をアプリと同じ経路（形態素解析 → 漢字を含む語を読みに置き換え）で読みに直したテキストが、全体の文字列のうち範囲に当たる部分と一致することを確かめる。違えば止まる。範囲の位置は全体の文字列の文字位置で持つ
5. 前処理の3段目（半角の `,` `.` の書き換え）は、1文字を1文字に直すだけで文字数を変えない。範囲の位置は全配列で共有し、連鎖の中身だけを配列ごとに作る。配列ごとの評価に渡す全体の文字数と、範囲の評価に渡すテキストが全体の同じ部分に一致することは、スクリプトが配列ごとに確かめる
6. 連鎖の表は同梱せず、実行のたびにコーパスから作る

## 再現の条件

結果に次を併記する。

- コーパスの版（zipのファイル名とsha256）と、記法を除いた全文のsha256
- 範囲の位置、範囲を選んだ乱数生成器の名前と種
- 読みの辞書と解析器の名前と版
- 前処理（仕様 §4.6）、配列・綴り・`N`・物理配列・指の割り当て
- 連鎖の次数、生成の規則、生成文と対照テキストの乱数生成器の名前と種の始まりの値
- 区間の長さ、分位点の方法
- 候補が1つしか無かった段の割合、続けた回数
- 文節の区切りの分割器の名前と版（`docs/segment-metrics.md`）

## 計算量

表を作る時間は文字数に比例する。範囲を除くのは、範囲と重なる並びだけを数えて引くので、全体を数え直さない。
評価は、1つの範囲×配列あたり、元のテキスト・生成文20個・対照テキスト40個の約61回で、主な時間はこの評価と、コーパス全文の読みへの変換にかかる。
