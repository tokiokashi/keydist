# 区切りごとの指標と、文節の区切りの判定の量

Run Chart（`docs/span-metrics.md`）に区切りを重ね、区切り方（文節・固定長・ランダム）で区間ごとの指標と区切りの前後の指標を比べる定義。
実装は `src/interpretation/segments.ts`（区切りの作成と集計）、`src/input/text/segmentation.ts`（区切りを評価に渡すテキストへ写す処理）。
距離モデルの値（`spec/distance-model.md`）は変えない。区間の集計は `docs/span-metrics.md` の分子と分母、ステップの帰属の規則をそのまま使う。

## 区切り

区切りは、評価に渡したテキストの文字位置の昇順の列（0とテキストの長さを含まない）。位置 `b` の区切りは、文字 `b − 1` と文字 `b` の間を指す。
区間は `[0, b₁)`, `[b₁, b₂)`, …, `[bₖ, 末尾)`。長さ0の区間は作らない。区間はテキスト全体を重ならずに覆うので、
区間ごとの分子と分母を足すとテキスト全体の値に戻る。

### 文節の区切り

分割器は BudouX（`budoux` 0.10.0、日本語のモデル）。次の順に、評価に渡すテキストの文字位置へ写す。

1. 分割器を、器が漢字を読みに直す前に持っている原文に当てる（かなに直した後の文には当てない）。区切りは原文の位置で得る。
2. 漢字を読みに直した語（`ReadingToken`）の途中に区切りが来たら、その語の後ろの境目へ寄せる。1語の読みを2つの区間に分けない。
   語の間の文字や、読みに直さない語の途中は、そのまま写す。
3. 利用者の読みの直しを当てた後の読みのテキストの文字数で位置を数える。直しで読みの文字数が変わっても、区切りは語の境目に載る。
4. 評価に渡すテキストの前処理（`spec/distance-model.md` §4.6）で取り除かれる記号の分だけ、区切りの位置を前へ詰める。
   取り除く記号は対象の記号の範囲（条件 `keepSymbols`）で決まるので、この写しは対象ごとに行う。
5. 寄せや取り除きで区切りが重なった時は1つにする。先頭や末尾に来た区切りは除く。

漢字を含まない原文と、辞書を読み込めなかった時は、語の列が無いので 1 と 4 だけで写す（2・3 は何もしない）。
どちらの場合も、結果に区切りの出どころとして記録する。かなだけの文では分割器の精度が落ちる見込みで、この精度は測っていない。

日本語以外のテキストでは、区切り方を選べない（分割器は日本語のモデルだけを使う）。
固定長とランダムは文節の区間の長さから作るので、同じく選べない。

### 固定長

文節の区間の長さ（文字数）の平均 `評価に渡すテキストの文字数 / 文節の区間の数` を丸めた長さ（最小1）で、テキストの先頭から区切る。
最後の区間は残りの長さになる。始まりの位置をずらした値は作らない。判定に使わない。

### ランダム

文節の区間の長さの列を、乱数で並べ替え（Fisher-Yates）、その順に区切りを置く。区切りの数も区間の長さの分布も文節と同じになるので、
区間の長さの違いが判定の量に入らない。

- 乱数生成器は mulberry32（32bitの種）。`src/interpretation/prng.ts`。名前を再現の条件に書く。`Math.random` は使わない
- 種は、解析設定の始まりの値 `s` から `s, s+1, …, s+19` の20個で固定する（個数は設定にしない）。同じテキストと同じ `s` からは同じ区切りが出る
- 図に重ねるランダムの区切りは、最初の種（`s`）のもの

## 区間ごとの値と、区切りの前後の値

指標は4つ（1文字あたりの距離・1打鍵あたりの距離・同指率・1文字あたりの打鍵数）。区切り方ごと、指標ごとに次を出す。

| 量 | 定義 |
|---|---|
| 区間の数 | 区切りの数 + 1 |
| 区間の中央値 | 値が決まった区間の値の中央値。個数が偶数の時は中央の2つの平均 |
| 区間の90%点 | 値が決まった区間の値を小さい順に並べた `⌈0.9n⌉` 番目の値（補間しない。`n` は値が決まった区間の数） |
| 区間の最大 | 値が決まった区間の値の最大 |
| 区切りの直前の1文字 | 全区切りについて、前の区間の最後の文字（文字 `b − 1`）を範囲 `[b − 1, b)` として求めた分子の和 / 分母の和 |
| 区切りの直後の1文字 | 同じく、次の区間の最初の文字（文字 `b`）の範囲 `[b, b + 1)` の分子の和 / 分母の和 |

- 区間の値は、その区間を範囲にした `docs/span-metrics.md` の値。打鍵の指標で分母が0の区間（その区間に帰属したステップが無い）は値が決まらないので、分位点・中央値・最大から除く。
  90%点に補間を使わないのは、観測した区間の値のどれかになり、導出を追えるため
- 1文字あたりの距離・1文字あたりの打鍵数では、直前・直後の量は「その1文字に帰属したステップの値の、全区切りでの平均」になる（分母が文字数1で、区切りの数で割るため）。
  1打鍵あたりの距離・同指率では、分母がステップ数なので、ステップの数で重み付けした値になる
- ランダムは、20個の種ごとの値を持つ。画面は既定で最小〜最大を出し、種ごとの値（1文字あたりの距離）は畳んで置く

## 文節の値の順位

特徴が無くても端に来る確率を読み手が知れるよう、二値の判定ではなく順位を出す。順位を付けるのは、1文字あたりの距離の次の2つの量だけで、
ほかの指標と量は表に並べるだけにする（量を増やすほど、特徴が無くても端に来る量が増えるため）。

- (a) 区間の90%点（上側の分位点。局所的に大きくなる箇所を見るため）
- (b) 区切りの直後の1文字の量

文節の値と、ランダムの20個の値を合わせた21個を小さい順に並べた時の、文節の値の順位を出す。

- 同じ値がある時は、順位を幅で示す（例: 「3〜5番目」）。値が同じかは、相対誤差 1e-12 以内で判定する
- 端に数えるのは、文節の値がランダムの20個のどれよりも厳密に小さいか大きい時だけ。同点の値があれば端に数えない。これで、特徴が無い時に端に来る確率は量ごとに 2/21（約9.5%）以下になる。量が2つなら、どちらかが端に来る確率は最大で約18%
- 「有意」とは書かない。区間どうしは重なり、打鍵どうしにも相関がある。外れている所を探す目安として出す
- 固定長には順位を付けない（区間の長さが全部同じで、文節の長さの分布と違うため）
- 配列の優劣の判定・順位・合成スコアは出さない。指標を1つのスコアにまとめない

## 再現の条件

結果に次を併記する。配列・綴り・`N`・物理配列・指の割り当て・前処理は、ペインの条件の要約が持つ。

- 区切り方
- 分割器の名前と版（BudouX、`package.json` の `budoux` と同じ版）
- 区切りの出どころ（漢字を辞書で読みに直した語の境目へ寄せた / 原文が漢字を含まない / 辞書を読み込めず漢字を読みに直していない）
- ランダムの乱数生成器の名前、種の始まりの値と個数
- 固定長の長さ

## 計算量

分割器と写しは、区切りを使う設定のときだけ動く。写しは語の数と区切りの数に比例する。
区間の集計は累積和から求めるので、区間1つあたり一定の時間で済む。
