# 区切りごとの指標と、文節の区切りの判定の量

Run Chart（`docs/span-metrics.md`）に区切りを重ね、区切り方（文節・固定長・ランダム）で区間ごとの指標と区切りの前後の指標を比べる定義。
実装は `src/interpretation/segments.ts`（区切りの作成と集計）、`src/input/text/segmentation.ts`（区切りを評価に渡すテキストへ写す処理）。
距離モデルの値（`spec/distance-model.md`）は変えない。区間の集計は `docs/span-metrics.md` の分子と分母、ステップの帰属の規則をそのまま使う。

## 区切り

区切りは、評価に渡したテキストの文字位置の昇順の列（0とテキストの長さを含まない）。位置 `b` の区切りは、文字 `b − 1` と文字 `b` の間を指す。
区間は `[0, b₁)`, `[b₁, b₂)`, …, `[bₖ, 末尾)`。長さ0の区間は作らない。区間はテキスト全体を重ならずに覆うので、
区間ごとの分子と分母を足すとテキスト全体の値に戻る。

### 文節の区切り

分割器は BudouX（`package.json` の `budoux` の版、日本語のモデル）。次の順に、評価に渡すテキストの文字位置へ写す。

1. 分割器を、器が漢字を読みに直す前に持っている原文に当てる（かなに直した後の文には当てない）。区切りは原文の位置で得る。
2. 漢字を読みに直した語（`ReadingToken`）の途中に区切りが来たら、その語の後ろの境目へ寄せる。1語の読みを2つの区間に分けない。
   語の間の文字や、読みに直さない語の途中は、そのまま写す。
3. 利用者の読みの直しを当てた後の読みのテキストのかな数で位置を数える。直しで読みのかな数が変わっても、区切りは語の境目に載る。
4. 評価に渡すテキストの前処理（`spec/distance-model.md` §4.6）で取り除かれる記号の分だけ、区切りの位置を前へ詰める。
   取り除く記号は対象の記号の範囲（条件 `keepSymbols`）で決まるので、この写しは対象ごとに行う。
5. 寄せや取り除きで区切りが重なった時は1つにする。先頭や末尾に来た区切りは除く。

漢字を含まない原文と、辞書を読み込めなかった時は、語の列が無いので 1 と 4 だけで写す（2・3 は何もしない）。
どちらの場合も、結果に区切りの出どころとして記録する。かなだけの文では分割器の精度が落ちる見込みで、この精度は測っていない。

日本語以外のテキストでは、区切り方を選べない（分割器は日本語のモデルだけを使う）。
固定長とランダムは文節の区間の長さから作るので、同じく選べない。

### 固定長

文節の区間の長さ（かな数）の平均 `評価に渡すテキストのかな数 / 文節の区間の数` を丸めた長さ（最小1）で、テキストの先頭から区切る。
最後の区間は残りの長さになる。始まりの位置をずらした値は作らない。判定に使わない。

### ランダム

文節の区間の長さの列を、乱数で並べ替え（Fisher-Yates）、その順に区切りを置く。区切りの数も区間の長さの分布も文節と同じになるので、
区間の長さの違いが判定の量に入らない。

- 乱数生成器は mulberry32（32bitの種）。`src/interpretation/prng.ts`。名前を再現の条件に書く。`Math.random` は使わない
- 種は、解析設定の始まりの値 `s` から `s, s+1, …, s+19` の20個で固定する（個数は設定にしない）。同じテキストと同じ `s` からは同じ区切りが出る
- 図に重ねるランダムの区切りは、最初の種（`s`）のもの

## 区間ごとの値と、区切りの前後の値

指標は4つ（1かな換算の移動距離・1アクションの移動距離・同指率・1かな換算のアクション数）。区切り方ごと、指標ごとに次を出す。

| 量 | 定義 |
|---|---|
| 区間の数 | 区切りの数 + 1 |
| 区間の中央値 | 値が決まった区間の値の中央値。個数が偶数の時は中央の2つの平均 |
| 区間の90%点 | 値が決まった区間の値を小さい順に並べた `⌈0.9n⌉` 番目の値（補間しない。`n` は値が決まった区間の数） |
| 区間の最大 | 値が決まった区間の値の最大 |
| 区切りの直前の1文字 | 全区切りについて、前の区間の最後の文字（文字 `b − 1`）を範囲 `[b − 1, b)` として求めた分子の和 / 分母の和 |
| 区切りの直後の1文字 | 同じく、次の区間の最初の文字（文字 `b`）の範囲 `[b, b + 1)` の分子の和 / 分母の和 |

- 区間の値は、その区間を範囲にした `docs/span-metrics.md` の値。アクションの指標で分母が0の区間（その区間に帰属したステップが無い）は値が決まらないので、分位点・中央値・最大から除く。
  90%点に補間を使わないのは、観測した区間の値のどれかになり、導出を追えるため
- 1かな換算の移動距離・1かな換算のアクション数では、直前・直後の量は「その1文字に帰属したステップの値の、全区切りでの平均」になる（分母がかな数1で、区切りの数で割るため）。
  1アクションの移動距離・同指率では、分母がステップ数なので、ステップの数で重み付けした値になる
- ランダムは、20個の種ごとの値を持つ。画面は既定で最小〜最大を出し、種ごとの値（1かな換算の移動距離）は畳んで置く

## 文節の値の順位

特徴が無くても端に来る確率を読み手が知れるよう、二値の判定ではなく順位を出す。順位を付けるのは、1かな換算の移動距離の次の2つの量だけで、
ほかの指標と量は表に並べるだけにする（量を増やすほど、特徴が無くても端に来る量が増えるため）。

- (a) 区間の90%点（上側の分位点。局所的に大きくなる箇所を見るため）
- (b) 区切りの直後の1文字の量

文節の値と、ランダムの20個の値を合わせた21個を小さい順に並べた時の、文節の値の順位を出す。

- 同じ値がある時は、順位を幅で示す（例: 「3〜5番目」）。値が同じかは、相対誤差 1e-12 以内で判定する
- 端に数えるのは、文節の値がランダムの20個のどれよりも厳密に小さいか大きい時だけ。同点の値があれば端に数えない。これで、特徴が無い時に端に来る確率は量ごとに 2/21（約9.5%）以下になる。量が2つなら、どちらかが端に来る確率は最大で約18%
- 「有意」とは書かない。区間どうしは重なり、打鍵どうしにも相関がある。外れている所を探す目安として出す
- 固定長には順位を付けない（区間の長さが全部同じで、文節の長さの分布と違うため）
- 配列の優劣の判定・順位・合成スコアは出さない。指標を1つのスコアにまとめない

## 再現の条件

結果に次を併記する。配列・綴り・`N`・物理配列・指の割り当て・前処理は、ペインの条件の要約が持つ。

- 区切り方
- 分割器の名前と版（BudouX、`package.json` の `budoux` と同じ版）
- 区切りの出どころ（漢字を辞書で読みに直した語の境目へ寄せた / 原文が漢字を含まない / 辞書を読み込めず漢字を読みに直していない）
- ランダムの乱数生成器の名前、種の始まりの値と個数
- 固定長の長さ

## 計算量

分割器と写しは、区切りを使う設定のときだけ動く。写しは語の数と区切りの数に比例する。
区間の集計は累積和から求めるので、区間1つあたり一定の時間で済む。

## 文節の中と境目の統計

文節の中の文字と、文節の境目の文字に分けて、指の移動距離の統計を配列ごとに出す定義。
実装は `src/interpretation/bunsetsu-stats.ts`、Analyzerは `src/analyzers/bunsetsu-stats/`（画面はMulti）。
距離モデルの値（`spec/distance-model.md`）は変えない。同じTraceのステップを、`docs/span-metrics.md` の帰属の規則どおりに文字位置へ帰属させ、文字の種類で分けて集計し直す。
順位・合成スコア・配列どうしの結論は出さない。配列ごとの表の行は、ツールが並べ替えの順を決めず、利用者が列の見出しで選ぶ表示の操作だけがある（既定は対象の順）。打ちやすさや、境目が何を意味するかも出さない。

### 言葉

- **評価に渡すテキスト**: 漢字を読みに直し、`spec/distance-model.md` §4.6 の前処理を通した後の文字の列。文字位置 `p` は先頭が0
- **文節の区切り**: 上の「文節の区切り」で評価に渡すテキストの位置へ写した区切り。位置 `p` の区切りは文字 `p−1` と `p` の間を指す
- **境目の文字**: 区切りの直後の1文字。**内側の文字**: 各文節の先頭の1文字を除いた文字。テキストの先頭の文字はどちらにも入れない
- **打鍵できなかった文字**: Trace生成が `skipped` を数えた文字の、評価に渡すテキストの文字位置の集合（`Trace.skippedPositions`。改行を含む）。ステップが1つも帰属しない文字は距離0になる。
  かな配列では、集合の大きさが `skipped` と一致する。ローマ字配列では、打てなかった展開後の英字を含む綴りの単位（1つ以上のかな）の文字を全部入れる。
  一部の英字だけ打てたかなも入るので、集合の大きさは `skipped`（展開後の英字の数）と一致するとは限らない。綴りの一部が欠けた打鍵は、そのかなを打った距離として読めないため。
  一部だけ打てたかなに帰属した距離は、打鍵できなかった文字の距離の和に入れ、境目の文字にも内側の文字にも入れない。
  画面の「数」と、境目の文字・内側の文字から除く文字は、この集合に従う（`spec/distance-model.md` §4.6の `skipped` の節）
- **bigram**: 評価に渡すテキストの連続する2文字（文字 `p−1` と `p`、`p ≥ 1`）。位置 `p` に区切りがあれば「またぐbigram」、無ければ「文節の中のbigram」
- **bigramの距離**: 2文字目の文字 `p` に帰属する距離。ローマ字の `っか` のように前の文字から始まる打鍵も入る
- **1文節の距離**: その文節の文字（先頭の文字を含む）に帰属する距離の和

### テキストの表（配列によらない量）

| 量 | 定義 |
|---|---|
| 文節の数 | 区切りの数 + 1（テキストが空なら0） |
| 境目の文字が全文字に占める割合 | 区切りの数 / 評価に渡すテキストのかな数 |
| またぐbigramのうち、文節の中にも出る並びの割合 | またぐbigramの出現のうち、同じ2文字の並びが文節の中のbigramとして1回以上出る並びの出現の数 / またぐbigramの出現の数（区切りの数） |

評価に渡すテキストは、記号の範囲（条件 `keepSymbols`）の上書きで対象ごとに違うことがある。テキストの表と上位の一覧の行は、区切りが渡された最初の対象のテキストから求める。
その対象と評価に渡すテキストまたは区切りが違う対象も、配列ごとの表の値と上位の一覧のセルを、自分のテキストで求める。一覧の行の文字列は基準の対象のものを、自分のテキストから引く
（自分のテキストに無い文字列のセルは値なし）。違う対象があれば、画面にその旨を書く。

### 配列ごとの表

| 量 | 定義 |
|---|---|
| 打鍵できなかった文字の数 | 上の位置の数 |
| うち区切りの直後の1文字になったもの | 境目の文字のうち、打鍵できなかった文字の数 |
| 境目の文字の距離の割合 | 境目の文字（打鍵できなかった文字を除く）に帰属する距離の和 / 全距離。全距離が0なら値なし |
| 境目の文字・内側の文字の1かな換算の移動距離 | 打鍵できなかった文字を除いた各文字に帰属する距離の平均 |
| 境目の文字・内側の文字の標準偏差 | 同じ文字ごとの距離の母標準偏差 `√(Σ(x−平均)²/n)` |
| 1文節の距離の標準偏差・90%点 | 1文節の距離を全文節で集め、母標準偏差と、小さい順に並べた `⌈0.9n⌉` 番目の値（`quantileNearestRank`） |
| 文節ごとの1かな換算の移動距離の中央値・90%点 | Run Chartで区切りを文節にした時の区間の値の中央値・90%点（上の「区間ごとの値と、区切りの前後の値」）と同じ定義・同じ関数。先頭の文字を含み、打鍵できなかった文字もかな数に数える |

- 文字の種類（先頭の文字・境目の文字・内側の文字・打鍵できなかった文字）の距離の和は全距離に一致する。境目の文字の距離の割合はこの和の比
- 境目の文字と内側の文字の統計では、打鍵できなかった文字を数えない。区切りの直後の1文字が改行になる区切りがあり、距離0の文字が境目の文字の平均を下げるため。
  `boundary-context.ts` の `boundaryInterior` は打鍵できなかった文字を分母に数える版で、既存の出力のために変えない
- 1かな換算の移動距離は、またぐbigramと文節の中のbigramの平均距離と（打鍵できなかった文字の扱いを除いて）同じ量なので、bigramの列は別に作らない
- 1文節の距離の平均は「全文の1かな換算の移動距離 × 文節の平均の長さ」で、文節の長さは配列によらないので出さない

### 上位の一覧（1行が1項目、列が配列）

どちらも行の並びは出現回数で決め（同じ回数は最初に出た順）、配列の値では並べ替えない。上位20行。

| 一覧 | 行 | セル |
|---|---|---|
| 頻出の文節 | 評価に渡すテキストの上での文節の文字列。かな数1の文節を除く。行に出現回数を添える | その文節の内側の文字（打鍵できなかった文字を除く）の1かな換算の移動距離を、全出現で合わせた値（距離の和 / かな数の和） |
| 頻出のまたぐbigram | またぐbigramの2文字の並び。行にまたいだ回数と、文節の中に出た回数を添える | その並びのまたいだ出現の平均距離と、文節の中の出現の平均距離（どちらも2文字目に帰属する距離。打鍵できなかった文字を除く）。文節の中に出ない並びは値なし |

同じ並びの2つの平均を並べると、2文字の並びの違いを揃えて読める。並びの外の打鍵の違いは残る。
画面は、値なしを「—」で、改行を「↵」、空白を「␣」、タブを「⇥」で表す。

### 画面の名前と定義の語

画面（`src/analyzers/bunsetsu-stats/`）は、次の名前で出す。左が画面の名前、右が上の定義の語。内部の型・関数・`data-*` の名前は定義の語のまま。

| 画面の名前 | 定義の語 |
|---|---|
| 文節頭 | 境目の文字（区切りの直後の1文字） |
| 文節中 | 内側の文字 |
| 文節頭の距離の割合 | 境目の文字の距離の割合 |
| 打てない文字・数 | 打鍵できなかった文字の数 |
| 打てない文字・うち文節頭 | うち区切りの直後の1文字になったもの |
| 文節頭の割合 | 境目の文字が全文字に占める割合 |
| またぐ並びのうち、文節の中にも出る並びの割合 | 文節をまたぐbigramの出現のうち、同じ並びが文節の中にも出る並びの出現の割合 |

### 表に出ない図だけの量（箱ひげ図）

Analyzer「箱ひげ図」（`src/analyzers/box-plot/`）は、表の列「文節ごとの1かな換算の移動距離」と同じ標本（1つの文節を区間にした1かな換算の移動距離を、全文節で集めたもの。打てない文字もかな数に数える）から、次の5つの値を求める。
分位点の関数は `src/interpretation/bunsetsu-stats.ts` の `segmentPerCharBox`。標本は表の列と同じ関数で作る。

| 図の要素 | 値 | 定義 |
|---|---|---|
| ひげの下端 | 10%点 | 標本を小さい順に並べた `⌈0.1n⌉` 番目の値（`quantileNearestRank`。補間しない） |
| 箱の下端 | 25%点 | 同じく `⌈0.25n⌉` 番目の値 |
| 箱の中の線 | 中央値 | `median`。個数が偶数なら中央の2つの平均 |
| 箱の上端 | 75%点 | 同じく `⌈0.75n⌉` 番目の値 |
| ひげの上端 | 90%点 | 同じく `⌈0.9n⌉` 番目の値。表の列「90%点」と同じ値 |

- 表の列に出るのは中央値と90%点だけで、10%点・25%点・75%点は図だけの量である
- 定義が混ざる点: 中央値は偶数個の時に2つの平均になり標本に無い値を取りうるが、ほかの分位点は標本のどれかの値になる。このため箱の中の線は、箱の中央とは限らない
- 文節が1つなら5つの値が同じになる。値が決まる文節が無い配列（テキストが空など）は値を出さない
- 距離の目盛りは0から始め、図の中の全配列と、Workspaceで並べた同じAnalyzerのペインで共通にする。ひげの外の値・基準の線・回帰直線・係数は描かない
- 評価に渡すテキストが対象ごとに違う時は、各配列を自分のテキストと区切りで求め、基準の対象と違う配列があれば画面に知らせ、文節の数を配列ごとに出す

### 日本語以外のテキストと分割器

文節の区切りは日本語のテキストでだけ使える。日本語以外のテキストと、分割器を読み込めなかった時は、値を出さず、その旨を示す。
区切りの出どころと分割器の名前・版は、Run Chartと同じ文面で示す（箱ひげ図は画面の文にせず、図の見方に短く出す）。

## 帯グラフの量

評価に渡したテキストを打った時の標本（かな、押下、移動距離）を、区分に分け、区分ごとの割合を配列ごとに1本の帯で並べる定義。帯に出す量は7つあり、ペインの見出しか解析設定で1つ選ぶ。既定は移動距離。
実装は `src/interpretation/band-quantities.ts`、Analyzerは `src/analyzers/band-chart/`（画面の名前は「帯グラフ」、Multi）。
距離モデルの値（`spec/distance-model.md`）は変えない。区切りは使わない。

### 量

| 量 | 標本 | 割合の分母 | 区分 |
|---|---|---|---|
| 移動距離 | かな。値は、そのかなを含む打鍵のまとまりの1かな換算の移動距離 | 数えたかなの数 | 0.5u未満・0.5〜1.5u・1.5〜2.5u・2.5u以上 |
| 打ち方 | かな。値は、そのかなを含む打鍵のまとまりの打ち方 | 数えたかなの数 | 単打・同時押し・2アクション・3アクション以上 |
| 押下数 | かな。値は、そのかなを含む打鍵のまとまりの押下数 | 数えたかなの数 | 1キー・2キー・3キー以上 |
| 手 | かな。値は、そのかなを含む打鍵のまとまりで使う手 | 数えたかなの数 | 左手・両手順次・両手同時・右手 |
| 段 | 押下。値は、押したキーの段 | 数えた押下の数 | 数字段・上段・中段・下段・親指 |
| 指ごとの押下 | 押下。値は、押した指 | 数えた押下の数 | 左小指・左薬指・左中指・左人差し指・左親指・右親指・右人差し指・右中指・右薬指・右小指 |
| 指ごとの移動距離 | 押下の移動距離 [u]。値は、押した指 | 数えた押下の移動距離の合計 | 指ごとの押下と同じ10区分 |

### 言葉

- **押下**: キーを1つ押すこと。距離モデル仕様 §11.2のキー数と同じく、同時に押したキーはキーの数だけ数える。1本の指でキーの間を押す時（`Press.keys` が2つ以上）も、キーの数だけ押下を数える
- **打鍵のまとまり**: 評価に渡したテキストの連続したかなの範囲と、その範囲を打つステップの組。ステップを順に見て、`kanaStart` から `kanaEnd` の範囲が前のまとまりの範囲と重なるステップは前のまとまりに入れ、重ならないステップから新しいまとまりを始める。`Stroke.inputIndex` が同じステップの組（仕様とコードの「入力単位」）とは別の分け方で、ローマ字入力で別の選択が `inputIndex` を共有する時も、範囲の重なりだけで決める。ローマ字入力の「きょ」を `kyo` と打つ時は、「き」と「ょ」の2かなと3つのステップが1つのまとまりになる。コンボで2かなを1アクションで打つ時は、2かなと1つのステップが1つのまとまりになる
- **確定の打鍵**（`Stroke.commit`。仕様 §4.7）: 他のステップと同じく、範囲の重なりでまとまりに入れ、打ち方のステップ数・押下数・手・段・指に数える。利用者が実際に押すキーなので除かない。確定の打鍵の移動距離も、まとまりの移動距離と指ごとの移動距離に入る
- **打鍵できなかった文字**: 上の「文節の中と境目の統計」と同じ（`Trace.skippedPositions`）。ローマ字配列で一部の英字だけ打てたかなも含む

### かなを標本にする量（移動距離・打ち方・押下数・手）

1つのかなを1つの標本にし、そのかなを含む打鍵のまとまりの値で区分を決める。打鍵のまとまりが覆うかなは、どれも同じ区分に入る。

| 量 | 区分の決め方 |
|---|---|
| 移動距離 | 打鍵のまとまりのステップの移動距離の和を、まとまりが覆うかなの数で割った値（1かな換算の移動距離）`d` [u]。下の境目で分ける |
| 打ち方 | ステップが1つで押下が1つなら単打、ステップが1つで押下が2つ以上なら同時押し、ステップが2つなら2アクション、3つ以上なら3アクション以上 |
| 押下数 | 打鍵のまとまりの押下の数（1・2・3以上） |
| 手 | 打鍵のまとまりの押下の指の手。親指は、その親指の手に数える。親指以外の押下がある時に親指を外す距離モデル仕様 §10の手の集合とは、別の定義。押下が左だけなら左手、右だけなら右手。両方の手の押下がある時は、1つのステップ（`Stroke.presses`）の中に左右両方の手の押下があれば両手同時、どのステップも片手の押下だけなら両手順次。前置シフトのように押下が複数のステップに分かれる時も、まとまり全体の押下の手で決める（左右の押下があってどのステップも片手だけなら両手順次、片手だけなら左手か右手） |

移動距離の境目は `0.5` 刻みで、境目ちょうどの値は上の区分に入る。境目は1キー分の距離の半分で、どの物理配列でも同じ値を使う。

| 区分 | 範囲 | 画面の名前 |
|---|---|---|
| 0 | `d < 0.5` | 0.5u未満 |
| 1 | `0.5 ≤ d < 1.5` | 0.5〜1.5u |
| 2 | `1.5 ≤ d < 2.5` | 1.5〜2.5u |
| 3 | `2.5 ≤ d` | 2.5u以上 |

打てない文字を1つでも含む打鍵のまとまりは、覆うかなを全部数えない。ローマ字入力で一部の英字だけ打てたかなは、打てなかった英字の分の値を持たないため。
打てない文字の値は0なので、数えると最も小さい区分の割合が大きく見える。

### 押下を標本にする量（段・指ごとの押下・指ごとの移動距離）

- 段と指ごとの押下は、押下を1つの標本にする。段は、親指が押したキーを「親指」に、それ以外を物理配列のキーの段（`Key.row` の0〜3。数字段・上段・中段・下段）で分ける。物理配列が4段より多い時は、端の段に寄せる
- 指ごとの移動距離は、押下の移動距離（`Press.distance`）を指ごとに足し、数えたステップの `Press.distance` の合計で割る。親指の移動距離は、親指キーが片手に1つの物理配列では、親指が親指キーだけを打つ間は0になる（距離モデル仕様 §3.1）。親指キーを片手に複数置く物理配列や、親指が親指キー以外を打つ割り当てでは0でなくなるので、区分は残す
- 打てない文字を含む打鍵のまとまりのステップは数えない。かなを標本にする量と、数える範囲をそろえる

### 配列ごとの値

| 量 | 定義 |
|---|---|
| 区分の割合 | その区分の標本の量 / 分母。割合の和は、丸める前で100% |
| 打てない文字 | `Trace.skippedPositions` の位置にある、評価に渡したテキストの文字。文字ごとの回数（その文字の位置の数）を、打てない文字がある配列ごとに表で出す。標本に入れず、割合の分母にも入れない。ローマ字入力で一部の英字だけ打てたかなも、この位置に入るので表に出る。回数の合計は `Trace.skipped`（展開後の英字の数）と一致しないことがある |

分母が0の配列（打てた文字が0、または指ごとの移動距離で数えた移動距離が0）は、割合を出さず、値を出せない行にする。

評価に渡すテキストは、記号の範囲（条件 `keepSymbols`）の上書きで対象ごとに違うことがある。各配列の割合は自分のテキストで求め、最初の対象のテキストと違う配列があれば画面に知らせる。

### 画面の見方

1行が1配列で、左に配列の名前、右に全体を100%にした帯を置く。区分は上の表の順に左から並べる。指は左小指から右小指へ、キーボードの上の並びと同じ順にする。
行の順は対象の順で、値で並べ替えない。特定の配列を色や太さで目立たせない。
帯の中に割合（整数に丸めた%）を書き、区分の幅が文字の入らない狭さの時は書かない。区分に重ねると、区分の名前と割合（小数1桁）を出す。
打てない文字がある時は、図の下に、配列と打てない文字（文字ごとの回数）の表を出す。打てない文字が全配列に無い時は表を出さない。改行・空白・タブは、文節ごとの統計と同じ記号（↵ ␣ ⇥）で出し、記号が出る時は表の見出しに説明を添える。
行を選ぶと、その配列の区分の割合（小数1桁）と標本の量（かな数・押下数・移動距離）を図の下に出す。
図の幅が狭い時は、名前を帯の上の行に置く。

区分の色は、移動距離・打ち方・押下数と、段の数字段〜下段が、区分に順序があるので1色の濃淡で、値の大きい区分ほど濃い。打ち方は、押すキーの数とアクションの数が増える順に濃くする。
段の「親指」は段の順序の外にあるので、別の色相にする。手・指ごとの押下・指ごとの移動距離は、左手と右手で色相を分け、手の中を濃淡で分ける。両手の2区分（順に・同時に）は、左右と別の1つの色相の濃淡で分ける。

凡例は、表示している配列のどれにも数が0の区分を出さない（値を出せない行の配列は判定に入れない。並び・色・帯の中の位置は変えない）。行を選んだ時の表は、0の区分も0%で出す。
凡例・図の見方（ⓘ）・キャプション・行を選んだ時の表は、選んだ量の区分と名前で出す。図の見方には、選んだ量の標本と分母を書く。
