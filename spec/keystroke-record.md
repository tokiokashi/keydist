# 打鍵の記録 仕様

評価に渡したテキストの範囲を、利用者が選んだ配列・物理配列・指の割り当てで実際に打ち、ストロークごとの時刻を残す。
この仕様は、記録の取り方・ストロークの時刻・保存する項目・記録と今の条件の食い違いの判定・打鍵の間隔の定義を定める。図の置き場と画面の文言は、この仕様の範囲に入れない。

打鍵の照合（違うキーを押した時の扱い・ローマ字の綴りの受け付け・コンボを出力の文字の読み方で打つ時の扱い・取れるキー・親指のキーの取得）は、
個人速度の「文章を打つ測定」と同じ規則を使う（`spec/playback-timing.md` §6.4）。ここには書き直さない。
この仕様が §6.4と違うのは、次の点だけである。

| 違う点 | §6.4 | 記録 |
|---|---|---|
| 打鍵の列を作る経路 | 境を入れず、全体のレベルの条件だけを読み、Setupを受け取らない | Run Chartと同じ経路（Setupと全レベルの条件、コンボを止める境を含む）で、評価に渡す全文から作る |
| 打つ単位 | 覚えられる短い文を複数本、各3回 | 全文を約1000字ごとに分けた範囲を、1回だけ |
| 打てない時の判定 | 示す文の全部 | 範囲ごと |
| 綴りを変えた時の打鍵の列の作り直し | 文全体 | 打っている間は文の単位の窓、保存する時は全文で1回 |
| 結果 | 個人速度の保存値を求める | 時刻の列をそのまま保存する。保存値は変えない |

## 1. 記録の単位

評価に渡した本文（前処理の後の本文）を、`src/input/text/display-ranges.ts` の範囲に分ける。約1000字ごとで、1000字に満たなければ全文で1つである。
利用者は範囲を1つ選び、その範囲を1回打つ。範囲は評価に渡した本文の文字位置の半開区間 `[start, end)` で表し、文字位置は全文の位置のまま使う。

### 1.1 範囲に入るストローク

打鍵の列は、Run Chartと同じ経路で評価に渡す全文から1度だけ作る（`recordBaseTrace`）。範囲のストロークは、そのストロークが属する入力の選択の文字位置 `e`（§2）が `[start, end)` に入るものである。

範囲のストロークは、全文の打鍵の列の連続した部分でなければならない。

### 1.2 打てない範囲

次の範囲は記録を始められない。理由を画面に出し、打てない文字を飛ばして記録する形は採らない。

| 理由 | 条件 |
|---|---|
| 配列の定義に不備がある | 打鍵の列を作る時に配列の誤りが出た |
| 打てない文字がある | 範囲の文字位置に、配列で打てず飛ばした文字がある。打鍵の列から飛ばされた改行と空白（`\s` に当たる文字。全角の空白を含む）は打たない文字なので数えない。半角の空白をスペースのキーで打つ配列では、空白は飛ばされず1打になる |
| 打つ文字が無い | 範囲に入るストロークが0 |
| 範囲の境目をまたぐ | 範囲のストロークが連続した部分でない、または範囲の端で1つの入力単位が2つの範囲に分かれる |
| 取れないキーが要る | 範囲を打つのに、§6.4「測れない配列」の規則で取れないキーが要る |

判定は範囲ごとに掛ける。ある範囲が打てなくても、他の範囲の判定は変わらない。範囲の外にある打てない文字は、その範囲の判定にも、保存する時の検証（§3.1）にも影響しない。

## 2. 文字位置 `e`

各ストロークは、属する入力の選択の文字位置 `e` を持つ。`e` は、同じ `selectionIndex` を持つストロークの組の `kanaEnd` の最大値を `[0, inputChars - 1]` に収めた値である。
`e` の定義はRun Chartの点の横位置の定義と同じで、`src/interpretation/selection-ends.ts` が両者に共通して提供する。
ストロークと点は1対1に対応せず、複数のストロークが同じ `e` に属しうる。

**条件の規則の綴りで打った記録の `e` の集合は、同じ条件のRun Chartの点の位置のうち範囲に入るものと等しい。**
ローマ字の配列で綴りを混ぜて打った記録でも、同じ集合になる。綴りが変わっても、ストロークの数は変わりうるが、`e` の集合は変わらない。
この等式は `test/keystroke-record-run-chart.test.ts` が、ローマ字の配列・かなの配列・コンボを持つ配列（範囲の中に境がある場合を含む）で確かめる。

## 3. 記録の取り方

1. 範囲のストロークを、§6.4の打鍵の照合に渡す。照合は、押下のキーが次に打つキーに当たるかで進める。
2. 各ストロークの時刻は、そのストロークの最初のキーの押下の時刻（`KeyboardEvent.timeStamp`）である。§6.4の `SentenceTap` と同じ項目を持つ。
   違うキーを押したストロークは、間隔を数えない印（`clean` が偽）を残す。コンボを出力の文字の読み方で打ち終えたストロークは、その印（`outputCompleted`）を残す。
3. 最後のストロークを打ち終えたら、記録を作って利用者に示す。利用者が保存を選ぶと保存し、破棄を選ぶと残さない。途中でやめた時は残さない。
4. 記録の時刻は、最初のストロークの時刻を0とした相対の時刻[ms]にし、0.1ミリ秒に丸める。絶対の時刻（時計の値）は保存しない。

### 3.1 ローマ字の綴り

ローマ字の配列では、§6.4「ローマ字の綴り」「打った綴りで求める」と同じく、かなごとに打った綴りを受け付ける。
綴りを選べる範囲（範囲の打鍵の列が、かなの入力単位（打鍵の列から飛ばされた改行・空白の単位を除く）と1対1に対応する範囲）では、記録は、かなごとに打った綴り `typed` を持つ。
`typed` は、打鍵の列から飛ばされた改行・空白を除く入力単位ごとの綴りで、条件の規則の綴りと全部同じでも持つ。綴りを選べない範囲（かなの配列、ローマ字の表を持たない配列、ローマ字の綴りだけで出力するコンボを持つ配列、範囲の打鍵の列がかなの入力単位と1対1にならない範囲）は `typed` を持たず、条件の規則の打ち方の打鍵の列を打つ。

**打っている間の作り直し。** 打った綴りで次に打つキーを決めるには、綴りを変えた時に打鍵の列を作り直す必要がある。
全文を作り直すと1打ごとの応答に間に合わないので、打っている間は、範囲を文の終わり（または100字）ごとに、かなの入力単位の境目で窓に分け、綴りを変えた単位を含む窓の本文だけで打鍵の列を作り直す。
窓の外のストロークは、全文の打鍵の列のものをそのまま使う。

この作り直しの範囲は、§6.4の「文全体を作り直す」と異なる。窓の境をまたぐ入力単位（コンボ）がある場合、窓だけの作り直しは全文の作り直しと違うキーの列になりうる。

**保存する時の検証。** 記録を保存する時は、打った綴りで全文を1度だけ作り直し、その範囲のストロークを取り出す。次のどれかなら保存しない。

| 理由 | 条件 |
|---|---|
| 作り直せない | 全文の作り直しが打てる打鍵の列にならない、または範囲を取り出せない |
| 窓の作り直しと食い違う | 打っている間に使った窓ごとの作り直しの結果と、全文で作り直した範囲が、同じ打つキーの列（ステップごとの、押すキーと出力の文字）でない。打っている間に使った窓の結果は、記録を作る側へ渡す |
| 数が合わない | 全文で作り直した範囲のストロークの数が、記録した打鍵の数と違う（§6.4と同じ） |

全部の単位を条件の規則の綴りで打った時は、全文の打鍵の列をそのまま使い、作り直さない。
`e` は、保存する時に作り直した打鍵の列から求める。

## 4. 保存する項目

記録は版付きの形式で、手持ちの資産として保存する。形式は `{ version, records }` で、`records` は記録の並びである。版は1である。

| 項目 | 内容 |
|---|---|
| `id` | 記録の識別子。同じ手持ちの中で重ならない。重なった記録は読み込まず、診断を残す |
| `recordedAt` | 記録した日時（ISO 8601、UTC） |
| `appVersion` | 記録した時のアプリの版 |
| `modelVersion` | 記録した時の `MODEL_VERSION` |
| `target` | 対象。`{ kind: 'layout' \| 'setup', id }` |
| `targetName` | 記録した時の対象の表示名。一覧の表示に使う |
| `shapeId` | 物理配列の識別子 |
| `fingerAssignmentId` | 指の割り当ての識別子（実効値） |
| `conditions` | 打鍵の列と構造を決める条件の実効値。`Metrics` の条件のスナップショットから、読みの変換（`reading`）を除いたもの |
| `text` | `{ identity, name, chars, digest }`。選んだテキストの識別・名前・評価に渡した本文の字数と照合値 |
| `range` | `{ start, end, digest, keysDigest }`。評価に渡した本文の文字位置の半開区間と、その範囲の本文の照合値、その範囲を打つキーの列（ステップごとの、押すキーと出力の文字）の照合値 |
| `typed` | かなごとに打った綴り（任意。§3.1） |
| `gaps` | ストロークごとの、直前のストロークからの時刻の差。0.1ミリ秒を単位とする整数。最初は0 |
| `deltas` | ストロークごとの `e` の差。直前のストロークの `e` からの差で、最初は `range.start` からの差 |
| `unclean` | 違うキーを押したストロークの位置の並び（任意）。昇順で重ならない |
| `outputCompleted` | コンボを出力の文字の読み方で打ち終えたストロークの位置の並び（任意）。昇順で重ならない |

照合値は、同じ文字列から同じ値が出る非暗号の32ビットのハッシュ2系統を並べた16桁の16進である。食い違いの検出に使い、改ざんの検知には使わない。

### 4.1 食い違いの判定

記録を読む側は、記録を今の入力と照らして、食い違う項目を求める。今の入力は、見ている対象のそれぞれを、記録を取った時と同じ経路（Setupと全レベルの条件、コンボを止める境を含む）で解決した値である。
`conditions` は読みの変換を持たず、コンボを止める境は文節の分割で変わりうるので、条件が同じでも打鍵の列は変わりうる。`range.keysDigest` は、その食い違いを検出する。

| 項目 | 食い違う条件 |
|---|---|
| 対象 | 記録の `target` が、見ている対象のどれにも当たらない。見ている対象に当たっても、今の条件で解決できない |
| 物理配列 | `shapeId` が、記録の対象を今解決した物理配列の識別子と違う |
| 指の割り当て | `fingerAssignmentId` が、今の指の割り当ての実効値と違う |
| 条件 | `conditions` が、今の条件の実効値（読みの変換を除く）と、項目の値のどれかで違う。項目の並びは問わない |
| 版 | `modelVersion` が今の `MODEL_VERSION` と違う |
| テキスト | `text.digest` が、今の評価に渡す本文の照合値と違う |
| 範囲 | `range.digest` が、今の本文の同じ範囲の照合値と違う、または範囲が今の本文に収まらない。テキストが食い違う時は判定しない（範囲の食い違いも含むので重ねて示さない） |
| 打鍵の列 | 作り直した打鍵の列が記録と違う。上の全項目が一致する時だけ判定する（食い違う条件のもとで作り直した列は、記録の列と比べる意味が無いため） |

どれか1つでも食い違えば、その記録の間隔の図も表も出さず、食い違う項目を全部示す。対象が食い違う時は、他の項目を判定しない（対象を解決できないため）。

**打鍵の列の作り直し。** 記録の `typed`（無ければ条件の規則の綴り）で、全文の打鍵の列を今の入力から作り直し（§3.1の保存する時の作り直しと同じ）、記録の範囲のストロークを取り出す。次のどれかなら、打鍵の列が食い違う。

- 範囲が今の本文で打てない（§1.2）、または記録した範囲の端が今の範囲の端と合わない
- 取り出したストロークの数が、記録のストロークの数と違う
- 取り出したストロークごとの `e` が、記録の `e` と違う
- 取り出したストロークの打つキーの列の照合値が、`range.keysDigest` と違う

### 4.2 読み込みの検査

次のどれかを満たさない記録は、診断を残して読み込まない。

- ストロークの数が1以上で `RECORD_MAX_STROKES`（10万）以下であり、`gaps` と `deltas` の長さがストロークの数と等しい
- `gaps` が0以上の整数で、最初が0
- 各ストロークの `e` が `[range.start, range.end)` に入る
- `unclean` と `outputCompleted` が、ストロークの数より小さい整数の昇順の並び
- `range` が空でなく `text.chars` に収まり、`keysDigest` が空でない
- `typed` の各綴りが空でなく、長さが16以下で、個数がストロークの数以下

## 5. 保存と書き出し

記録は、他の資産と別のキー（`keydist:keystroke-records`）に保存する。
データ・設定の管理の書き出しファイル（`keydist-user-assets`）には入れない。記録は他の資産より大きく（`docs/architecture.md`「保存容量の見積もり」）、
そのファイルの種類ごとの件数の上限（100件）と、全データを入れても収まる大きさの前提（16MiB）を変えてしまうためである。
共有リンク（URL）には載せない。

記録だけを書き出す・読み込むファイルを別に持つ。形式は `{ format: 'keydist-keystroke-records', version, records }` で、`version` と `records` は手持ちの形式そのものである。
読み込みは、手持ちに同じ `id` がある記録を飛ばし、形式が不正な記録を捨てる。読み込める大きさは、データ・設定の管理のファイルと同じ16MiBである。

## 6. 打鍵の間隔

間隔を、Run Chartの点と同じ横軸（評価に渡した本文の文字位置 `e`）に並べる。この節は、間隔の定義と集計を定める。時間モデル（`spec/playback-timing.md` §3〜§5）は変えず、記録の時刻から求めるだけにする。

### 6.1 ストロークの間隔

ストローク `i`（`i ≥ 1`）の間隔 `g(i)` は、ストローク `i` の時刻と、記録の中で直前のストローク `i − 1` の時刻の差である。時刻は、記録の最初のストロークを0とした相対の時刻[ms]である。
範囲の最初のストロークは直前のストロークを持たないので、間隔を持たない。

次の間隔は数えず、欠けとする（`spec/playback-timing.md` §6.4と同じ）。

- 違うキーを押したストローク（`clean` が偽）の間隔
- 出力の文字の読み方で完了したコンボのストローク（`outputCompleted`）の間隔と、その直後のストロークの間隔

句読点（`spec/playback-timing.md` §6.4の「、」「。」「，」「．」「！」「？」）を打つストロークと、その直後のストロークの間隔は、図では欠けにせず数える。句読点の後の止まりも、打鍵の間隔が長くなる箇所の候補だからである。
`spec/playback-timing.md` §6.4は休む間を値に入れないために、この2つの間隔を数えない。表（本仕様の§6.3）は同じ§6.4に合わせて、この2つを数えない。

### 6.2 `e` ごとの値

`e` ごとの値は、記録の中でその `e` を最初に持つストロークの間隔である。ストローク `i` が `e` を最初に持つのは、`e(i)` を持つストロークが `i` より前に無い時である。
ストロークと `e` は1対1に対応せず、同じ `e` のうち最初のストロークより後のストロークは、その単位の中の打鍵（かなの中の2打目以降）にあたるので、値には入れない。
最初のストロークが欠けの間隔（§6.1）の `e` は、値を持たず欠けにする。範囲の最初の `e` は間隔を持たず欠けになる。

値を持つ `e` の集合と欠けの `e` を合わせた集合は、記録の `e` の集合（§2）と等しい。

Run Chartの集計窓の幅でならした値は出さない。間隔は1つの `e` に1つの値で、窓の幅ごとの値は、止まりが1文字に現れるかを見分けにくくする。

### 6.3 文節の区切りの直後の間隔

文節の区切りの直後のストロークと、それ以外のかなを打ち始めるストロークで、生の間隔を比べる表を求める。生の間隔は、§6.4と違い、基準の時間も打鍵の上乗せも引かない。

数えるストローク `i`（`i ≥ 1`）は、次の全部を満たすものである。

- 間隔を数える（§6.1の数えない間隔を除く）
- 句読点を打つストロークと、その直後のストロークでない（`spec/playback-timing.md` §6.4と同じ）
- かなを打ち始める。ストローク `i` の `kanaStart` が、直前のストローク `i − 1` の `kanaEnd` より大きい（`spec/playback-timing.md` §6.4と同じ）

数えるストロークのうち、`kanaStart` が文節の区切りの位置（評価に渡した本文の文字位置。位置 `b` の文字が次の文節の最初の文字で、0と末尾は含まない）に当たるものを「区切りの直後」の群、当たらないものを「それ以外」の群とする。
群ごとに、打数・間隔の四分位平均・間隔の平均を求める。四分位平均は、`spec/playback-timing.md` §6.4の `interquartileMean` と同じで、小さい方と大きい方から `floor(n / 4)` 個ずつを除いた残りの平均である。平均は外れた値を除かない。
群の打数が0の時は、その群の値を持たない。2群の差と、打数の下限は求めない。

`kanaStart`・`kanaEnd` は、§4.1で作り直した打鍵の列のストロークのものを使う。
区切りは、Run Chartが区切り方を選んだ時に重ねる文節の区切りと同じ分割器の結果を使う。Run Chartの区切り方の選択（なし・固定長・ランダム）によらず、この表は文節の区切りを使う。
テキストが日本語でない時と、分割器を読み込めない時は、表を求めない。

間隔と指標の相関係数は求めない。

## 7. 適用範囲

- 取れる時刻は `KeyboardEvent.timeStamp` の精度（ブラウザによって0.1ミリ秒から1ミリ秒以上に丸められる）による。記録は、取れた値を0.1ミリ秒に丸めて持つ
- 間隔は、時刻の揺れ（ブラウザの処理の遅れ・画面の描画）を除かない。記録は、打った時の時刻をそのまま持つ
- 間隔の図と表は、記録1件の値で、記録した人の打ち方・その時の条件・その範囲の文章に限る。複数の記録をまとめた値と、記録どうしの優劣は出さない
- 表は、打数の少ない群の平均と四分位平均を、打数と並べて示す。打数の下限は置かない（下限を置くと、短い範囲の記録がいつも空になる。打数が少ない値の揺れは、打数で読み手が判断する）
- 打っている間の窓の作り直しは、窓の境をまたぐ入力単位で全文の作り直しと違いうる。違った時は保存しない（§3.1）。保存できない範囲の割合は測っていない
- 記録は利用者がアプリの中で打ったものだけを扱う。外のツールの記録は読み込まない
